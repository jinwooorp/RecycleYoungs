# RecycleYoungs 문서 안내

처음 합류했다면 루트 README에서 서비스가 지원하는 기능을 살펴보고 웹 앱을 실행합니다. 지도나 API까지 확인할 때는 아래 표에서 목적에 맞는 실행 방식을 고릅니다. [프로젝트 소개와 빠른 시작](../README.md#빠른-시작)

## 작업별 읽는 순서

| 하고 싶은 일 | 읽는 순서 |
| --- | --- |
| 로컬에서 앱 실행 | [개발 환경 설정](SETUP.md#팀원-클론과-실행-방식)에서 화면, 합성 API, 로컬 데이터 연동 중 필요한 실행 방식을 고릅니다. |
| 기능이 동작하는 위치 찾기 | [제품 요구사항](PRD.md)에서 화면 동작을 확인한 뒤 [시스템 아키텍처](ARCHITECTURE.md)에서 요청 경로와 관련 코드를 찾습니다. |
| API 연동 또는 DB 변경 | [REST API](API.md)에서 요청·응답을, [데이터 설계](DATABASE.md)에서 테이블·제약·마이그레이션을 확인합니다. |
| 공공데이터 검사 또는 게시 | [ETL 가이드](ETL.md#전체-데이터-흐름)에서 작업 경로를 고르고 절차와 원천 판본의 검증 근거를 확인합니다. |
| 웹 화면에 공통 스타일 적용 | [웹 디자인 시스템](DESIGN_SYSTEM.md)에서 브랜드, 색상, 글자, 접근성과 공통 컴포넌트를 확인합니다. |
| 코드 변경 검증 또는 CI 실패 조사 | [개발 규칙](CONVENTIONS.md)에서 작성·협업 기준을 확인하고 [테스트와 CI](TESTING.md)에서 변경 범위에 맞는 검사를 고릅니다. |

## 기능을 추가할 때 수정할 문서

사용자에게 제공하는 범위가 바뀌면 PRD에 구현 상태와 후속 계획을 구분해 기록합니다. 변경이 결정되면 아래 표에서 담당 문서와 영향을 받는 문서를 찾습니다. [제품 요구사항](PRD.md)

| 변경 상황 | 먼저 확인할 문서 | 변경에 따라 함께 수정할 문서 |
| --- | --- | --- |
| 새 업종 지원 | [PRD](PRD.md)에서 지원 범위와 화면 정책을 정리하고 [ETL](ETL.md)에서 업종 분류와 자료 범위를 확인합니다. | 저장 형식이나 응답이 바뀌면 [DATABASE](DATABASE.md)와 [API](API.md)를 갱신합니다. 업종별 검증 절차는 [TESTING](TESTING.md)에 반영합니다. |
| 서울 외 지역 지원 | [PRD](PRD.md)에서 서비스 지역을 정리하고 [ARCHITECTURE](ARCHITECTURE.md)에서 지역 처리의 영향을 확인합니다. | 경계와 통계 원천은 [ETL](ETL.md), 지역 키와 공간 조건은 [DATABASE](DATABASE.md)·[API](API.md)에 반영합니다. 실행 설정이나 검증 범위가 바뀌면 [SETUP](SETUP.md)·[TESTING](TESTING.md)도 갱신합니다. |
| 새 공공데이터 수집 | [ETL](ETL.md)에서 출처·판본·검증·게시 방법을 정리합니다. | 저장 구조는 [DATABASE](DATABASE.md), 공개 필드는 [API](API.md), 새 키나 실행 조건은 [SETUP](SETUP.md), 검증 절차는 [TESTING](TESTING.md)에 반영합니다. |
| 새 API 또는 DB 테이블 추가 | 요청·응답은 [API](API.md), 테이블과 마이그레이션은 [DATABASE](DATABASE.md)에서 시작합니다. | 데이터 흐름이 바뀌면 [ARCHITECTURE](ARCHITECTURE.md), 적재가 바뀌면 [ETL](ETL.md), 검증 절차가 바뀌면 [TESTING](TESTING.md)을 갱신합니다. |

상세 설명은 담당 문서의 기존 절에서 갱신하고, 관련 문서에서 그 절을 링크합니다. 기존 문서의 역할과 다른 목적이 생기면 새 문서를 추가합니다.

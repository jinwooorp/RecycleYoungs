## 엔드포인트·이용 조건과 차단 사유

### 서울 열린데이터광장

- 6종 공통 공식 주소는 `http://openapi.seoul.go.kr:8088/{KEY}/json/{SERVICE}/{START_INDEX}/{END_INDEX}/`입니다. 시작·끝은 1부터 양끝을 포함합니다. 일반 키의 요청당 상한은 1,000행, 공개 `sample`의 조회 위치는 1~5입니다. 정상 응답의 `list_total_count`를 모든 페이지에서 대조합니다. 일반 키의 일일 한도, 활용사례 승인과 서비스별 예외는 발급 계정 및 기관에 확인합니다. [Open API 이용안내](https://data.seoul.go.kr/together/guide/useGuide.do) · [일반 인증키 발급](https://data.seoul.go.kr/together/mypage/actkeyMain.do) · [이용약관](https://data.seoul.go.kr/etc/accessTerms.do)
- **공식 HTTPS 확인 이력.** 같은 공식 호스트에 공개 표본으로 HTTPS를 요청했을 때 443은 연결 시간 초과(curl 28), 8088은 TLS 연결 실패(curl 35)였습니다. [2026-11-10 검증](archive/etl-validation-history.md#oa-22179-공개-표본과-https-확인-2026-11-10)과 같은 결과입니다. 데이터셋 안내 페이지의 HTTPS는 API 전송 지원의 근거가 아닙니다. 공공데이터포털에서도 6종과 같은 판본을 제공하는 별도의 공식 HTTPS API 주소는 확인하지 못했습니다.
- 서울시 통계 6종의 probe와 게시는 정확히 `http://openapi.seoul.go.kr:8088`에서만 `--allow-insecure-http`로 평문 전송을 허용합니다. 인증키 탈취와 응답 변조 위험이 있으며 실제 인증키 호출은 명시적 승인이 필요합니다. 5종의 실키 전체 수집 및 실제 데이터 게시는 별도 승인 대기 중입니다. [실행 및 위험 안내](etl-guide.md#서울시-open-api-전체-수집-probe)
- 서울시에 이 6개 서비스의 공식 HTTPS 호스트·포트·경로와 인증 방식, 응답 판본·기간 필터·정렬, 호출 한도를 확인합니다. 공식 주소를 확보하면 공개 표본으로 인증서의 호스트 일치와 응답 형식을 확인한 뒤 서버에서만 `SEOUL_OPEN_API_KEY`를 사용합니다. 리다이렉트 차단과 URL·예외 원문 비출력 정책을 유지합니다. 중간 프록시를 거쳐도 마지막 구간이 HTTP이면 키가 노출됩니다. 현재는 공식 HTTPS 파일·Sheet CSV를 확보해 기존 파일 ETL로 검증하는 경로가 가능합니다. [공식 다운로드 방식 검증](archive/official-source-verification-20261-20262.md#공식-출력의-재확인-조건)

### 소진공 상가(상권)정보

- 공식 기본 주소는 `https://apis.data.go.kr/B553077/api/open/sdsc2`입니다. 이번 무키 `storeListInDong` 요청은 HTTPS로 HTTP 401을 받았습니다. 활용신청 후 승인된 공공데이터포털 **Decoding 키**를 `SEMAS_API_KEY`로 사용합니다. 포털에 개발계정 트래픽 10,000, 활용사례 등록 후 운영계정 증량 신청, 이용허락범위 제한 없음이 표시됩니다. 운영 전 실제 계정에 적용되는 시간 단위·할당량을 확인합니다. [공식 명세와 이용 조건](https://www.data.go.kr/data/15012005/openapi.do)
- 업소 조회는 `pageNo`·`numOfRows`, 응답은 `totalCount`·페이지 정보·헤더 `stdrYm`을 사용합니다. 현행 클라이언트는 전체 수집 시 1,000행/페이지, probe 시 최대 5행을 요청하며 연속 호출은 초당 최대 2회로 제한합니다. 1,000행은 현행 클라이언트의 요청값입니다. 기관의 별도 최대 페이지 크기와 현재 승인 계정의 실제 응답은 **미확인**입니다.
- CSV 대조 시 같은 기준년월, 서울 코드와 소분류로 범위를 맞추고 업소번호로 조인합니다. 행정동과 법정동 코드, 분류 코드·명칭, 주소, WGS84 좌표·결측 및 좌표의 DB 반영 정밀도를 비교합니다. API가 현재 판본을 응답하므로 파일 시점이 다르면 같은 스냅샷으로 간주할 수 없습니다.

### 도형을 제공하는 경계 API

- 서울 OA-22160·OA-22161의 공식 경계 도형은 ZIP으로 확보할 수 있습니다. 동일한 도형·면적·판본을 제공하는 공식 API는 **미확인**입니다. 공공데이터포털의 [행정동 영역 15147263](https://www.data.go.kr/data/15147263/fileData.do)도 파일 카탈로그입니다.
- 국가데이터처 SGIS는 공식 `https://sgisapi.mods.go.kr/OpenAPI3/boundary/hadmarea.geojson`에서 코드와 기준연도에 따른 실제 경계 `geometry`를 명세합니다. 서버는 SGIS 서비스 ID와 Secret으로 발급받은 `accessToken`을 사용합니다. `adm_cd`·`low_search`로 구·동을 계층별로 조회하며, 이 경계 API 명세에는 페이지·전체 건수 계약이 없습니다. 약관은 키당 하루 50,000회 이하로 제한합니다. 이번 무토큰 요청의 HTTP 500은 HTTPS 응답까지만 확인한 결과입니다. **인증 도형 검증 BLOCKED**입니다. 서울 OA 코드·판본과의 동등성, 좌표계·도형 해상도·면적 산식·대표점은 별도로 확인해야 합니다. [경계 명세](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/addressBoundary.html) · [인증 명세](https://sgis.mods.go.kr/developer/html/newOpenApi/api/dataApi/basics.html) · [약관](https://sgis.mods.go.kr/developer/html/openApi/app/rules.html)
- [국토교통부 행정구역도 15059008](https://www.data.go.kr/data/15059008/openapi.do)의 WFS 시군구·읍면동 피처도 후보입니다. 카탈로그의 읍면동은 법정동 구역이므로 서울 행정동 대체 근거로 사용하기 어렵습니다. 소진공 명세의 `baroApi`도 행정경계조회로 안내되지만, 서울 상권분석 경계와 같은 도형·코드·판본을 제공하는지는 **미확인**입니다. 현재 경계 적재의 EPSG:5181, 원본 면적, 구별 결합, SRID 4326과 내부 대표점 계약을 유지합니다. [경계 적재 계약](etl-guide.md#행정동자치구-경계-적재)

API와 CSV는 같은 [자치구 인구 게시 파이프라인](../etl/src/domains/foot-traffic/district-foot-traffic.ts)을 사용합니다. API 수집 오류도 `FAILED` 배치로 기록하며, 전체 검증을 마친 입력만 staging·FK 검사·Advisory Lock·Upsert로 넘깁니다. 기존 값과 출처는 게시 트랜잭션에서 함께 반영합니다. 원본 유형별 체크섬과 이전 배치를 대조하므로 같은 CSV 값을 API로 다시 받아도 출처 전환은 새 게시로 기록합니다.

자치구 유동인구 REST는 정상 CSV·API 배치를 모두 조회합니다. 격리 DB에서 CSV·API가 섞인 과거 분기와 API 전용 게시본의 조회·출처를 검증했습니다. OA-22179는 실제 서울시 원본과 CSV·개발 DB의 전수 대조 및 격리 DB 게시·REST 확인을 완료했습니다. [현재 Backend 조회 조건](../backend/src/main/java/kr/ac/recycleyoungs/foottraffic/DistrictFootTrafficStatRepository.java)

## CSV·API 대조와 게시 승인 조건

1. **판본을 고정합니다.** 공식 데이터셋 ID, 서비스명, 구·동 범위, 분기 조건, 응답의 기준 시점·조회 시각, 공개 메타정보와 CSV 내부 바이트 SHA-256을 기록합니다. 압축 ZIP 바이트의 해시는 별도로 관리합니다. API의 스냅샷 식별자가 없으면 수집 앞뒤 메타데이터와 재수집 지문을 확인합니다. 요청 인증정보·전체 URL·원본 경로는 결과에 남기지 않습니다.
2. **페이지와 전체 행 수를 검증합니다.** API 원천 전체와 비교할 필터 범위를 각각 기록합니다. 기대 행 수는 CSV 전체 및 기관 근거와 대조합니다. 누락·중복 페이지, 중복 키, 총건수 변경, 응답 오류나 제한 초과는 전체 실패입니다. 행정동 점포·매출의 전 기간 API 메타데이터를 최근 기간 CSV 행 수와 직접 대조하지 않습니다.
3. **키와 필드를 매핑합니다.** `STDR_YYQU_CD`는 `YYYYQ`, `SIGNGU_CD`는 5자리, `ADSTRD_CD`는 8자리, `SVC_INDUTY_CD`는 `CS`+6자리 문자열로 비교합니다. 점포·매출은 분기·지역·업종, 인구는 분기·지역 키를 사용합니다. 업종 명칭 충돌과 FK 누락은 별도로 집계합니다. 양방향 차집합과 분기별 구·동 및 업종 범위를 비교합니다.
4. **측정값과 결측을 검증합니다.** 점포는 `STOR_CO`·`SIMILR_INDUTY_STOR_CO`·`FRC_STOR_CO`·`OPBIZ_STOR_CO`·`CLSBIZ_STOR_CO` 및 `OPBIZ_RT`·`CLSBIZ_RT`를 비교합니다. 매출은 `THSMON_SELNG_AMT`·`THSMON_SELNG_CO`·`MDWK_SELNG_AMT`·`WKEND_SELNG_AMT`, 인구는 `TOT_FLPOP_CO`·`ML_FLPOP_CO`·`FML_FLPOP_CO`를 비교합니다. 숫자 토큰을 문자열로 유지하고 기존 BIGINT·NUMERIC 규칙을 적용합니다. 정확한 값, 소수 자릿수, NULL·빈 셀·실제 0·행 부재를 따로 대조합니다. 합계 차이와 분기별 누락은 원본대로 보존합니다.
5. **게시 동작을 격리 DB에서 확인합니다.** 차이가 남으면 원인을 판정할 때까지 파일 입력을 유지합니다. 동등한 행을 기존 검증·staging·FK·트랜잭션에 전달하며 Flyway V1~V7과 API 응답 계약을 유지합니다. 출처 유형·요청 범위·건수·수집 시각을 기존 배치의 출처 필드에 기록하고, API는 필드 순서·복합키 정렬·정규화 규칙·입력 판본을 고정한 체크섬을 정의합니다. CSV의 바이트 해시를 API 체크섬과 동일시하지 않습니다. 동일 원본의 `SKIPPED`, 정상 `PUBLISHED`, 부분 실패의 롤백, 누락 입력 키와 기존 게시 시각·출처 보존을 검증합니다. `unverified` 전분기 증감 비공개 정책은 유지합니다. [현행 게시 계약](etl-guide.md#공통-입력-검증과-게시)

## 권장 구현 순서

1. **OA-22179 전체 API·CSV·게시 DB 대조.** 기존 550행 CSV와 개발 DB를 재검증했습니다. 승인된 실제 요청으로 세 원천을 전수 대조했고 별도 격리 DB에 게시해 REST 응답을 확인했습니다. [OA-22179 전수 대조 절차](etl-guide.md#oa-22179-550행-apicsv게시-db-대조) · [2026-11-13 재검증](archive/etl-validation-history.md#oa-22179-csv와-게시-db-재검증-2026-11-13)
2. **소규모 통계부터 읽기 전용으로 확대합니다.** 합성 검증을 마친 행정동 인구, 자치구 점포·매출 순으로 실제 인증과 동일 판본을 검증합니다. 값·판본·출처 검증이 끝난 자료만 격리 DB에서 기존 배치 경로와 회귀 검증합니다.
3. **행정동 점포·매출의 실제 범위를 검증합니다.** 전체 수집과 CSV 분기 선택을 대조합니다. 업종은 점포·매출 원천에서 같은 기간 범위의 코드·명칭 집합이 일치할 때 전환합니다. 경계와 업종 기준은 해당 통계보다 먼저 준비합니다.
4. **카페 API를 독립적으로 유지·검증합니다.** 기존 소진공 키의 활용 승인·할당량을 확인합니다. 동일 기준년월의 공식 파일을 확보할 수 있으면 읽기 전용 대조를 추가합니다. 서울시 일반 키와 별개이며, SGIS ID·Secret은 경계 대체를 별도로 검토하기로 한 경우에만 발급합니다.
5. **검증 결과에 맞춰 문서를 갱신합니다.** [ETL 가이드](etl-guide.md)에 키·한도·실행·실패 시 파일 경로를, [데이터 설계](data-design.md)에 필드·판본·체크섬 대응을, [검증 이력](archive/etl-validation-history.md)에 실제 대조 결과를 기록합니다.

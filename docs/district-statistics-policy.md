# 자치구 통계 원천 및 집계 정책

- [데이터 설계](data-design.md)
- [ETL 가이드](etl-guide.md)

자치구 통계는 **서울시가 별도로 제공하는 자치구 원천을 우선 사용**합니다. 행정동 통계의 합계를 공식 자치구 통계로 간주하지 않습니다. 이 문서는 원천 조사·실제 점포 CSV 검증과 V5 자치구 점포 저장·적재 계약을 정리합니다. DB 없는 probe를 유지하고 공식 자치구 점포 조회 API를 제공합니다. 자치구 추정매출·유동인구 DB/ETL·API와 점수 기능은 후속 계획입니다.

## 확인 범위와 근거 수준

2026-10-31 기준으로 공식 포털의 설명·공개 Open API 출력항목·Sheet 컬럼 정의와 각 서비스의 공개 `sample` 5행을 확인했습니다. 개인 인증키, 개발 DB, 다른 브랜치나 과거 Git 이력은 사용하지 않았습니다. 이후 사용자가 제공한 점포-자치구 CSV를 전체 probe로 검증했습니다. 아래 세 수준은 서로 다른 증거입니다.

| 수준               | 확인한 것                                                                        | 확인하지 못하는 것                                                |
| ------------------ | -------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 공식 메타데이터    | 데이터셋 식별자, 갱신주기·갱신일, 제공 변경 공지, 출력명·한글 설명, API 서비스명 | 전체 실제 행의 기간·코드·결측·중복·완전성                         |
| 공개 API 표본      | 서비스당 5행의 실제 필드·값 표현, 표본에 나타난 분기와 자치구 코드               | 전체 제공 기간의 최소·최대, 최신 분기, 전 자치구·업종의 커버리지  |
| 실제 CSV 전체 검증 | 사용자가 지정한 파일에 probe를 실행했을 때의 헤더·체크섬·행 수·키·기간·NULL      | 공식 배포본 전체와의 동일성·DB FK·게시 가능 여부는 별도 대조 필요 |

최초 공식 조사는 포털 metadata·sample만 사용했고 CSV를 내려받지 않았습니다. 이후 별도로 제공된 **점포-자치구 CSV의 12개 한글 헤더·CP949 인코딩·수치 표기와 전체 54,765행**을 검증했습니다. 아래 점포 한글 별칭은 이 실제 CSV와도 일치합니다. 자치구 추정매출·인구 CSV 전체는 아직 검증하지 않았으며, 일반 페이지의 정적 추출에 파일 목록이 비어 보인다는 사실로 CSV 제공 중단을 판단하지 않습니다.

공식 페이지의 Open API·Sheet 탭은 동적으로 조회됩니다. 공개 탭 경로는 `/dataList/openApiView.do?infId=…&srvType=A`, `/dataList/sheetView.do?infId=…&srvType=S`이며 포털은 해당 데이터셋의 공개 폼 값으로 POST합니다. 정적 페이지 텍스트만으로 컬럼 부재를 판단하지 않습니다.

## 컬럼과 행정동 원천 비교

### 공통 식별자

아래 대응은 세 자치구 데이터셋의 공식 Open API 출력항목과 Sheet 컬럼 정의에서 확인했습니다. 자치구 코드는 이름이나 행정동 필드를 추측해 대체하지 않습니다.

| 한글 출력설명·Sheet label | 영문 출력명        | 사용 범위·정책                                              |
| ------------------------- | ------------------ | ----------------------------------------------------------- |
| `기준_년분기_코드`        | `STDR_YYQU_CD`     | 세 데이터셋 공통; 프로젝트는 `YYYYQ` 문자열로 검증          |
| `자치구_코드`             | `SIGNGU_CD`        | 세 데이터셋 공통; 프로젝트는 ASCII 숫자 5자리 문자열로 검증 |
| `자치구_코드_명`          | `SIGNGU_CD_NM`     | 세 데이터셋 공통; 표시·명칭 대조용이며 키가 아님            |
| `서비스_업종_코드`        | `SVC_INDUTY_CD`    | 점포·매출; 프로젝트는 `CS` + 숫자 6자리 문자열로 검증       |
| `서비스_업종_코드_명`     | `SVC_INDUTY_CD_NM` | 점포·매출; 표시·명칭 대조용이며 키가 아님                   |

공식 출력명과 프로젝트 검증 형식은 구분합니다. 예를 들어 공개 점포 표본의 `SIGNGU_CD=11740`은 실제 5자리 값의 사례이지, 모든 원천 행이 형식을 지킨다는 보장이 아닙니다. `SIGNGU_CD`와 `ADSTRD_CD`를 같은 필드의 별칭으로 받지 않습니다. [공식 점포 컬럼 안내](https://data.seoul.go.kr/dataList/OA-22173/A/1/datasetView.do), [공식 매출 컬럼 안내](https://data.seoul.go.kr/dataList/OA-22176/A/1/datasetView.do), [공식 인구 컬럼 안내](https://data.seoul.go.kr/dataList/OA-22179/A/1/datasetView.do)

### 점포의 7개 측정값

3개 코드 키와 아래 7개 측정값이 점포 probe의 필수 컬럼입니다. 두 명칭 컬럼은 복합키에 포함하지 않습니다. 한 필드에 한글·영문 헤더가 동시에 존재하면 모호한 입력으로 처리합니다.

| 한글 출력설명·Sheet label | 영문 출력명             | 의미·V5 저장 컬럼                            |
| ------------------------- | ----------------------- | -------------------------------------------- |
| `전체_점포_수`            | `SIMILR_INDUTY_STOR_CO` | 전체 점포 수 → `store_count`                 |
| `일반_점포_수`            | `STOR_CO`               | 일반 점포 수 → `general_store_count`         |
| `프랜차이즈_점포_수`      | `FRC_STOR_CO`           | 프랜차이즈 점포 수 → `franchise_store_count` |
| `개업_율`                 | `OPBIZ_RT`              | 원천 개업률 → `opening_rate`                 |
| `개업_점포_수`            | `OPBIZ_STOR_CO`         | 개업 점포 수 → `opened_store_count`          |
| `폐업_률`                 | `CLSBIZ_RT`             | 원천 폐업률 → `closure_rate`                 |
| `폐업_점포_수`            | `CLSBIZ_STOR_CO`        | 폐업 점포 수 → `closed_store_count`          |

`SIMILR_INDUTY_STOR_CO`가 전체, `STOR_CO`가 일반입니다. 포털 설명에 전체 = 일반 + 프랜차이즈 관계가 있지만, probe는 값을 보정하거나 불일치를 자동 수정하지 않습니다. 실제 공개 API 표본의 점포 수에는 `749.0`, `43.0`, `2.0`처럼 정수 의미의 소수 표기가 있습니다. 후속 실제 점포 CSV에서도 7개 수치 모두 소수 표기임을 확인했습니다. 자치구 원천의 관찰 결과로 기존 행정동 ETL의 숫자 허용 규칙을 변경하지 않습니다. [공식 점포 설명·출력항목](https://data.seoul.go.kr/dataList/OA-22173/A/1/datasetView.do), [공개 점포 표본](http://openapi.seoul.go.kr:8088/sample/xml/VwsmSignguStorW/1/5/)

## 기간과 원천 판본

세 자치구 페이지에는 `2026-07-03` 적용 공지가 있습니다. 2024년부터 공간 기준이 표준단위구역으로 변경되었고, 해당 기준 카드 매출의 제공 시작을 이유로 2021년 이후 자료만 제공한다고 설명합니다. 이는 현재 제공의 하한 정책이며, `20211`부터 모든 자치구·업종·분기가 완전하다는 보장은 아닙니다. 2024년 전후의 비교와 재배포된 과거 자료의 접합에는 판본·공간 기준 확인이 필요합니다. [점포 공지](https://data.seoul.go.kr/dataList/OA-22173/S/1/datasetView.do), [매출 공지](https://data.seoul.go.kr/dataList/OA-22176/S/1/datasetView.do), [인구 공지](https://data.seoul.go.kr/dataList/OA-22179/S/1/datasetView.do)

공식 서비스 소개에는 일반적인 분기 제공·분기 후 갱신 예정과 더 오래된 시간범위 안내도 있습니다. 이 문서에서는 개별 데이터셋의 날짜가 명시된 최신 제공 변경 공지를 우선하며, 갱신 예정일로 실제 최신 제공 분기를 추측하지 않습니다. [공식 서비스 소개](https://golmok.seoul.go.kr/introduce.do)

| 구분        | 공개 sample 5행에서 관찰한 분기 집합 | 표본 응답의 전체 건수 메타데이터 |
| ----------- | ------------------------------------ | -------------------------------- |
| 자치구 점포 | `20262`                              | `54,765`                         |
| 자치구 매출 | `20223`, `20224`, `20244`, `20261`   | `33,803`                         |
| 자치구 인구 | `20242`, `20243`, `20244`            | `550`                            |

이 값은 조사 시점의 공개 표본·응답 메타데이터이며 고정 기대 건수로 쓰지 않습니다. 실제 수집은 5행씩만 했습니다. 표본 최솟값·최댓값과 `list_total_count`로 전체 기간, 최신 분기, `25구 × 분기 × 업종`의 완전성을 역산하지 않습니다. [점포 표본](http://openapi.seoul.go.kr:8088/sample/xml/VwsmSignguStorW/1/5/), [매출 표본](http://openapi.seoul.go.kr:8088/sample/xml/VwsmSignguSelngW/1/5/), [인구 표본](http://openapi.seoul.go.kr:8088/sample/xml/VwsmSignguFlpopW/1/5/)

기존 [ETL 검증 기록](etl-guide.md#공공데이터-검증-현황)의 실제 행정동 입력은 점포 `20251`~`20262` 211,832행, 매출 `20251`~`20262` 100,431행, 인구 `20211`~`20262` 9,350행입니다. 이는 기존에 적재·검증한 파일 판본의 결과이며 이번 자치구 조사에서 재검증한 결과가 아닙니다. 공식 포털의 현재 제공 범위나 자치구 파일 범위로 전용하지 않습니다.

## 실제 자치구 점포 CSV 검증

사용자가 제공한 `서울시 상권분석서비스(점포-자치구).csv`에 기존 `district-stores --probe --expected-rows 54765`를 실행했습니다. 이 결과는 공개 API 5행 표본과 별개인 로컬 파일 전체 형식 검증입니다.

| 검증 항목        | 실제 결과                                                             |
| ---------------- | --------------------------------------------------------------------- |
| 인코딩·판독 건수 | CP949, 54,765행(헤더 제외); 유효 54,765·거부 0                        |
| 분기             | `20211`~`20262`, 연속 22개 분기                                       |
| 자치구·업종      | 25개 구·100개 서비스 업종                                             |
| 헤더·키          | 공식 12개 한글 컬럼 확인; 분기·구·업종 복합키 중복 0                  |
| 수치             | 7개 측정값 모두 소수 표기; 점포 수는 정수 의미, 형식 오류 없음        |
| NULL·0           | 이 파일의 수치 빈 셀은 0개; 실제 0 존재. 일반 계약의 NULL 허용은 유지 |
| 비율             | 개업률 최대 `100.0`; 폐업률 `200.0`인 1행 확인, 100% 초과를 허용      |
| 빠진 조합        | 관찰 차원의 곱 `22 × 25 × 100 = 55,000` 대비 235개 조합 없음          |
| DB 부수 효과     | `databaseChecked=false`, `batchCreated=false`, `loadedRows=0`         |

CSV 원본 바이트의 SHA-256은 `84702068872a5ab8c6c824f11294a16f8b306afb6c19a25689af4c135bf377fd`입니다. 구·업종 수와 빠진 조합·NULL·비율 범위는 같은 파일을 별도로 읽어 대조한 결과이며 probe JSON에 새 필드를 추가한 것은 아닙니다. 최대 5행 표본만 출력했습니다.

이 파일의 형식 검증 성공이 포털의 모든 판본·공식 전체 조합의 완전성을 보장하지 않습니다. 235개 없는 조합을 오류로 취급하거나 0으로 생성하지 않습니다. 개발 DB의 FK와 실제 저장 데이터는 조회하지 않았으며, V5·적재 동작은 개발 DB와 분리된 일회용 PostGIS에서 검증합니다. 같은 실제 CSV 54,765행을 일회용 PostGIS에 적재해 7개 측정값을 전수 문자열 대조했고, 재실행 `SKIPPED`와 기존 정상 게시 출처 보존도 확인했습니다. 이때 FK는 관찰 코드로 구성한 합성 기준 행을 사용했으며 개발 DB의 기준 데이터 대조를 대신하지 않습니다. 자치구 매출·인구 원본 전체 검증은 후속 과제입니다.

## 지표별 집계 정책

### 점포 수·개업 수·폐업 수

공식 자치구 값을 우선 제공합니다. 행정동 파생 합계는 다음 조건을 모두 입증한 별도 계산에서만 허용합니다.

1. 동일한 분기·업종 정의·원천 판본·통계 기준을 사용합니다.
2. 해당 분기의 모든 대상 행정동과 자치구 소속을 확인하고, 현재 경계를 과거 통계에 자동 적용하지 않습니다.
3. 공간 범위의 누락·중첩과 복합키 중복이 없고 점포가 집계 범위 간 중복 계상되지 않는다는 근거를 확보합니다.
4. 일부 동·업종의 행 누락과 측정값 NULL을 실제 0으로 바꾸지 않습니다. 커버리지가 부족하면 완전한 구 합계로 게시하지 않습니다.
5. 단순 숫자 형식·키 유일성 검증과 집계 가능성 검증을 구분합니다. 합계는 별도의 산출값이며 공식 원천과 일치한다고 가정하지 않습니다.

점포 수는 분기별 상태를 나타내므로 여러 분기를 더해 연간 점포 수로 만들지 않습니다. 개·폐업 수도 기간 경계·신고 기준·수정 판본이 호환된다는 근거 없이 기간을 합산하지 않습니다. 전체·일반·프랜차이즈의 원천 불일치가 있으면 기록하고 임의 조정하지 않습니다.

### 개업률·폐업률

행정동 비율의 합계와 단순 평균은 금지합니다. 기존 점포 수를 임의의 가중치로 선택하는 것도 금지합니다. 공식 서비스 소개는 당기 신고 점포 수와 전체 점포 수로 개·폐업률을 산출한다고 안내하고, 전체 점포의 기간상 포함 조건을 설명합니다. 그러나 이 일반 설명만으로 개별 OA 데이터셋·판본에서 `SIMILR_INDUTY_STOR_CO`가 정확한 분모라는 점이나 반올림 규칙까지 입증되지는 않습니다. [공식 개·폐업률 정의](https://golmok.seoul.go.kr/introduce.do)

파생 비율 재계산은 적용 대상 원천의 분자·분모·기간 정의와 중복 없는 커버리지를 확인한 뒤 별도 승인된 계산 계약으로만 진행합니다. 분모가 0·NULL이거나 일부 동이 누락되면 계산하지 않습니다. 가중평균도 동일한 정확한 분모와 반올림 전 수치를 확보한 경우에만 검토합니다. 현재 단계에서는 공식 자치구 비율을 원문 정밀도로 유지하고 재계산·100% 상한 적용을 하지 않습니다.

### 추정매출액·건수

공식 서비스 소개는 카드결제 기반 추정과 자치구·행정동·표준단위구역·업종별 보정비율을 안내합니다. 보정 기준이 공간 단위별로 다를 수 있으므로 행정동 추정매출의 합계가 공식 자치구 추정매출과 같다고 보장할 수 없습니다. 이는 공식 안내에 근거한 보수적 판단이며, 실제 불일치 수치를 측정한 결과는 아닙니다. [공식 추정매출 설명](https://golmok.seoul.go.kr/introduce.do)

매출액뿐 아니라 건수도 범위·추정·보정·반올림·중복 기준을 확인하기 전에는 자동 합산하지 않습니다. 주중·주말·요일·시간대별 값은 전체와 구분되는 세부 분류이며 전체에 다시 더하지 않습니다. `당월` 의미를 유지하고 분기 합계나 월평균으로 환산하지 않습니다. 동일 업종·분기라도 결측 동, 업종 제공 범위, 공간·원천 판본이 다르면 공식 수치와의 수치 대조를 보류합니다.

### 길단위 유동인구

공식 설명은 서울시·KT 생활인구를 바탕으로 10m 길 구간에 배분한 유동인구라고 안내합니다. 따라서 프로젝트는 이를 추정 유동 규모로 해석하며, 개인별 중복을 제거한 고유 방문자 수·주민 수·카페 방문 고객 수라고 표현하지 않습니다. 공식 설명에서 개인의 공간·시간 중복 제거를 보장한 것으로 읽지 않습니다. [공식 길단위인구 정의·배분 과정](https://golmok.seoul.go.kr/introduce.do)

도로·행정동·시간대·요일 사이의 중첩과 배분 기준이 검증되지 않았으므로 정수처럼 보인다는 이유로 단순 인원 합산을 허용하지 않습니다. 기간 평균·합계·일평균 변환도 명세를 확인하기 전에는 하지 않습니다. 총계와 성별·연령·시간대·요일 세부 값을 중복해 더하지 않으며, 세부 합계의 원천 차이를 보정하지 않습니다. 인구 통계에는 업종 차원이 없으므로 업종별 점포·매출과 조인해 업종 수만큼 인구를 중복 집계하지 않습니다.

## 공식 통계와 행정동 파생 통계의 구분

공식 자치구 원천은 `OFFICIAL_DISTRICT`, 행정동에서 계산한 산출물은 `DERIVED_DONG`처럼 구분하는 방향을 제안합니다. 이 명칭은 후속 모델의 제안이며 현재 DB enum이나 API 필드가 아닙니다.

| 방식                           | 장점                                                                                                       | 제한·비용                                                                                                                                     |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 공식 자치구 원천 우선          | 서비스가 요구하는 구 단위의 공식 값·비율·출처를 직접 보존하며 공간 단위별 추정 보정을 임의로 재현하지 않음 | 별도 원본 확보·판본·제공 기간·업종 범위 검증과 독립 ETL·DB 모델이 필요하며 공식 결측이 사라지는 것은 아님                                     |
| 조건이 검증된 행정동 파생 합계 | 기존 동별 자료를 근거로 계산 과정을 추적하고 구·동별 내역을 설명할 수 있음                                 | 과거 소속·전체 커버리지·중복·NULL과 지표별 가산성을 입증해야 하며 공식 구 값과의 동일성을 보장하지 않음; 비율·추정 지표는 별도 산식 계약 필요 |

- 기본 구 통계는 공식 자치구 원천입니다. 행정동 파생 통계는 집계 가능성이 입증된 지표에 한해 별도 선택·표시합니다.
- 공식 행·측정값이 없으면 데이터 부족 상태를 유지합니다. 누락된 공식 값을 행정동 합산으로 몰래 대체하거나 한 응답의 출처를 섞지 않습니다.
- 두 원천의 수치가 다르더라도 한쪽을 다른 쪽에 맞추지 않습니다. 기준 분기·업종·경계·판본·커버리지·추정·반올림 차이를 먼저 조사합니다.
- 비교에는 입력 출처와 산출 방법을 함께 제시합니다. 판본·기간이 맞지 않으면 차이율이나 일치 판정을 제공하지 않습니다.
- 구 전체 통계를 반경 500m·1km의 실제 수치로 표시하지 않습니다. 여러 구의 점수 합산·구와 동 점수의 직접 비교도 이 정책의 대상이 아닙니다. [서비스의 평가 범위](service-spec.md#점수-평가-범위)를 따릅니다.

## 점포 CSV probe의 검증 범위

probe의 대상은 사용자가 명시적으로 지정한 점포-자치구 CSV·ZIP의 형식 확인입니다. 적재 명령과 같은 입력 검증기를 사용하지만 읽기 전용 분기는 유지합니다. 네트워크 다운로드·DB 연결·FK 조회·스테이징·`etl_batch` 기록·게시·행정동 합산은 probe의 책임에 포함하지 않습니다.

구현된 probe는 위에서 확인한 3개 코드 키와 7개 측정값의 한글·영문 별칭, 전체 행 수·복합키 중복·코드 및 수치 형식을 검증합니다. 성공하면 CSV 내용의 SHA-256 체크섬·인코딩·판독/유효/거부 건수·입력에서 관찰한 분기 범위와 최대 5행의 `sample`을 반환합니다. 경로·ZIP entry·분기별 자치구 커버리지·NULL별 건수는 출력하지 않습니다. `validationScope=LOCAL_FILE_FORMAT`, `databaseChecked=false`, `batchCreated=false`, `loadedRows=0`을 명시하며, 코드 형식이 맞아도 실제 서울 자치구·업종 FK의 존재나 원천의 완전성을 확인한 것으로 표시하지 않습니다. 지정 파일에서 관찰한 분기 범위는 공식 전체 제공 기간과 구분합니다.

측정값은 `Number`로 변환하거나 반올림하지 않습니다. 점포 수는 `749.0`·정수 의미의 지수 표기도 정확한 정수 문자열로 정규화하고 비정수·음수·BIGINT 범위 초과는 거부합니다. 비율은 기존 점포 계약과 같은 0 이상 일반 십진수 문자열(지수 표기 제외)로 검증하고 원본 소수 자릿수·끝의 0을 보존하며 100 상한을 강제하지 않습니다. NUMERIC 정수부 131072자리·소수부 16383자리 한계를 적용합니다. 빈 셀만 NULL로 처리하고 공백·문자 `NULL`·잘못된 수치 표기를 0이나 NULL로 고치지 않습니다. 헤더 누락·중복·모호한 별칭과 동일 값의 복합키 중복도 오류입니다. 기존 행정동 점포·매출 원본의 숫자 허용 규칙은 변경하지 않았습니다.

합성 테스트의 성공과 실제 CSV 검증을 구분합니다. 이번 점포 CSV는 위와 같이 전체 probe를 완료했으며, 향후 다른 파일을 실행하지 못한 경우에는 `미검증`으로 남깁니다. 포털 metadata·sample로 전체 파일 검증을 대체하지 않습니다. 실행 명령·옵션과 현재 구현 세부 계약은 [ETL 가이드](etl-guide.md#자치구-점포-읽기-전용-검증)에서 관리합니다.

## 후속 저장·게시·API 방향

점포는 실제 파일 검증 후 V5와 `district-stores` 적재를 구현했습니다. 아래에서 점포 저장·적재·조회 API는 구현 계약이고 추정매출·인구는 후속 제안입니다.

| 항목          | 구현 계약·후속 제안                                                                                         |
| ------------- | ----------------------------------------------------------------------------------------------------------- |
| 테이블        | `district_store_stat`은 V5 구현; `district_sales_stat`·`district_foot_traffic_stat`는 V3와 분리할 후속 제안 |
| 키            | 점포·매출 `(district_code, industry_code, quarter_code)`, 인구 `(district_code, quarter_code)`              |
| FK            | `district`, 점포·매출의 `service_industry`, 실제 게시 출처의 `etl_batch` 참조                               |
| 자료형        | 점포 수·금액·건수는 정수 의미와 범위 확인 후 `BIGINT`, 비율·인구는 고정 소수 자릿수 없는 `NUMERIC`          |
| NULL          | 모든 측정값 NULL 허용·기본값 없음; 실제 0과 구분; 일부 NULL을 총계 0으로 바꾸지 않음                        |
| 마이그레이션  | 기존 V1~V4 불변; 점포는 `V5__create_district_store_stat.sql`, 나머지는 이후 버전에서 확정                   |
| 데이터셋 코드 | 점포 `SEOUL_DISTRICT_STORE_STAT` 구현, 기존 `SEOUL_DONG_STORE_STAT`와 구분; 매출·인구 별도 코드는 후속 확정 |

점포 게시 이력은 CSV 내용 체크섬·관찰 분기 범위와 ETL 버전 `district-store-stat-v1`을 기록합니다. `source_reference`는 `datasetId=OA-22173`, `serviceName=VwsmSignguStorW`, 원본 `path`, 선택적 ZIP `entry`, `encoding`을 담은 JSON입니다. 출처 조건은 `CSV`·`SEOUL`·`scope_code=NULL`입니다. 원천의 배포/수정 판본, 실제 자치구·업종별 커버리지, 측정 기준·경계 판본의 상세 출처 및 추가 메타데이터 스키마는 후속 검토 대상입니다. 포털 페이지 갱신일만으로 원천 판본을 식별하지 않습니다.

점포 적재는 전체 입력·키 중복을 검증하며 1,000행 이하 묶음으로 staging한 뒤 실제 staging 건수·자치구/업종 FK를 확인하고, 대상 행 Upsert와 `PUBLISHED`를 한 트랜잭션으로 반영합니다. 파일에 없는 이전 키는 보존하며 전체 조합을 요구하지 않습니다. 동일 체크섬·ETL 버전의 정상 `PUBLISHED` 배치(`CSV`·`SEOUL`·범위 코드 NULL·게시 시각 존재)와 실제 저장값 7개(비율의 소수 자릿수 포함)·게시 출처가 모두 일치해야 `SKIPPED`로 기록하고 기존 출처를 유지합니다. 오류는 반영을 롤백한 뒤 `FAILED`로 기록하며 기존 정상 데이터를 보존합니다. 이 적재·게시 동작은 `--probe` 분기에서는 실행하지 않습니다.

공식 점포 조회는 `GET /api/v1/districts/{districtCode}/stats/stores?quarterCode=20262&industryCode=CS100010`으로 구현했습니다. `db` 프로필에서 최신 정상 경계의 자치구를 확인한 뒤 `district_store_stat`을 직접 읽고, 각 행의 `SEOUL_DISTRICT_STORE_STAT`·`CSV`·`SEOUL`·범위 코드 NULL·`PUBLISHED`·게시 시각 존재 조건을 검증합니다. 정상 게시 이력뿐 아니라 이를 참조하는 실제 행이 있어야 준비 상태이며, 과거 정상 분기도 전역 최신 배치 제한 없이 조회합니다. 경계·통계 미준비는 503, 현행 자치구 미존재는 404, 준비 후 조건별 행 미존재는 `200`과 `data: null`입니다.

측정값은 문자열 또는 JSON `null`로 보내 BIGINT·NUMERIC 정밀도·소수 자릿수·0·NULL 및 100% 초과 비율을 유지합니다. 측정값이 모두 NULL인 행도 데이터 객체와 실제 `sourceBatch`를 반환합니다. 원본 경로·체크섬·인증정보를 노출하지 않고 경계·통계·출처를 읽기 전용 `REPEATABLE_READ` 스냅샷에서 조회합니다. 입력·응답·합성 JSON의 확정 계약은 [자치구 점포 API 계약](data-design.md#자치구-점포-통계-rest-api-계약)에 있습니다. 자치구 매출·인구 API는 아직 없으며, 정확한 분기·업종 유지와 원본 정밀도·NULL·출처 보존, 자동 분기·행정동 합산 대체 금지 원칙을 후속 설계에서도 따릅니다.

## 미확인 사항과 다음 검증

1. 제공된 점포 CSV는 위 실제 검증 결과로 관리합니다. 공식 배포 판본과의 동일성·구/업종별 결측 사유 및 자치구 매출·인구 CSV·ZIP 전체는 추가 검증 대상입니다. CSV 성공을 실제 ZIP 파일이나 다른 판본의 검증으로 확대하지 않습니다.
2. 제공된 점포 파일은 `20211`~`20262`의 22개 연속 분기를 확인했습니다. 포털 전체의 정확한 최신 제공 분기와 자치구 매출·인구의 전 기간 연속성은 미확인입니다. 파일별 전체 검증과 공식 배포 판본 대조가 필요합니다.
3. 통계 판본에 적용된 공간 경계와 현재 프로젝트 경계의 일치, 과거 분기의 자치구·행정동 소속 변화는 미확인입니다.
4. OA별 개·폐업률 분모 매핑·반올림, 매출 보정과 기간 의미의 세부 명세, 인구의 공간·시간 배분 및 중복 처리에 대한 집계 동등성은 미확인입니다. 공식 구 통계와 동 합계를 비교할 때 별도 검증해야 합니다.
5. 공식 자치구와 행정동 파생 합계의 실제 수치 대조·일치 허용 오차는 정하지 않았습니다. 근거 없이 동일성 검사나 자동 보정 규칙을 만들지 않습니다.
6. 자치구 점포 V5·ETL·조회 API는 구현했으나 실제 개발 DB 적용·적재는 수행하지 않았습니다. 자치구 매출·인구 DB/ETL·API, 화면·점수·운영 갱신은 후속 범위이며 기존 행정동 통계·적재 계약은 유지합니다.

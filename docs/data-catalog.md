# 원본 데이터 목록

2026-09-30(Asia/Seoul)에 `data/raw/dataset/`의 CSV 6개를 전수 검사했습니다. 사용자 제공 `dataset.zip`은 약 93.43 MiB, CSV 합계는 약 365.72 MiB입니다. 원본은 수정하지 않고 CSV 파싱, 행 수·분기·후보 식별키·지역 코드 집합과 SHA-256을 확인했습니다. 아래의 행 수는 헤더를 제외한 **원본 CSV 레코드 수**이며 DB 적재 완료 건수가 아닙니다.

원천 다운로드일과 이용 조건은 제공된 CSV만으로 확인하지 못했습니다. 검사일을 다운로드일로 사용하지 않습니다. 전체 헤더, 분기별 행 수, 파일 크기·해시와 미확인 항목은 [data/manifest.json](../data/manifest.json)에 기록합니다.

## 보관과 Git 관리

- 입력 위치: `data/raw/dataset/`. 파일명을 유지해 배치합니다.
- CSV와 ZIP은 Git에서 제외하고 `.gitkeep`, 이 문서와 `data/manifest.json`을 Git으로 관리합니다.
- 다른 파일로 교체하거나 새로운 기간을 추가할 때는 기존 원본의 보존 여부를 확인하고 목록·해시를 갱신합니다. 같은 파일명이어도 해시가 다르면 같은 데이터 버전으로 취급하지 않습니다.
- 재확보한 파일이 현재 목록과 다른 버전이면 기준 기간·지역 코드·헤더를 다시 검사합니다.

## 데이터 연결 기준

첫 조회는 **행정동 + 서울시 서비스 업종 + 2025년 공통 분기**로 시작합니다. 점포 통계와 행정동 매출 모두 425개 행정동 코드가 있으며 두 코드 집합은 완전히 같습니다. 다만 점포 통계에는 100개, 행정동 매출에는 63개 서비스 업종 코드가 있으므로 모든 지역·업종·분기의 매출 값이 존재한다고 가정하지 않습니다. 조회 API는 누락된 값을 0과 구분해야 합니다.

상권 매출의 1,577개 상권 코드는 영역 자료의 1,650개 상권 코드에 모두 포함됩니다. 매출 코드의 참조 누락은 0개이고, 영역에는 있지만 매출에 없는 상권 코드는 73개입니다. 영역 자료에 나타나는 행정동은 399개로 통계의 425개와 다르므로, 영역 자료만으로 행정동 통계 전체의 기준 목록을 만들지 않습니다. 코드가 일치하더라도 경계 버전의 호환성은 추가 확인이 필요합니다.

개별 점포의 `상권업종소분류코드`와 서울시 `서비스_업종_코드`는 다른 코드 체계입니다. V1의 `industry_mappings`에는 `SEOUL` 매핑 네 개만 있으며 `CAFE → SEOUL / CS100010`을 소상공인 코드에 재사용하지 않습니다. `etl_stores.py`는 원본 소분류 코드·명칭을 보존하고 `industry_id`를 NULL로 저장합니다. `SEMAS` 매핑은 CAFE도 공식 분류와 실제 원본 분포를 검증하지 않았으므로 아직 등록하지 않습니다.

개별 점포는 **파일명 기준 2026-06 스냅샷**이며 CSV에 기준 날짜 열이 없습니다. 2025 Q1~Q4 매출·점포 통계와 동일 시점의 자료로 표시하지 않습니다. 공간 분석에서도 업종 매핑·통계 분기·점포 스냅샷을 구분하고, 스냅샷에서 특정 점포가 사라졌다는 사실만으로 폐업을 판단하지 않습니다.

## 좌표와 인구 자료의 한계

영역 CSV에는 상권별 X/Y 대표점과 면적 값이 있으며 **Polygon 경계가 없습니다**. X는 182,509~215,352, Y는 437,249~465,573 범위이고 숫자로 읽을 수 없는 좌표 행은 없었습니다. 범위만으로 좌표계를 확정하지 않습니다.

2026-10-07(Asia/Seoul)에 서울 열린데이터광장 [서울시 상권분석서비스(영역-상권), OA-15560](https://data.seoul.go.kr/dataList/OA-15560/S/1/datasetView.do) 본문에서 **“좌표계 EPSG: 5181”**을 직접 확인했습니다. 현재 공식 데이터셋 메타데이터의 CRS는 **EPSG:5181**입니다. 과거 `EPSG:5186` 기본값과의 충돌은 이 공식 메타데이터를 기준으로 정리합니다. 다만 보관 CSV의 정확한 다운로드일·배포 버전과 현재 공식 페이지에서 제공되는 파일과의 동일 배포본 여부는 여전히 미확인이고, 현재 페이지의 갱신일을 보관 파일의 기준 시점으로 대신 사용하지 않습니다.

현재 `commercial_areas.location GEOMETRY(POINT, 4326)`은 ETL이 원본 X/Y를 EPSG:4326 경위도로 변환해 저장하도록 정의된 **상권 대표 POINT**이며 경계 Polygon이 아닙니다. 이 POINT로 후보 좌표의 상권 포함 여부를 판정할 수 없습니다. `AREA_SOURCE_CRS`는 공란 기본값과 미설정 시 적재 거부를 유지하며, 향후 검산에는 `EPSG:5181`을 명시합니다. 이번에는 환경 설정·ETL 실행·상권 재적재·DB 변경을 하지 않았고, **EPSG:5181 → EPSG:4326 실제 좌표 변환 검산은 미완료**입니다.

현재 보유 원본에는 행정동·상권 Polygon 파일이 없습니다. 행정동 통계 425개와 연결할 행정동 Polygon을 우선 확보·검증하고, 이후 상권 Polygon을 검토합니다. 서울 열린데이터광장 [영역-행정동, OA-22160](https://data.seoul.go.kr/dataList/OA-22160/S/1/datasetView.do)의 경계 ZIP 안내도 확인했지만 파일은 내려받지 않았습니다. 안내 페이지 확인은 geometry·코드 집합·이름·SRID·2025 통계와의 버전 호환성 검증을 대신하지 않습니다([검증 절차](spatial-data-validation.md)).

`data/manifest.json`은 2026-09-30의 입력 검사 기록으로 유지합니다. 당시 `source_coordinate_crs: null`과 5181/5186 충돌 이력을 이번 문서 확인만으로 덮어쓰지 않습니다. 공식 CRS의 기계 검증 방식과 manifest 반영은 후속 단계에서 결정합니다.

개별 점포의 `경도` 범위는 약 126.7682~127.1827, `위도`는 약 37.4305~37.6926이고 누락되거나 숫자로 읽을 수 없는 좌표 행은 없었습니다. 경위도 열이 있다는 사실과 원천 좌표계의 공식 검증은 구분합니다.

인구 파일은 서울시 코드 하나에 대해 분기마다 한 행씩 총 22행입니다. 행정동·상권 식별 열이 없어 후보지별 인구 수요나 반경별 인구를 계산할 수 없습니다. 위치별 수요 분석은 원하는 공간 단위의 인구 자료를 추가 확보한 뒤 연결합니다.

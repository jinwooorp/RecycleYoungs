# 원본 데이터 목록

2026-09-30(Asia/Seoul)에 `data/raw/dataset/`의 CSV 6개를 전수 검사했습니다. 사용자 제공 `dataset.zip`은 약 93.43 MiB, CSV 합계는 약 365.72 MiB입니다. 원본은 수정하지 않고 CSV 파싱, 행 수·분기·후보 식별키·지역 코드 집합과 SHA-256을 확인했습니다. 아래의 행 수는 헤더를 제외한 **원본 CSV 레코드 수**이며 DB 적재 완료 건수가 아닙니다.

원천 다운로드일과 이용 조건은 제공된 CSV만으로 확인하지 못했습니다. 검사일을 다운로드일로 사용하지 않습니다. 전체 헤더, 분기별 행 수, 파일 크기·해시와 미확인 항목은 [data/manifest.json](../data/manifest.json)에 기록합니다.

## 보관과 Git 관리

- 입력 위치: `data/raw/dataset/`. 파일명을 유지해 배치합니다.
- CSV와 ZIP은 Git에서 제외하고 `.gitkeep`, 이 문서와 `data/manifest.json`을 Git으로 관리합니다.
- 다른 파일로 교체하거나 새로운 기간을 추가할 때는 기존 원본의 보존 여부를 확인하고 목록·해시를 갱신합니다. 같은 파일명이어도 해시가 다르면 같은 데이터 버전으로 취급하지 않습니다.
- 재확보한 파일이 현재 목록과 다른 버전이면 기준 기간·지역 코드·헤더를 다시 검사합니다.

## 데이터 연결 기준

첫 조회는 **행정동 + 서울시 서비스 업종 + 2025년 공통 분기**로 시작합니다. 점포 통계와 행정동 매출 모두 425개 행정동 코드가 있으며 두 코드 집합은 완전히 같습니다. 다만 점포 통계에는 100개, 행정동 매출에는 63개 서비스 업종 코드가 있으므로 모든 지역·업종·분기의 매출 값이 존재한다고 가정하지 않습니다. 조회 API는 누락된 값을 0과 구분해야 합니다.

상권 매출의 1,577개 상권 코드는 영역 자료의 1,650개 상권 코드에 모두 포함됩니다. 매출 코드의 참조 누락은 0개이고, 영역에는 있지만 매출에 없는 상권 코드는 73개입니다. 영역 자료에 나타나는 행정동은 399개로 통계의 425개와 다르므로, 영역 자료만으로 행정동 통계 전체의 기준 목록을 만들지 않습니다. 코드가 일치하더라도 경계 버전의 호환성은 추가 확인이 필요합니다.

개별 점포의 `상권업종소분류코드`와 서울시 `서비스_업종_코드`는 다른 코드 체계입니다. V1의 `industry_mappings`에는 `SEOUL` 매핑 네 개만 있으며 `CAFE → SEOUL / CS100010`을 소상공인 코드에 재사용하지 않습니다. `etl_stores.py`는 원본 소분류 코드·명칭을 보존하고 `industry_id`를 NULL로 저장합니다. 2026-10-07에 CAFE 범위의 `SEMAS / I21201` 매핑 근거를 검증했지만 DB 등록·ETL 변경은 하지 않았습니다. 나머지 업종의 SEMAS 매핑은 미검증입니다.

개별 점포는 **파일명 기준 2026-06 스냅샷**이며 CSV에 기준 날짜 열이 없습니다. 2025 Q1~Q4 매출·점포 통계와 동일 시점의 자료로 표시하지 않습니다. 공간 분석에서도 업종 매핑·통계 분기·점포 스냅샷을 구분하고, 스냅샷에서 특정 점포가 사라졌다는 사실만으로 폐업을 판단하지 않습니다.

## 좌표와 인구 자료의 한계

영역 CSV에는 상권별 X/Y 대표점과 면적 값이 있으며 **Polygon 경계가 없습니다**. X는 182,509~215,352, Y는 437,249~465,573 범위이고 숫자로 읽을 수 없는 좌표 행은 없었습니다. 범위만으로 좌표계를 확정하지 않습니다.

2026-10-07(Asia/Seoul)에 서울 열린데이터광장 [서울시 상권분석서비스(영역-상권), OA-15560](https://data.seoul.go.kr/dataList/OA-15560/S/1/datasetView.do) 본문에서 **“좌표계 EPSG: 5181”**을 직접 확인했습니다. 현재 공식 데이터셋 메타데이터의 CRS는 **EPSG:5181**입니다. 과거 `EPSG:5186` 기본값과의 충돌은 이 공식 메타데이터를 기준으로 정리합니다. 같은 날 후속 조사에서 현재 공식 CSV를 내려받아 보관 CSV와 byte/SHA-256 동일성을 확인했습니다. 최초 다운로드일·배포 버전 이력은 여전히 미확인이고, 현재 페이지의 갱신일을 보관 파일의 기준 시점으로 대신 사용하지 않습니다.

현재 `commercial_areas.location GEOMETRY(POINT, 4326)`은 ETL이 원본 X/Y를 EPSG:4326 경위도로 변환해 저장하도록 정의된 **상권 대표 POINT**이며 경계 Polygon이 아닙니다. 이 POINT로 후보 좌표의 상권 포함 여부를 판정할 수 없습니다. `AREA_SOURCE_CRS`의 공란 기본값과 미설정 시 적재 거부는 유지합니다. 2026-10-07 임시 파일 분석에서 EPSG:5181 → EPSG:4326 변환 1,650행의 sanity·독립 투영 수치를 검산하고 대표 8점의 행정동 포함을 확인했습니다. 추가 전수 대조의 홍지문 `3110531` 1점은 CSV 지정 부암동 밖/확보 경계의 홍은1동 안이며 원천 참조 기준·경계 버전 차이 원인은 미확인입니다. 환경 설정·ETL 실행·재적재·DB 변경은 없고 보관 CSV의 최초 배포 이력도 여전히 미확인입니다([실제 검사와 범위](project-status.md#2026-10-07-공간-데이터-24단계-실제-검증)).

기존 CSV 6개에는 Polygon이 없지만, 2026-10-07에 공식 행정동 경계 ZIP을 별도 로컬 raw 공간으로 확보했습니다. 후속 홍지문 조사에서 확보한 OA-15560 공식 상권 ZIP도 재사용해 전체 feature의 MVP 최소 품질·코드 대조를 수행했으며 invalid 6건은 미해결입니다. 실제 경계 버전 호환은 이 검사와 구분합니다([검증 절차](spatial-data-validation.md)).

`data/manifest.json`은 2026-09-30의 입력 검사 기록으로 유지합니다. 당시 `source_coordinate_crs: null`과 5181/5186 충돌 이력을 이번 문서 확인만으로 덮어쓰지 않습니다. 공식 CRS의 기계 검증 방식과 manifest 반영은 후속 단계에서 결정합니다.

개별 점포의 `경도` 범위는 약 126.7682~127.1827, `위도`는 약 37.4305~37.6926이고 누락되거나 숫자로 읽을 수 없는 좌표 행은 없었습니다. 경위도 열이 있다는 사실과 원천 좌표계의 공식 검증은 구분합니다.

인구 파일은 서울시 코드 하나에 대해 분기마다 한 행씩 총 22행입니다. 행정동·상권 식별 열이 없어 후보지별 인구 수요나 반경별 인구를 계산할 수 없습니다. 위치별 수요 분석은 원하는 공간 단위의 인구 자료를 추가 확보한 뒤 연결합니다.

## 4단계 미완료 원인 후속 조사

2026-10-07에 현재 공식 [점포-행정동 OA-22172](https://data.seoul.go.kr/dataList/OA-22172/S/1/datasetView.do)·[추정매출-행정동 OA-22175](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do)의 2025 ZIP을 내려받았습니다. 압축 내 CSV는 보관 원본/manifest와 byte·SHA-256·행 수·분기별 코드 집합까지 동일합니다. 현재 제공 파일과의 동일성은 확인했지만 최초 게시일·교체 이력·2026-05-21 수정의 성격은 확인하지 못했습니다.

원본시스템 [서비스 소개](https://golmok.seoul.go.kr/introduce.do)는 발달상권·전통시장 구축에 사용한 2022년 표준단위구역을 통계청 조사·집계구·도로망을 반영한 공간 단위로 설명합니다. 이 설명은 2025 행정동 통계의 환산 규칙이나 참조 경계 기준일을 명시하지 않습니다. 현재 행정동 코드 PDF도 용신동·상일동·일원2동을 유지하지만 고정 기준일/재집계 정책 근거로 해석하지 않습니다. 경계 버전 문제는 **unresolved**, 통계 정책 판정과 전체 공간 검증 판정은 **B**, 로드맵 4단계는 미완료입니다.

OA-15560의 현재 공식 CSV에서 홍지문 `3110531`은 보관 행과 완전히 동일합니다. 반면 같은 페이지의 SHP는 X/Y·상권 코드/이름을 유지하면서 `ADSTRD_CD=11410660`, `ADSTRD_CD_=홍은1동`을 기록하고, 자치구는 여전히 `11110 종로구`입니다. 공식 행정동 코드표의 `11410 서대문구 / 11410660 홍은1동`과 대조하면 SHP 내부에도 종로구 자치구 속성과 서대문구 홍은1동 행정동 속성 사이의 계층 불일치가 있습니다. 확보 행정동 경계와의 교차 면적은 부암동 약 41.133%, 홍은1동 약 58.867%이며 대표점은 해당 상권 MultiPolygon 안에 있지만 면적 centroid와 약 98.625m 다릅니다. 이는 공식 파일 형식 간 속성 차이와 공간 관찰이며 귀속 정책·오류·수정 이력을 증명하지 않습니다. 현재 CSV가 수정된 것도 아니므로 홍지문은 **H5 — 원인 미확인**입니다.

새 공식 파일의 hash·schema, 행정안전부 원본 코드, 분기별 용신동 행 수와 과거 공식 목록 PDF 비교는 [후속 조사 기록](project-status.md#2026-10-07-공간-검증-4단계-미완료-원인-조사)에 둡니다. 보관 CSV·manifest·기존 검증 산출물은 교체하지 않았습니다.

## SEMAS CAFE 6단계 검사 결과

[소상공인365 공식 분류표 공지](https://bigdata.sbiz.or.kr/#/notice/267352041576902656)의 첨부 XLSX(106067 bytes·SHA-256 `89b6aae58262c89225752a5764ffa3901b174113aaa8c3edf148af25a1646986`)는 대/중/소분류 10/75/247개, `I2 음식점업 → I212 비알코올 음료점업 → I21201 카페`를 정의합니다. I21201은 커피전문점/카페/다방·생과일주스·보드게임/사주/전통찻집/애견카페를 통합한 범주이며 커피만의 순수 집합이 아닙니다.

MVP에서는 공식 SEMAS 소분류 경계를 그대로 사용해 자의적 재분류를 피하고 재현성을 확보하는 정책으로 I21201 전체를 CAFE 경쟁군으로 채택합니다. 검증된 `M_cafe={I21201}`, `CAFE → SEMAS / I21201`은 `SEOUL / CS100010`과 독립된 근거입니다. KSIC·상호명으로 추가 필터링하지 않으며 별도 분류의 빵/도넛·떡/한과·아이스크림/빙수·버거·편의점·음료 소매·독서실/스터디 카페는 CAFE에서 제외합니다.

2026-06 서울 원본은 301889640 bytes·UTF-8 BOM·554092행, SHA-256 `08d3fd08b37840256cccd4f09bad6fc33133b647cbff05f22f26fc962cf84152`로 manifest와 일치합니다. I21201은 **22739행 / 고유 source id 22739개**이며 좌표 NULL·파싱 실패·비유한값·전세계 범위 오류·서울권 bbox 밖·중복 ID·같은 ID 복수 소분류 모두 0입니다. bbox는 경도 `[126.7,127.2]`·위도 `[37.4,37.75]`의 sanity 범위이며 정확한 행정경계 포함 검증은 아닙니다.

공식 분류·원본 분포·포함/제외 기준·offline 반경 계산 가능성을 확인해 **6단계 완료: CAFE 범위**로 기록합니다.

# 원본 데이터 목록

2026-09-30(Asia/Seoul)에 `data/raw/dataset/`의 CSV 6개를 전수 검사했습니다. 사용자 제공 `dataset.zip`은 약 93.43 MiB, CSV 합계는 약 365.72 MiB입니다. 원본은 수정하지 않고 CSV 파싱, 행 수·분기·후보 식별키·지역 코드 집합과 SHA-256을 확인했습니다. 아래의 행 수는 헤더를 제외한 **원본 CSV 레코드 수**이며 DB 적재 완료 건수가 아닙니다.

원천 다운로드일과 이용 조건은 제공된 CSV만으로 확인하지 못했습니다. 검사일을 다운로드일로 사용하지 않습니다. 전체 헤더, 분기별 행 수, 파일 크기·해시와 미확인 항목은 [data/manifest.json](../data/manifest.json)에 기록합니다.

## 보관과 Git 관리

- 입력 위치: `data/raw/dataset/`. 파일명을 유지해 배치합니다.
- CSV와 ZIP은 Git에서 제외하고 `.gitkeep`, 이 문서와 `data/manifest.json`을 Git으로 관리합니다.
- 다른 파일로 교체하거나 새로운 기간을 추가할 때는 기존 원본의 보존 여부를 확인하고 목록·해시를 갱신합니다. 같은 파일명이어도 해시가 다르면 같은 데이터 버전으로 취급하지 않습니다.
- 재확보한 파일이 현재 목록과 다른 버전이면 기준 기간·지역 코드·헤더를 다시 검사합니다.

## 데이터 연결 기준

첫 조회는 **행정동 + 서울시 서비스 업종 + 2025년 공통 분기**로 시작합니다. 점포 통계와 행정동 매출 모두 425개 행정동 코드가 있으며 두 코드 집합은 완전히 같습니다. 다만 점포 통계에는 100개, 행정동 매출에는 63개 서비스 업종 코드가 있으므로 모든 지역·업종·분기의 매출 값이 존재한다고 가정하지 않습니다. 조회 API는 누락된 값을 0과 구분해야 합니다.

상권 매출의 1,577개 상권 코드는 영역 자료의 1,650개 상권 코드에 모두 포함됩니다. 매출 코드의 참조 누락은 0개이고, 영역에는 있지만 매출에 없는 상권 코드는 73개입니다. 영역 자료에 나타나는 행정동은 399개로 통계의 425개와 다르므로, 영역 자료만으로 행정동 통계 전체의 기준 목록을 만들지 않습니다. 코드가 일치하더라도 경계 버전의 호환성은 추가 확인이 필요합니다.

개별 점포의 `상권업종소분류코드`와 서울시 `서비스_업종_코드`는 다른 코드 체계입니다. 개별 점포의 파일명 기준 2026년 6월 스냅샷과 2025년 매출·점포 통계를 동일 시점의 자료로 표시하지 않습니다. 두 자료를 연결할 때 업종 매핑과 서로 다른 기준 시점을 함께 표시합니다.

## 좌표와 인구 자료의 한계

영역 CSV에는 상권별 X/Y 기준점과 면적 값이 있으며 **Polygon 경계가 없습니다**. X는 182,509~215,352, Y는 437,249~465,573 범위이고 숫자로 읽을 수 없는 좌표 행은 없었습니다. 범위만으로 좌표계를 확정할 수 없습니다. 정리 전 문서의 `EPSG:5181`과 ETL 기본값의 `EPSG:5186`이 충돌했으므로, 원천 좌표계 메타데이터 확인 후 `AREA_SOURCE_CRS`를 명시적으로 설정해야 합니다. 이 점을 상권 포함 판정에 사용하지 않으며 좌표 기반 포함 조회에는 통계와 호환되는 별도의 경계 자료가 필요합니다.

개별 점포의 `경도` 범위는 약 126.7682~127.1827, `위도`는 약 37.4305~37.6926이고 누락되거나 숫자로 읽을 수 없는 좌표 행은 없었습니다. 경위도 열이 있다는 사실과 원천 좌표계의 공식 검증은 구분합니다.

인구 파일은 서울시 코드 하나에 대해 분기마다 한 행씩 총 22행입니다. 행정동·상권 식별 열이 없어 후보지별 인구 수요나 반경별 인구를 계산할 수 없습니다. 위치별 수요 분석은 원하는 공간 단위의 인구 자료를 추가 확보한 뒤 연결합니다.

# ETL 가이드

이 문서는 처음 데이터를 적재하거나 이미 게시된 값을 원본과 대조하는 개발자를 위한 안내입니다.

ETL은 원본 데이터를 수집하고 검증한 뒤, 서비스에서 쓸 수 있는 형식으로 바꿔 DB에 저장하는 작업입니다.

새 DB에서는 테이블을 만든 뒤에도 지역과 상권 데이터를 준비해야 합니다.

데이터가 게시되면 서비스에서 조회할 수 있습니다.

현재 ETL은 터미널에서 명령을 입력하는 방식인 CLI로 수동 실행합니다.

## 전체 데이터 흐름

1. 필요한 자료를 고르고, 어느 시점에 제공된 원본인지 확인합니다.

2. 읽기 전용 검사인 `--probe`가 제공되면 먼저 실행합니다.

3. 대상 DB와 기준 데이터를 확인한 뒤 적재 명령으로 게시합니다.

   경계와 업종 기준은 이를 참조하는 통계보다 먼저 준비합니다.

4. 게시 범위와 행 수, 데이터가 어느 입력에서 왔는지 확인합니다.

   같은 입력으로 재실행했을 때 정상 데이터가 유지되는지도 확인합니다.

## 공공데이터 원천

서울신용보증재단의 구·동 통계는 서울 열린데이터광장에서 제공합니다.

점포와 추정매출은 지역·분기·업종을 기준으로 집계합니다.

현재 MVP의 카페 통계에는 서울시 업종 코드 `CS100010`을 사용합니다.

길 단위 유동인구는 지역·분기 단위이며 업종 구분이 없습니다.

| 자료 | 확인할 수 있는 내용 |
| --- | --- |
| 행정동별 점포 현황 | 동과 업종별 전체·일반·프랜차이즈 점포 수, 개·폐업 수와 비율 |
| 자치구별 점포 현황 | 같은 지표를 자치구 단위로 집계한 공식 값 |
| 행정동별 추정매출 | 동과 업종별 당월 추정매출액·건수와 주중·주말 금액 |
| 자치구별 추정매출 | 같은 지표를 자치구 단위로 집계한 공식 값 |
| 행정동별 길 단위 유동인구 | 길 구간에 배분한 추정 인구의 행정동별 총계와 남성·여성 수 |
| 자치구별 길 단위 유동인구 | 같은 지표를 자치구 단위로 집계한 공식 값 |

위 자료명은 문서에서 쓰는 설명용 이름입니다.

공식 명칭과 호출에 필요한 값은 별도 표에 정리했습니다.

처음 확인한 공공누리 제1유형의 출처 표시 조건을 보존하고, 사용할 판본의 이용조건을 확인합니다.

[원본 자료 및 API 식별 정보](#원본-자료-및-api-식별-정보)

지역 경계는 행정동 도형 파일인 Shapefile에서 가져옵니다.

서비스의 자치구 경계는 같은 구에 속한 행정동 도형을 합쳐 만듭니다.

별도의 공식 자치구 경계 ZIP은 이 결과를 대조할 때 사용할 수 있는 후보입니다.

[행정동 경계 원천(OA-22160)](https://data.seoul.go.kr/dataList/OA-22160/S/1/datasetView.do) · [자치구 경계 원천(OA-22161)](https://data.seoul.go.kr/dataList/OA-22161/S/1/datasetView.do)

개별 카페의 위치와 업소 정보는 소상공인시장진흥공단 자료를 사용합니다.

지도나 반경의 카페 수와 구·동 전체의 점포 통계는 원천과 포함 범위가 다릅니다.

최신 목록에서 업소가 빠져도 폐업으로 간주하지 않습니다.

[상가(상권)정보 API](https://www.data.go.kr/data/15012005/openapi.do)

## 지원 입력과 인증키

파일 입력은 준비한 원본을 읽습니다.

API 수집은 제공기관에 요청을 보내 페이지 단위로 값을 가져옵니다.

파일과 API 모두 검증과 게시 단계를 구분합니다.

| 대상 | 지원 입력 | 인증 |
| --- | --- | --- |
| 행정동 경계 | Shapefile ZIP 또는 `.shp`와 같은 이름의 `.dbf`, `.prj`, `.cpg` | 로컬 파일 |
| 서비스 업종 기준 | 행정동별 점포 현황 CSV 필수, 행정동별 추정매출 CSV 선택 | 로컬 파일 |
| 서울시 통계 6종 | CSV, CSV 하나를 담은 ZIP 또는 서울시 Open API | 파일은 키 불필요. API는 `SEOUL_OPEN_API_KEY` 일반 키 |
| 개별 카페 | 소상공인시장진흥공단의 고정 HTTPS API | 활용 승인된 공공데이터포털 Decoding 키를 `SEMAS_API_KEY`로 설정 |

공식 파일은 각 데이터셋 페이지에서 다운로드합니다.

Sheet 미리보기와 공개 API의 작은 표본으로 전체 기간이나 포함 범위를 판단하지 않습니다.

대체 경계 API의 도형·면적·코드·판본 동등성과 통계 CSV를 대체할 독립 업종 API는 미확인입니다.

개별 카페를 별도 파일과 대조할 때는 기준년월, 서울 범위와 업종 소분류를 먼저 맞춥니다.

업소번호로 같은 업소를 찾아 분류·행정동 코드, 주소, 좌표와 빈 값을 비교합니다.

[소진공 명세](https://www.data.go.kr/data/15012005/openapi.do)

## 설치 및 공통 실행

Node.js 24와 npm 11을 준비한 후 저장소 루트에서 시작합니다.

```bash
cd etl
npm ci
npm run dev -- --help
```

이후 명령은 `etl/`에서 실행합니다.

빌드 결과를 사용할 때는 `npm run build` 뒤에 `npm start -- …`로 같은 인자를 전달합니다.

인자 없이 실행하거나 `--help`를 지정하면 DB 연결 없이 도움말을 표시합니다.

[CLI 도움말 구현](../etl/src/cli/help.ts)

파일 검사만 한다면 원본과 해당 판본의 기대 행 수를 준비합니다.

DB 대조나 적재를 한다면 로컬 DB의 주소, 권한, 백업과 기준 데이터를 확인합니다.

DB 구조 변경 이력을 관리하는 Flyway의 적용 버전도 확인합니다.

[로컬 DB](SETUP.md#로컬-db-준비) · [마이그레이션](DATABASE.md#db-마이그레이션-방향)

`DATABASE_URL`은 `localhost`, `127.0.0.1`, `::1`만 허용합니다.

접속 URL의 쿼리로 호스트 등을 덮어쓸 수 없습니다.

URL의 비밀번호에 예약 문자가 있으면 인코딩합니다.

환경변수는 실행 위치의 `.env`나 셸에서 설정합니다.

두 곳에 같은 변수가 있으면 셸 값이 우선합니다.

루트의 공통 설정을 사용하려면 `etl/`에서 다음 명령을 실행합니다.

```bash
set -a
source ../.env
set +a
```

DB 연결 수를 정하는 `DB_POOL_MAX`의 기본값은 10입니다.

연결 대기 시간을 정하는 `DB_CONNECTION_TIMEOUT_MS`의 기본값은 5,000ms입니다.

두 값은 양의 정수입니다.

[ETL 환경변수 예시](../etl/.env.example)

실제 키는 서버 측 환경변수로만 전달합니다.

키, 전체 인증 URL, 접속 정보, 원본 경로는 결과나 외부 로그에 남기지 않습니다.

원본, 실제 환경 파일, 로컬 검사용 입력 목록은 Git 외부에서 관리합니다.

## 공통 입력 검증과 게시

검사는 파일을 읽을 수 있는지 확인하는 것부터 시작합니다.

그다음 지역·분기·업종으로 행을 식별할 수 있는지, 측정값이 유효한지 확인합니다.

### 파일과 행을 검사하는 기준

CSV 인코딩은 UTF-8(BOM 포함) 또는 CP949입니다.

ZIP은 파일이 손상되지 않았는지 CRC로 확인하고, 512 MiB 제한 안에서 CSV 하나를 메모리로 읽습니다.

통계 CSV의 체크섬은 파일 바이트를 비교하기 위한 SHA-256 값입니다.

ZIP 전체가 아니라 내부 CSV를 기준으로 계산합니다.

필수 열 이름은 한글과 영문 이름 중 하나를 사용합니다.

열이 빠졌거나 중복되거나 어느 열인지 모호하면 거부합니다.

행의 열 수가 헤더와 달라도 실패합니다.

[측정값의 한글·영문 헤더](DATABASE.md#구동-공통-측정값)

| 행을 식별하는 항목 | CSV 헤더 | 입력 형식 |
| --- | --- | --- |
| 자치구 | 자치구_코드 / `SIGNGU_CD` | ASCII 숫자 5자리 |
| 행정동 | 행정동_코드 / `ADSTRD_CD` | ASCII 숫자 8자리 |
| 분기 | 기준_년분기_코드 / `STDR_YYQU_CD` | `YYYYQ` |
| 점포·매출의 업종 | 서비스_업종_코드 / `SVC_INDUTY_CD` | `CS`와 ASCII 숫자 6자리 |

지역·분기와 필요한 경우 업종을 조합한 키를 복합키라고 합니다.

동일 복합키가 반복되면 실패합니다.

파일의 `--expected-rows`에는 헤더를 제외한 전체 행 수를 양의 안전한 정수로 지정합니다.

### 숫자와 비어 있는 값

빈 수치 셀은 NULL로 처리합니다.

실제 0과 원본에 행 자체가 없는 경우는 각각 구분합니다.

공백, 문자 `NULL`, NaN, Infinity는 거부합니다.

수치를 JavaScript `Number`로 바꾸거나 반올림하지 않습니다.

[DB의 결측과 정밀도](DATABASE.md#결측과-정밀도)

| 수치 | 허용 형식과 변환 |
| --- | --- |
| 행정동별 점포 현황의 건수 | 0 이상 BIGINT 정수 문자열. 소수·지수 표기 거부 |
| 자치구별 점포 현황의 건수와 구·동 추정매출 | 0 이상 BIGINT. 정수 의미의 `749.0`이나 지수 표기는 정수 문자열로 변환. 비정수와 음수 표기(`-0` 포함) 거부 |
| 구·동 개·폐업률 | 0 이상 일반 십진수. 지수 거부. 소수 자릿수와 후행 0 보존. 100% 상한 없음 |
| 구·동 길 단위 유동인구 | 0 이상 NUMERIC. 허용 범위의 정수·소수·지수를 정확히 변환하고 소수 자릿수 보존. 음수 표기(`-0` 포함) 거부. 범위 밖 지수로 표기한 0은 `"0"` |

BIGINT는 정수를 저장하는 형식으로 허용하는 최대값은 `9223372036854775807`입니다.

NUMERIC은 소수까지 정확히 저장하는 형식입니다.

정수부 131,072자리와 소수부 16,383자리 한계를 적용합니다.

원본의 합계 차이는 보존합니다.

[집계 정책](#공식-자치구-통계와-집계-정책)

### 배치 상태와 재실행

검증한 행은 staging이라는 중간 저장 공간에 옮깁니다.

통계와 카페는 한 번에 최대 1,000행을 옮깁니다.

기대 행 수, 유효 행 수와 실제 게시 후보 행 수를 확인합니다.

지역·업종 기준 행이 있는지는 외래키(FK) 조건으로 검사합니다.

유동인구는 지역 외래키만 확인합니다.

같은 데이터셋의 쓰기는 한 번에 하나씩 처리하고 필요한 기준 데이터를 잠급니다.

기존 키는 갱신하고 새 키는 추가하는 Upsert를 사용합니다.

값 반영과 실행 이력 확정은 하나의 트랜잭션에서 처리합니다.

| 배치 상태 | 확인할 내용 |
| --- | --- |
| `RUNNING` | 수집·검증·적재 진행 중 |
| `PUBLISHED` | 데이터와 정상 게시 이력을 함께 확정 |
| `SKIPPED` | 같은 입력·버전과 실제 값·소수 자릿수·출처를 명령별로 대조한 결과 기존 정상 게시 유지. 새 게시 시각 없음 |
| `FAILED` | 수집·검증·반영이 실패해 부분 변경을 되돌림. 정상 값·출처는 유지. 배치 생성 전이나 DB 연결 실패 시 기록이 없을 수 있음 |

같은 체크섬이어도 현재 값이나 출처가 다르면 다시 게시합니다.

통계는 새 입력에 없는 기존 키·출처를 유지합니다.

경계에서 기존 코드가 빠지면 적재를 중단합니다.

카페는 이전 수집의 업소 행을 보존하고 최신 목록은 최신 배치의 행에서 조회합니다.

## 읽기 전용 검증

파일만 검사하려면 `--probe`를 지정합니다.

자치구별 점포 현황, 추정매출, 길 단위 유동인구의 기본 검사는 파일 전체를 읽습니다.

DB나 인증 요청을 사용하지 않으며, 최대 5행을 표본으로 반환합니다.

아래 경로와 건수는 검증한 판본의 예시입니다.

```bash
npm run dev -- district-stores --probe --source /절대경로/자치구점포.csv --expected-rows 54765
npm run dev -- district-sales --probe --source /절대경로/자치구매출.csv --expected-rows 33803
npm run dev -- district-foot-traffic --probe --source /절대경로/자치구인구.csv --expected-rows 550
```

성공한 결과에서 `mode=PROBE`와 `validationScope=LOCAL_FILE_FORMAT`으로 검사 종류를 확인합니다.

`databaseChecked=false`, `batchCreated=false`, `loadedRows=0`은 DB를 읽거나 쓰지 않았음을 보여 줍니다.

`datasetId`, `serviceName`, 예상·판독·유효·거부 건수, 분기 범위, `checksum`, `encoding`, `sample`도 반환합니다.

매출 4개, 인구 3개 등 채택한 측정값이 검사 대상입니다.

표본에는 원본 경로·ZIP 항목·배치 ID가 들어가지 않습니다.

실패 시 종료 코드 1과 안전한 오류를 반환하며 부분 성공 JSON은 없습니다.

[채택 측정값](DATABASE.md#구동-공통-측정값)

자치구별 길 단위 유동인구는 `--compare-db`를 추가해 게시 값도 읽기 전용으로 확인할 수 있습니다.

### 공식 자치구 CSV 갱신 사전검증

자치구의 세 자료를 한 번에 확인하려면 매니페스트라는 UTF-8 JSON 입력 목록을 준비합니다.

각 자료를 한 번씩 지정합니다.

`source`에는 절대경로나 목록 파일 기준 상대경로를 사용합니다.

필요하면 내부 CSV의 64자리 16진수 해시를 `expectedSha256`으로 추가합니다.

```json
{
  "datasets": [
    { "datasetId": "OA-22173", "source": "stores.csv", "expectedRows": 3 },
    { "datasetId": "OA-22176", "source": "sales.zip", "expectedRows": 2 },
    { "datasetId": "OA-22179", "source": "foot-traffic.csv", "expectedRows": 2 }
  ]
}
```

```bash
npm --silent run dev -- official-sources --probe --manifest /절대경로/official-sources.json
```

이 명령은 DB와 네트워크를 사용하지 않습니다.

파일별 행 수·해시·기간과 분기별 구 집합을 확인합니다.

`checksumVerification`은 `MATCHED`, `MISMATCH`, `NOT_PROVIDED`, `NOT_CHECKED`를 구분합니다.

세 입력이 통과하면 `coverageComparison`에서 범위 차이도 보고합니다.

파일·해시·건수 오류는 `FAIL`과 종료 코드 1로 표시합니다.

판독을 끝내지 못하면 전체 집계는 `null`입니다.

성공은 입력 형식과 실제로 확인한 범위에 해당합니다.

## 서울시 Open API 전체 수집 probe

1. 자료 식별 정보와 구·동 범위, 조회 시각, API 전체 예상 건수를 확인합니다.

   비교 CSV의 분기와 내부 SHA-256도 확인합니다.

   API 전체 건수와 최근 기간 Sheet CSV의 건수는 따로 기록합니다.

   [자료 식별 정보](#원본-자료-및-api-식별-정보) · [판본 재확인 근거](#공식-출력의-재확인-조건)
2. 전송 주소와 방식, 발급 계정의 호출 한도, 기본·최대 요청 수를 확인합니다.

   실제 키를 전송하기 전에 승인을 받습니다.

   기본 요청 수는 전체 행 수를 페이지 크기로 나누어 올림한 값입니다.

   최대 요청 수에는 일시 실패 시 페이지당 한 번의 재시도를 포함합니다.

3. `--probe`로 API와 CSV의 키를 양쪽 방향으로 확인하고 채택 측정값을 대조합니다.

   정확한 십진수 값을 비교하고 후행 0 등 표현 차이는 별도로 셉니다.

   NULL과 0을 구분합니다.

   총건수·페이지·키·수치가 다르면 게시를 보류합니다.

4. 게시하려면 대상 DB, 백업과 쓰기 범위에 대해 별도 승인을 받습니다.

   게시 후 건수·출처·시각과 재실행 동작을 확인합니다.

   같은 값이 다시 수집돼도 원천의 내부 스냅샷과 이후 응답이 같다고 단정할 수 없습니다.

### 전송과 인증 조건

코드의 서울시 수집 주소는 `http://openapi.seoul.go.kr:8088`입니다.

`--allow-insecure-http`는 이 주소에만 평문 전송을 허용합니다.

HTTP에서는 키와 응답이 노출되거나 변조될 수 있습니다.

코드는 다른 주소로 다시 보내는 리다이렉트를 따르지 않습니다.

키가 없거나 `sample`이거나 평문 전송을 허용하지 않으면 실제 수집 전에 차단합니다.

공개 `sample`은 1~5행을 제공하는 별도 표본입니다.

공식 HTTPS 허용 목록은 비어 있습니다.

2026-11-10 당시 공개 표본 HTTPS는 443에서 시간 초과, 8088에서 TLS 실패였습니다.

안내 페이지의 HTTPS와 API 전송의 HTTPS 지원 여부는 각각 확인합니다.

공식 Sheet CSV나 파일을 내려받아 검사하는 경로도 사용할 수 있습니다.

[수집 설정](../etl/src/common/config.ts) · [서울시 Open API 이용안내](https://data.seoul.go.kr/together/guide/useGuide.do)

### 검사와 게시에 쓰는 인자

`--api`와 함께 `--probe` 또는 `--publish` 중 하나를 지정합니다.

파일용 `--source`는 `--api`와 함께 사용할 수 없습니다.

| 자료와 실행 방식 | `--expected-rows` | `--compare-csv` | `--compare-db` | `--csv-period` |
| --- | --- | --- | --- | --- |
| 자치구별 길 단위 유동인구 검사 | 선택 | 선택 | CSV 대조를 함께 지정할 때 선택 | 미지원 |
| 자치구별 길 단위 유동인구 게시 | 필수 | 미지원 | 미지원 | 미지원 |
| 나머지 5종 검사 | 필수 | 선택 | 미지원 | CSV 대조를 함께 지정할 때 선택 |
| 나머지 5종 게시 | 필수 | 필수 | 미지원 | 선택 |

### 자치구별 길 단위 유동인구 대조

첫 명령은 파일과 DB를 대조합니다.

두 번째 명령은 승인된 API 수집 결과도 함께 대조합니다.

예시의 550행은 해당 판본의 값입니다.

```bash
npm --silent run dev -- district-foot-traffic --probe \
  --source /절대경로/자치구인구.csv --expected-rows 550 --compare-db

npm --silent run dev -- district-foot-traffic --api --probe --allow-insecure-http \
  --expected-rows 550 --compare-csv /절대경로/자치구인구.csv --compare-db
```

`--compare-db`는 읽는 동안 같은 DB 상태를 보도록 `REPEATABLE READ`로 조회합니다.

전체 키, 채택 측정값, 게시 출처를 읽은 뒤 트랜잭션을 롤백합니다.

CSV 출처의 체크섬은 대조 CSV와 일치해야 합니다.

API 출처는 정규화한 행의 체크섬을 사용합니다.

`matchingCsvSourceRows`에는 일치한 CSV 출처 행만 셉니다.

결과의 `databaseChecked=true`, `batchCreated=false`, `loadedRows=0`과 양방향 대조 결과를 확인합니다.

### 자치구별 길 단위 유동인구 API 게시

V7과 자치구 기준 데이터가 필요합니다.

실제 키 전송과 대상 DB 쓰기를 각각 승인받은 뒤 실행합니다.

```bash
npm run dev -- district-foot-traffic --api --publish --allow-insecure-http --expected-rows 550
```

이 명령은 먼저 `RUNNING`을 기록합니다.

전체 수집을 검증한 뒤 중간 저장, 외래키 검사, 게시를 진행합니다.

체크섬은 자치구·분기 키순으로 정렬한 행을 기준으로 합니다.

정규화한 행을 고정 순서 JSON 배열과 줄바꿈으로 표현해 UTF-8로 해시합니다.

값이 같아도 출처가 CSV에서 API로 바뀌면 새 정상 게시로 기록합니다.

### 점포·추정매출과 행정동별 길 단위 유동인구 API 수집·게시

점포와 추정매출은 행정동과 자치구 자료를 모두 지원합니다.

길 단위 유동인구는 이 절에서 행정동 자료를 다룹니다.

[다섯 자료의 CLI 명령](#원본-자료-및-api-식별-정보)

`--expected-rows`에는 API 전체 행 수를 지정합니다.

`--csv-period`를 사용하면 API 전체를 읽되, 비교 CSV에 실제로 있는 분기만 대조하고 게시합니다.

아래 775,084행은 당시 행정동별 점포 현황 API의 전체 건수 예시입니다.

```bash
npm --silent run dev -- stores --api --probe --allow-insecure-http \
  --expected-rows 775084 --compare-csv /절대경로/행정동점포.csv --csv-period

npm --silent run dev -- stores --api --publish --allow-insecure-http \
  --expected-rows 775084 --compare-csv /절대경로/행정동점포.csv --csv-period
```

검사는 DB 없이 실행하며 전체 키 중복과 업종명 충돌을 확인합니다.

게시는 같은 수집의 트랜잭션에서 임시 저장 공간을 채웁니다.

양방향 CSV 대조, 외래키와 업종 기준을 통과한 자료만 확정합니다.

수집 동안 연결과 트랜잭션 하나가 유지되므로 시간·연결 제한을 확인합니다.

실패하면 롤백하고 처음부터 재실행합니다.

배치에는 전체 수집 건수와 게시 후보 건수를 나누어 기록합니다.

분기, 페이지 수, 범위 밖 행 수, 비교 CSV 해시도 기록합니다.

API 체크섬은 복합키·측정값·업종명 배열의 행별 해시를 복합키순으로 이은 뒤 다시 SHA-256을 계산한 값입니다.

재실행은 최신 완전 서울 배치의 실제 값과 출처까지 확인합니다.

## 게시 결과 확인

의도한 로컬 DB의 배치를 읽기 전용으로 확인합니다.

아래 데이터셋과 테이블은 작업에 맞게 바꿉니다.

```sql
SELECT batch_id, status, source_checksum, expected_rows, fetched_rows,
       valid_rows, rejected_rows, period_from, period_to, published_at
FROM etl_batch WHERE dataset_code = 'SEOUL_DISTRICT_STORE_STAT'
ORDER BY started_at DESC;

SELECT source_batch_id, count(*), min(quarter_code), max(quarter_code)
FROM district_store_stat
GROUP BY source_batch_id;
```

기대 범위와 건수, 실제 출처, `PUBLISHED` 시각을 확인합니다.

`SKIPPED`에서는 이전 출처와 값이 유지돼야 합니다.

경계는 구·동 수, SRID, 유효 도형과 내부 대표점을 확인합니다.

카페는 최신 적격 배치의 행만 집계합니다.

### 실패했을 때 확인할 사항

| 증상 | 확인할 곳 |
| --- | --- |
| 파일 검사 실패 | 파일 경로, 인코딩, 헤더와 기대 행 수 |
| API 요청 차단 또는 건수 불일치 | 승인, 키와 전송 방식, 조회 범위, 페이지 수와 제공기관의 전체 건수 |
| 적재 실패 | 로컬 DB 대상, 마이그레이션 버전, 지역·업종 기준 행, 배치 상태 |
| 값은 맞지만 출처나 기간이 다름 | 입력 판본의 해시·분기와 실제 행의 출처 배치 |

원인을 해소한 뒤 재실행합니다.

`source_reference`와 오류 세부 정보는 내부 확인에만 사용합니다.

## 공식 자치구 통계와 집계 정책

자치구 통계는 공식 구 자료를 사용합니다.

빠진 구 값을 동 합계나 평균으로 대체하거나, 공식 값과 파생값을 같은 응답에 섞지 않습니다.

지역 전체 수치를 500m·1km 반경의 실측값으로 환산하지 않습니다.

### 점포 수와 개·폐업률

점포와 개·폐업 수는 공식 원본의 값을 유지합니다.

전체와 세부 값이 달라도 보정하지 않습니다.

여러 분기의 점포 수를 더해 연간 점포 수로 쓰지 않습니다.

개·폐업 건수를 합산하려면 기간 경계, 신고 기준, 수정 판본이 호환되는지 확인합니다.

개·폐업률은 원본 비율과 소수 자릿수를 유지합니다.

100% 상한을 적용하거나 재계산하지 않습니다.

동별 비율을 단순 합산하거나 평균 내지 않으며 임의 가중치도 적용하지 않습니다.

파생 비율을 검토하려면 같은 분자·분모 정의와 기간, 반올림 전 값, 중복 없는 포함 범위가 필요합니다.

분모가 0 또는 NULL이거나 일부 동이 빠지면 계산을 보류합니다.

### 추정매출과 길 단위 유동인구

추정매출은 원 단위를 사용하고 원천이 말하는 `당월`의 의미를 유지합니다.

분기 합계나 월평균으로 환산하지 않습니다.

주중·주말 합계가 다르더라도 값을 조정하지 않습니다.

금액과 건수를 합산하기 전에는 기간, 범위, 보정, 반올림, 중복 기준을 확인합니다.

길 단위 유동인구는 서울시·KT 생활인구를 길 구간에 배분한 추정 규모입니다.

고유 방문자 수, 카페 고객 수, 반경 인구로 해석하지 않습니다.

공간·시간에 배분하는 방식과 중첩을 검증하기 전에는 합산하거나 일평균으로 환산하지 않습니다.

총계에 성별·시간대 같은 세부 값을 다시 더하거나 업종별로 반복 집계하지 않습니다.

[지표 제공 설명](https://golmok.seoul.go.kr/introduce.do)

### 행정동 값으로 별도 통계를 계산할 때

합산에 의미가 있다고 검증된 지표에 한해 별도 표시를 검토합니다.

분기·업종·원천 판본·산식이 같아야 합니다.

해당 시점의 구 소속, 동의 전체 범위와 중복 여부도 확인합니다.

빠진 동·업종이나 NULL을 0으로 채우지 않습니다.

계산식과 입력 출처를 기록합니다.

공식 구 값과 차이가 있다면 판본, 기간, 경계, 포함 범위, 추정 방식과 반올림을 확인합니다.

허용 오차와 비교 산식은 미확정입니다.

`OFFICIAL_DISTRICT`와 `DERIVED_DONG`은 출처 표기 후보입니다.

### API 요청과 수집 한도

서울시 요청 경로는 `/{KEY}/json/{SERVICE}/{START_INDEX}/{END_INDEX}/` 형식입니다.

행 번호는 1부터 시작하며 시작 번호와 끝 번호를 모두 포함합니다.

개별 카페의 소진공 API에서 `smallUpjongList`는 업종 분류 조회에 사용합니다.

`storeListInDong`은 업소 목록을 조회합니다.

| 서울시 API 수집 한도 | 자치구별 길 단위 유동인구 | 나머지 5종 |
| --- | --- | --- |
| 페이지당 행 수 | 최대 100행 | 최대 1,000행 |
| 전체 수집 | 최대 100,000행 | 최대 100만 행·1,000페이지 |
| 페이지 본문 · 시간 | 4 MiB · 요청과 본문 읽기 10초 | 4 MiB · 10초 |
| 추가 크기 제한 | 정규화 수치 문자열 32 MiB | 페이지당 정규화 데이터 16 MiB, 비교 CSV 데이터 128 MiB |

자치구별 길 단위 유동인구는 `INFO-000` 응답과 구간별 건수를 검사합니다.

헤더의 전체 건수인 `list_total_count`가 일정한지 확인합니다.

자치구·분기 키가 중복되지 않는지도 확인합니다.

나머지 5종은 페이지를 순차 처리합니다.

# 점수 입력 스냅샷 외부 보존·오프라인 검증 도구

**상태:** 명시 실행용 도구를 구현하고 합성 입력·일회용 PostGIS로 검증합니다. 이번 작업에서는 실제 개발 DB 내보내기·실제 원본 저장·승인 manifest 발급을 하지 않습니다. 보관 위치·백업 체계와 운영 책임자는 아직 미확정입니다.

기준은 [계산 계약 6.2절](score-v1-contract.md#62-승인-입력-스냅샷을-불변-배포-아티팩트로-보존), [R01·R02 계산·직렬화 규칙](score-snapshot-reproducibility.md), [R03의 남은 한계](archive/score-r03-validation.md)입니다. 기존 계산식·Repository·Service·API 계약은 바꾸지 않습니다.

## 1. 두 도구의 실행 조건

| Gradle 작업           | 실행 조건                                                           | 수행 내용                                                                 |
| --------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `scoreSnapshotExport` | `SCORE_SNAPSHOT_EXPORT_ENABLED=1`, DB 환경변수, 외부 절대 출력 경로 | 한 읽기 전용 스냅샷에서 구·동 전체 입력을 읽고 검증·롤백 후 새 파일 보존  |
| `scoreSnapshotVerify` | `SCORE_SNAPSHOT_INPUT_PATH`로 파일 하나를 명시                      | DB·Spring Context 없이 두 아티팩트의 형식·해시·출처·집단·정확한 결과 재현 |

도구는 `backend/src/scoreRegression/`에 있으며 일반 `test`·`integrationTest`·`build`에서 자동 실행하지 않습니다. 제품 JAR과 공개 API에 포함되지 않습니다. 테스트에서는 같은 코드를 합성 데이터·JUnit 소유 임시 디렉터리·일회용 DB에만 호출합니다.

명령행 인자는 받지 않고 `.env`도 자동 로드하지 않습니다. `DB_JDBC_URL`은 `${DB_NAME}` 같은 참조가 남지 않은 PostgreSQL JDBC URL이어야 합니다. 접속정보는 환경변수로만 전달하고 출력·기록하지 않습니다. URL query는 기존 회귀 도구처럼 `sslmode`·`ssl`·`currentSchema`만 허용합니다.

| 환경변수                                | 사용처·의미                                                |
| --------------------------------------- | ---------------------------------------------------------- |
| `SCORE_SNAPSHOT_EXPORT_ENABLED`         | 내보내기를 명시적으로 허용할 때만 `1`                      |
| `SCORE_SNAPSHOT_OUTPUT_PATH`            | 내보낼 파일의 저장소 밖 실제 절대 경로. 기존 파일은 금지   |
| `DB_JDBC_URL`, `DB_USER`, `DB_PASSWORD` | 내보내기에만 필요. 검증 도구는 읽거나 사용하지 않음        |
| `SCORE_SNAPSHOT_INPUT_PATH`             | 오프라인 검증할 외부 파일의 실제 절대 경로                 |
| `SCORE_SNAPSHOT_EXPECTED_DISTRICT_ID`   | 선택: 외부에서 별도로 확보한 구 payload SHA-256            |
| `SCORE_SNAPSHOT_EXPECTED_DONG_ID`       | 선택: 외부에서 별도로 확보한 동 payload SHA-256            |
| `SCORE_SNAPSHOT_EXPECTED_FILE_SHA256`   | 선택: 외부에서 별도로 확보한 보존 파일 전체 바이트 SHA-256 |

외부 기준 해시는 모두 소문자 64자리입니다. 변수를 제공했는데 값이 비어 있거나 일치하지 않으면 실패합니다. 파일에서 읽은 해시를 그대로 기준값으로 다시 넣는 것은 독립 검증이 아닙니다.

## 2. 내보내기 절차와 파일 형식

1. 활성화·출력 경로·연결 설정을 확인합니다. 출력 경로 검사까지는 파일이나 DB를 생성·변경하지 않습니다.
2. 기존 회귀 도구의 연결 안전 설정을 재사용합니다. `default_transaction_read_only=on`, JDBC 읽기 전용, `REPEATABLE_READ`, `SET TRANSACTION READ ONLY`를 사용하고 실제 DB 설정을 조회해 확인합니다. Flyway 자동 구성·마이그레이션·ETL은 시작하지 않습니다.
3. 기존 Repository로 `20262`·`CS100010`의 구와 동을 각각 한 번씩 일괄 조회합니다. 공식 구 통계를 직접 사용하며 유동인구에는 업종 조건을 적용하지 않습니다.
4. 같은 트랜잭션 안에서 각각 `ScoreSnapshotArtifact.capture()`를 호출합니다. 경계·네 원본 문자열·행별 출처·정책·완비/제외 목록·정확한 분수 결과를 보존합니다.
5. 두 단위의 분기·업종·스키마·알고리즘·정책·경계 메타데이터·조회 시각이 일치하는지 확인합니다. 동의 부모 구 코드·명칭과 같은 UUID의 배치 메타데이터도 대조합니다.
6. `ROLLBACK` 완료 통지를 확인하고 DB Context를 닫습니다. 묶음 바이트를 다시 역직렬화·재현 검증한 뒤에만 파일을 저장합니다.

보존 파일의 최상위는 다음 세 필드뿐입니다. 중복 키·추가 필드·지원하지 않는 버전·한 단위 누락을 거부합니다.

| 필드                  | 내용                                 |
| --------------------- | ------------------------------------ |
| `bundleSchemaVersion` | `score-snapshot-bundle-v1`           |
| `district`            | 기존 구 `ScoreSnapshotArtifact` 전체 |
| `dong`                | 기존 동 `ScoreSnapshotArtifact` 전체 |

두 아티팩트는 별도 입력 해시와 독립된 비교 집단을 유지합니다. 한 파일에 묶는 이유는 구 파일만 저장된 상태를 완료로 남기지 않기 위해서입니다. **승인 manifest가 아닙니다.**

입력 해시는 기존 R01처럼 요청 시각을 제외한 각 payload의 정규 JSON에 적용합니다. 파일 SHA-256은 요청 시각을 포함한 묶음 파일 바이트 전체에 적용하므로, 같은 입력을 다른 시각에 다시 보존하면 입력 해시는 같아도 파일 해시는 다를 수 있습니다.

## 3. 외부 경로·권한·실패 처리

보관 담당자가 미리 만든 **현재 사용자 소유의 POSIX `0700` 디렉터리**를 사용해야 합니다. 도구는 부모 디렉터리를 만들거나 기존 권한을 바꾸지 않습니다. 경로는 실제 절대 경로여야 하며 `..`·중간/최종 심볼릭 링크·저장소 내부 경로를 거부합니다. macOS의 경로 별칭도 실제 경로로 해석해 준비합니다.

상위 디렉터리는 root 또는 현재 사용자 소유여야 합니다. 다른 사용자가 쓸 수 있는 비보호 경로는 거부하며, `/tmp` 유형의 sticky 디렉터리는 소유자 보호를 확인합니다. 보관 디렉터리를 실행 도중 이동하거나 권한을 바꾸지 않습니다. 보관 계정은 신뢰 주체이며 여러 사용자와 공유하지 않아야 합니다.

지원하는 provider에서는 `SecureDirectoryStream`으로 디렉터리를 고정합니다. 현재 검증한 macOS provider는 이를 지원하지 않아 POSIX 소유권·sticky 보호·링크·부모 inode 동일성 검사를 사용합니다. POSIX 권한·파일 식별·하드 링크 등 필요한 기능을 사용할 수 없으면 저장을 중단합니다. Linux의 고정 디렉터리 분기는 이번 macOS 실행으로 검증했다고 주장하지 않습니다.

정상 저장은 같은 디렉터리의 무작위 `.score-snapshot-*.part`를 `CREATE_NEW`·`NOFOLLOW`·`0600`으로 만들고, 전체 바이트 기록·파일 동기화 후 `0400`으로 바꿉니다. 하드 링크로 최종 이름을 원자적으로 게시하므로 기존 파일·디렉터리·링크를 덮어쓰지 않습니다. 새 최종 파일은 처음부터 완성된 두 아티팩트를 가집니다. 성공 후 임시 이름을 지웁니다.

일반 실패에서는 파일 식별자가 일치하는 이번 실행의 임시 파일·미완료 게시 항목만 정리합니다. 기존 파일이나 이전 실행의 남은 파일은 임의 삭제하지 않습니다. 프로세스 강제 종료·전원 장애·보관 계정의 경로 변경까지 자동 복구한다고 보장하지 않습니다. 파일 동기화는 백업이나 디렉터리 게시의 전원 장애 내구성을 대신하지 않습니다.

실패 시 다음 순서로 복구합니다.

1. 종료값과 안전한 실패 단계만 확인합니다. `NOT_COMPLETED`를 저장 성공으로 취급하지 않습니다.
2. 지정한 비공개 보관 위치를 담당자가 확인합니다. `.part`는 완성본으로 사용하거나 자동 승인하지 않습니다. 소유·생성 이력이 확인된 항목만 별도로 정리합니다.
3. 기존 최종 파일이 있으면 덮어쓰지 말고 검증 도구로 검사합니다. 재시도는 별도의 새 출력 이름을 명시합니다.
4. 실패 원인·권한·여유 공간·파일시스템 지원을 확인합니다. 원본 파일 내용·접속 문자열·예외 원문을 로그나 이슈에 붙이지 않습니다.

검증 도구도 명시한 파일 하나만 읽습니다. 링크·비정규 파일·읽는 동안의 파일 변경을 거부하고, 자원 보호를 위해 파일 크기를 64 MiB 이하로 제한합니다. 이 제한은 점수나 커버리지 정책이 아닙니다.

## 4. 명령과 결과 해석

아래 명령은 `backend/`에서 실행합니다. DB 설정과 사용자 선택 경로는 먼저 안전한 환경변수로 준비합니다. 권장 출력 이름은 `*.score-snapshot.json`이며 해당 패턴과 임시 파일은 `.gitignore`로도 보호합니다. 이름을 바꾸었다고 원본의 Git 추가가 허용되는 것은 아닙니다.

```bash
# 내보내기: 외부 출력 경로와 DB 환경변수를 준비한 뒤 명시적으로 실행
SCORE_SNAPSHOT_EXPORT_ENABLED=1 ./gradlew scoreSnapshotExport --quiet --console=plain 2>/dev/null

# 검증: SCORE_SNAPSHOT_INPUT_PATH와 필요한 외부 기준 해시를 준비
./gradlew scoreSnapshotVerify --quiet --console=plain 2>/dev/null
```

Java 도구 종료값은 0=보존/검증 성공, 2=설정·접속·안전 조건·파일·해시·재현 오류입니다. Gradle은 비정상 종료를 작업 실패로 전달합니다. 표준출력은 집단 수·제외 수·해시·읽기 전용/롤백 결과·미승인 상태만 담고 경로·내용·접속정보를 출력하지 않습니다. Gradle 일반 오류에 Java 실행 경로가 섞일 수 있어 위 명령은 표준오류를 버립니다. 실패 시 `--debug`·`--info`·`--stacktrace` 로그를 공유하지 않습니다.

검증 결과의 `externalPins=0`이면 외부 기준 해시 없이 내부 형식·계산 일관성만 확인한 것입니다. 외부 기준이 모두 맞아도 원천의 진위·의미적 비교 가능성·전체 목록의 독립적인 승인까지 증명하지 않습니다. 파일을 새 해시·기대 결과와 함께 고쳐 만든 공격은 신뢰할 수 있는 외부 기준이나 서명이 없으면 탐지할 수 없습니다.

모든 결과는 `publication=NOT_APPROVED`, `sourceTrust=NOT_ESTABLISHED`, `R03_COMPLETE=false`를 유지합니다. 과거 2026-11-02 12:17 전체 입력 fixture는 여전히 없으며 이번 도구 구현으로 과거 재현을 완료한 것이 아닙니다.

## 5. 검증과 운영 전 결정 사항

2026-11-02 합성 검증 결과: 신규 도구 단위 **22개**·일회용 DB 통합 **5개**, 전체 단위 **548개**·통합 **833개**가 통과했습니다. 실패·건너뜀은 없고 기존 R01·R02 코어 44개 및 고정 SHA-256 fixture도 유지했습니다. 빌드·Spotless·문서 Prettier·링크·신규 파일 공백 검사를 확인했습니다. 실제 개발 DB는 사용하지 않았습니다.

테스트는 합성 전체 3구·3동을 사용합니다. 내보내기 비활성·안전 속성 덮어쓰기·외부 경로·권한·기존 파일·링크·경로 교체·부분 저장 정리·변조·외부 기준 불일치와 오프라인 재현을 검증합니다. 일회용 PostGIS에서는 실제 읽기 전용 설정·롤백·두 단위 저장·동시 입력 변경 중 동일 스냅샷·인증 실패·빈 최신 경계·게시 실패를 검증합니다. 테스트 DB에서의 마이그레이션·fixture 쓰기는 내보내기 도구의 쓰기가 아닙니다.

전체 검증 명령은 다음과 같습니다. 실제 개발 DB 내보내기·기존 실데이터 회귀 도구는 이번 작업에서 실행하지 않습니다.

```bash
./gradlew test
./gradlew integrationTest
./gradlew build
./gradlew spotlessCheck
```

운영 전에 실제 보관 위치, 계정·접근 권한, 백업/복원·보존 기간·배포 책임, 독립 해시 보관 경로를 결정해야 합니다. 이후 전체 입력과 정책·판본·커버리지 승인을 연결하는 manifest 발급·검증이 필요합니다. 현재 도구는 승인 발급·공개 API·과거 입력 폴백을 구현하지 않습니다.

# 창업 환경 점수 설계

**현재는 후보 알고리즘을 비교하는 설계 단계입니다. 최종 모델·가중치·정규화 방식은 정하지 않았고, 점수 API와 저장 테이블도 구현하지 않았습니다.**

MVP의 구체적인 정책 권장안과 Spring Boot 계산·API·테스트 제안은 [MVP v1 계산 계약](score-v1-contract.md)에 정리했습니다. 최종 채택 전 설계이며, 현재 데이터 판본의 비교 가능성이 확인되기 전에는 공개 점수 제공을 승인하지 않습니다.

지금까지의 결론은 다음과 같습니다.

- 매출·유동인구·점포 수·폐업률로 지역의 특성을 비교할 수 있지만, 이 값만으로 창업 성공을 판단할 수는 없습니다.
- A는 낮은 매출을 다른 지표가 메울 수 있습니다. B·C는 점포가 적을 때 점포당 지표가 커지는 문제가 있습니다.
- D는 이런 보상을 줄이지만, 정규화값 하나가 0이면 전체가 0점이 됩니다. E에도 보상은 남습니다.
- 먼저 원천 데이터가 어떤 점포·기간을 집계했는지와 결측 원인을 확인해야 합니다. 그다음 입력·계산 방법을 선택하고 Spring Boot 구현 계약을 정합니다.

**핵심 본문은 1~8절입니다.** 계산 목적·모델 차이·실제 결과를 먼저 읽고, 구현 규칙이 필요할 때만 [기술 부록](#기술-부록-계산-규칙)을 확인하세요.

## 1. 왜 창업 환경 점수가 필요한가요?

카페를 열 동네를 찾는 사람에게 매출, 유동인구, 경쟁 점포 수를 한꺼번에 읽기는 어렵습니다. 점수는 이 정보를 묶어 **어떤 지역을 더 자세히 살펴볼지 정하는 출발점**을 제공하려는 것입니다.

예를 들어 사람이 많이 다니는 동네라도 카페가 많거나 소비 규모가 작을 수 있습니다. 점수와 함께 원본 통계를 보여 주면, 사용자가 장점과 주의할 점을 비교할 수 있습니다.

점수는 **같은 분기의 서울 자치구끼리 또는 행정동끼리 비교한 0~100의 상대값**입니다. 80점이 성공 확률 80%나 예상 수익을 뜻하지 않습니다. 구 70점과 동 70점을 직접 비교하거나, 행정동 점수를 그 안의 특정 점포·반경 500m의 점수로 해석하지 않습니다.

원본 통계의 저장·조회 API는 구현돼 있습니다. 지역 점수 계산·저장·조회와 실제 서비스 화면은 앞으로 구현할 영역입니다. 목표 동작은 [서비스 명세](service-spec.md#3-창업-환경-점수-확인), 확정된 DB·API 계약은 [데이터 설계](data-design.md)에서 관리합니다.

## 2. 어떤 데이터를 사용하나요?

기존 실험은 **2026년 2분기(`20262`), 카페 업종(`CS100010`, DB 명칭 `커피-음료`)**를 사용했습니다. 유동인구에는 업종 구분이 없으므로 업종 조건을 붙이지 않습니다.

### 데이터가 말해 주는 것과 말해 주지 않는 것

| 입력         | 알 수 있는 것                           | 해석할 때 주의할 점                                                  |
| ------------ | --------------------------------------- | -------------------------------------------------------------------- |
| 추정매출     | 지역의 카페 관련 소비 규모              | 카드 자료와 보정값으로 추정하며, 개별 카페의 실제 매출·순이익이 아님 |
| 유동인구     | 길 구간에 배분한 생활인구 규모          | 카페 방문자나 중복을 제거한 고객 수가 아님                           |
| 전체 점포 수 | 일반 점포와 프랜차이즈를 포함한 카페 수 | 적다는 것이 기회일 수도, 수요 부족일 수도 있음                       |
| 폐업률       | 원천이 제공하는 폐업 비율               | 창업 실패 확률이 아니며, 점수 계산을 위해 임의로 다시 산정하지 않음  |

공식 구 통계를 동 합계나 동 점수 평균으로 대체하지 않습니다. [자치구 통계 정책](district-statistics-policy.md#지표별-집계-정책)을 따르며, 실제 DB 테이블·컬럼과 정상 게시 출처 조건은 [부록 A](#a-입력-조회와-출처-검증)에 모았습니다.

공식 자료를 조사해 확인한 내용과 미확인 범위는 다음과 같습니다. **아래는 기존 조사 결과이며 이번 재작성에서 외부 자료를 새로 수집하지 않았습니다.**

1. [서울시 서비스 소개](https://golmok.seoul.go.kr/introduce.do)는 카드 기반 매출 추정, 해당 기간 개·폐업 신고 점포를 전체 점포로 나눈 비율, 서울시·KT 생활인구를 10m 길에 배분하는 방식을 안내합니다. [데이터 출처](https://golmok.seoul.go.kr/source.do)는 그리드·집객시설을 이용한 인구 배분과 분기 제공을 설명합니다.
2. [행정동 매출 자료](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do)는 원 단위 추정매출을, [점포 자료](https://data.seoul.go.kr/dataList/OA-22172/A/1/datasetView.do)는 전체=일반+프랜차이즈를 안내합니다. [길단위 인구 자료](https://data.seoul.go.kr/dataList/OA-22178/A/1/datasetView.do)는 행정동별 생활인구입니다. 제공 기준 변경 공지는 2024년부터 표준단위구역을 사용하며 2021년 이후 자료를 제공한다고 설명합니다.
3. **기간·추정 방식은 판본 확인이 더 필요합니다.** [서울시 배포 자료 8쪽](https://culture.seoul.go.kr/culture/cmmn/file/fileDown.do?atchFileId=af365d87d23c4c5b8411d3ba236292f6&bbsId=&fileSn=2&menuNo=200050#page=8)은 동대문 상권 분석에서 ‘당월 매출액’을 분기 월평균으로 설명합니다. 이를 현재 적재한 구·동 데이터 판본 전체에 적용할 근거는 확보하지 못했습니다. 원본 필드명과 값을 유지하며 분기 합계·월평균으로 환산하지 않습니다.
4. 소개와 [별도 제공정보 안내](https://golmok.seoul.go.kr/policy/sectorAnalysis.do)는 카드사 구성과 보정 설명에도 차이가 있습니다. 설명 문장은 곱셈, 표는 나눗셈을 제시합니다. 어느 쪽을 임의로 선택해 보정식을 재현하지 않습니다.

통계가 집계하려는 대상 전체를 **모집단**이라고 합니다. 아직 **점포 수와 매출의 대상 점포가 일치하는지**, 정확한 매출 집계 기간, 폐업률의 분모 필드·반올림, 인구 총계의 기간 합·평균 및 외국인 포함·중복 제거 기준, 통계 시점 경계와 현재 경계의 호환성을 확인하지 못했습니다. 따라서 점포당 매출·인구는 실제 카페 평균 매출·고객 수가 아닌 **탐색용 나눗셈**입니다.

## 3. 점수는 어떻게 계산하나요?

### ① 조회·검증·비교 집단 구성

같은 분기·지역의 네 입력을 연결한 뒤 정상 출처인지, 필요한 값이 모두 있는지, 계산 가능한 값인지 검사합니다. 기존 비교에서는 모든 모델에 **네 입력이 유한한 비음수이고 점포 수는 0보다 커야 한다**는 공통 조건을 적용했습니다.

그 결과 원래 경계 **25구·425동** 중 **25구·421동**을 사용했습니다. 매출이 없는 다음 4동은 모든 모델에서 제외했습니다.

| 행정동             | 코드       |
| ------------------ | ---------- |
| 중랑구 면목5동     | `11260550` |
| 노원구 하계2동     | `11350612` |
| 서대문구 북가좌1동 | `11410710` |
| 강남구 개포1동     | `11680660` |

네 동에는 점포·인구 행이 있습니다. 매출 누락 원인이 비공개·원천 미제공·모집단 차이·적재 차이 중 무엇인지는 확인하지 못했습니다. **0원으로 채우거나 다른 분기로 대체하지 않습니다.**

각 모델은 같은 지역 목록을 사용하고 구와 동은 따로 계산합니다. 선택한 구의 동들만으로 기준을 다시 만들거나, 지표마다 다른 지역 집단을 사용하지 않습니다.

### ② 단위가 다른 입력을 0~1로 맞춥니다

매출 수억 원과 점포 수 수십 개를 그대로 더하면 숫자가 큰 매출이 결과를 좌우합니다. **정규화**는 단위가 다른 값을 같은 눈금에 놓는 과정입니다. 두 방식을 비교했으며 어느 쪽도 채택하지 않았습니다.

**순위 방식은 원본의 크기 대신 동네 사이의 순서를 씁니다.** 다음은 실제 DB와 무관한 가상 동네 다섯 곳의 매출 예시입니다.

| 가상 동네 | 매출(원) | 작은 값부터의 순위 | 0~1 변환값 |
| --------- | -------- | ------------------ | ---------- |
| 가        | 1,000    | 1                  | 0          |
| 나        | 2,000    | 2                  | 0.25       |
| 다        | 3,000    | 3                  | 0.5        |
| 라        | 4,000    | 4                  | 0.75       |
| 마        | 5,000    | 5                  | 1          |

매출이 높은 쪽일수록 큰 값을 줍니다. 점포 수·폐업률은 적을수록 유리하다고 가정해 방향을 반대로 둡니다. 같은 원본값에는 같은 값을 주며, 정확한 동률 처리는 부록에 있습니다.

이 방식은 매우 큰 값 하나에 덜 휘둘립니다. 대신 **1억과 2억의 차이인지, 2억과 10억의 차이인지**는 잃습니다. 순서가 같으면 변환값도 같습니다. 적은 점포가 유리하다는 가정 자체도 검증 대상입니다.

**log/winsor 혼합 방식은 큰 값의 격차를 줄이고 양끝을 제한합니다.** 먼저 규모가 매우 큰 값의 차이를 압축합니다. 다음으로 같은 비교 집단의 하위·상위 5% 경계 밖 값을 경계값으로 바꾸고, 나머지를 0~1로 옮깁니다. 지역을 삭제하는 방식은 아닙니다.

순위만 쓸 때 사라지는 규모 차이를 일부 남기려는 시도지만, 양끝의 서로 다른 값이 같은 점수로 묶일 수 있습니다. 매출·인구·점포 수·점포당 지표에만 적용하고 **폐업률은 기존 순위 방식을 유지한 혼합안**입니다. 상세 계산은 [부록 B의 순위 규칙](#b-순위-정규화와-동률)과 [부록 C의 혼합 방식](#c-logwinsor와-type-7-분위수)에 있습니다.

### ③ 비중을 적용하고 모델별로 결합합니다

**가중치**는 각 입력을 얼마나 중요하게 반영할지 정한 비중입니다. A는 매출·인구를 각각 30%, 점포 수·폐업률을 각각 20% 반영합니다. 합계가 100%라는 것과 실제로 타당한 비중이라는 것은 별개입니다.

이 값들을 더할지, 곱할지, 좋은 조건과의 차이를 비교할지가 A~E의 차이입니다. 결과는 100점 만점으로 표현하고 높은 점수부터 순위를 매깁니다. **같은 점수라도 계산 방법과 비교 집단이 다르면 같은 의미가 아닙니다.**

### 실제 0·결측·산출 불가는 다릅니다

- **실제 0:** 폐업률 0처럼 원천에서 관찰한 값입니다. 그대로 사용합니다.
- **결측:** 매출 행이 없거나 필수 값이 비어 있는 상태입니다. 0으로 채우거나 남은 항목의 비중을 늘리지 않습니다.
- **변환 후 0:** 원본이 양수여도 집단에서 가장 낮거나 경계 밖이면 생길 수 있습니다.
- **산출 불가:** 필수 입력·정상 출처가 없거나 나눗셈 등을 할 수 없는 상태입니다. 임의의 0점·50점을 주지 않습니다.

D에서 계산된 **0점은 산출 불가가 아닙니다.** 예외별 정확한 처리는 [부록 E](#e-예외-정밀도와-재현-규칙)에 있습니다.

## 4. A~E 모델은 무엇이 다른가요?

**A·D·E는 같은 네 입력·방향·가중치에 서로 다른 계산법을 적용합니다. B·C는 점포당 매출·인구를 사용하며, A·D·E와 입력·가중치가 다릅니다. B와 C 사이에서도 가중치가 다릅니다.**

다섯 모델은 **어떤 정보를 볼지와 좋은 조건이 나쁜 조건을 얼마나 메울 수 있는지**를 비교하기 위한 후보입니다. 아래의 문제는 기존 실험에서 확인한 것이며, 대표 지역의 실제 수치는 5절에서 함께 봅니다.

| 모델 | 만든 이유와 평가 방식                                   | 확인한 문제                                  | 현재 판단                                              |
| ---- | ------------------------------------------------------- | -------------------------------------------- | ------------------------------------------------------ |
| A    | 네 조건에 비중을 주어 더하는 단순한 기준선              | 낮은 매출을 다른 조건이 메울 수 있음         | 설명은 쉽지만 보상 허용 범위를 결정해야 함             |
| B    | 카페 한 곳당 매출·인구로 지역 규모를 보정하려는 대안    | 카페 수가 적으면 두 입력이 함께 커짐         | 작은 분모와 원천 대상 점포의 일치 여부를 검증해야 함   |
| C    | B의 항목별 비중을 동일하게 두어 비중 선택의 영향을 비교 | B와 같은 입력을 쓰므로 작은 분모 문제도 유지 | 균등 비중이라고 객관적인 정답이 되지 않음              |
| D    | 낮은 조건의 영향을 더 강하게 반영하려는 대안            | 변환값 하나가 0이면 전체가 0점               | 상대 순위의 끝값을 강한 거부 조건으로 볼지 결정해야 함 |
| E    | 좋은 조건·나쁜 조건을 모은 두 기준과 비교하려는 대안    | 낮은 매출의 보상과 기준 집단 의존이 남음     | 다른 균형 기준일 뿐, 실제 창업 성과 검증이 필요함      |

### A: 네 조건을 더합니다

카페를 열 때 매출·인구·경쟁·폐업 상황을 한 번에 보기 위한 가장 단순한 방식입니다. 각 조건에 비중을 곱해 더하므로, 어떤 항목이 점수를 높였는지 설명하기 쉽습니다.

한 조건이 낮아도 다른 조건이 메울 수 있습니다. 이를 **보상**이라고 합니다. 실제 삼성동처럼 매출이 집단 최저여도 다른 조건 덕분에 점수가 높아질 수 있었습니다. 어디까지 보상해도 되는지 정하지 못해 채택하지 않았습니다.

### B: 카페 한 곳당 규모를 봅니다

같은 매출·인구라도 카페 10개가 나누는 곳과 100개가 나누는 곳을 구분하려는 모델입니다. 지역의 매출과 인구를 각각 카페 수로 나눈 뒤 평가합니다. 이 나눗셈이 실제 한 카페의 예상 매출·고객 수를 뜻하지는 않습니다.

문제는 카페 수가 작아지면 두 입력이 동시에 커진다는 것입니다. 실제 가양3동은 A보다 B에서 순위가 크게 올라갔습니다. 작은 분모의 영향과 매출·점포 모집단을 확인하기 전에는 최종 모델로 쓸 수 없습니다.

### C: B에서 비중만 같게 둡니다

B의 결과가 특정 비중 때문에 생겼는지 살펴보는 비교 기준입니다. 점포당 매출·점포당 인구·폐업률을 각각 같은 비중으로 반영합니다.

입력 자체는 B와 같으므로 카페가 적을 때 값이 커지는 문제도 남습니다. 실제로 작은 점포 수 지역의 상위 진입이 B보다 많았습니다. 비중을 같게 했다는 이유만으로 채택하지 않았습니다.

### D: 낮은 조건을 쉽게 메우지 못하게 합니다

A의 보상을 줄이려고 네 조건을 더하는 대신 비중을 반영해 곱합니다. 좋은 조건이 여러 개여도 낮은 조건이 전체 결과를 더 강하게 끌어내립니다.

하지만 한 조건의 변환값이 0이면 전체도 0점입니다. 실제 강남구·서교동은 경쟁 점포가 가장 많다는 이유로 D가 0점이 됐습니다. 상대적으로 불리한 한 조건이 모든 장점을 무효로 만들어도 되는지 정하지 못해 채택하지 않았습니다.

### E: 좋은 조합에 가깝고 나쁜 조합에서 먼지 봅니다

좋은 조건만 모은 기준과 나쁜 조건만 모은 기준을 만들고, 각 지역의 조건이 어느 쪽에 가까운지 비교합니다. 여기서 거리는 지리적 거리가 아니라 **조건 사이의 차이**입니다.

이를 TOPSIS형이라고 부르지만, 이번 E는 기존 순위값을 재사용한 비교용 변형입니다. 표준 절차를 그대로 구현한 모델이 아닙니다. 실제 삼성동에서도 다른 조건이 낮은 매출을 메웠고, 비교할 지역이 바뀌면 기준도 달라집니다. 계산 방식이 다르다는 이유로 더 나은 모델이라고 판단하거나 채택하지 않았습니다.

## 5. 실제 실험에서 무엇을 알게 됐나요?

아래는 **기존 2026-11-01 실험 결과**입니다. 각 비교는 별도의 읽기 전용 스냅샷에서 수행됐고, 각 실험 안에서는 같은 입력·집단을 사용했습니다. 25구·421동과 출처·입력의 일치도 재확인됐습니다. 이번 재작성에서는 DB 조회·새 모델 실험을 하지 않았습니다.

### B·C는 점포가 적을 때 민감했습니다

공통 421동 중 점포 10개 미만은 12동, 20개 미만은 62동입니다. 다음은 **상위 약 10%인 43동에 포함된 수**입니다. 전체 집단에서 상위 10% 경계에 걸친 동점 지역까지 포함한 결과가 43동이었습니다. 정확한 기준은 부록 E에 있습니다. 작은 집단별로 다시 정규화하지 않았습니다.

| 점포 수 구간 | 동 수 | 순위 A | 순위 B | 순위 C | 혼합 B | 혼합 C |
| ------------ | ----- | ------ | ------ | ------ | ------ | ------ |
| 10개 미만    | 12    | 0      | 4      | 6      | 4      | 6      |
| 20개 미만    | 62    | 0      | 13     | 16     | 14     | 16     |

10개 미만은 20개 미만의 부분집합입니다. 이 기준은 위험을 살피기 위한 구간이며 산출 제외 정책으로 채택한 것이 아닙니다.

가양3동은 **점포 7개·폐업률 14%**인데 A **28.76점·408위**, B **66.81점·35위**, C **59.52점·91.5위**였습니다. 점포당 지표가 높은 값을 받아 높은 폐업률을 메울 수 있었습니다. 상계9동은 점포 7개로 B·C 모두 4위였습니다.

행정동 A–B 순위 상관은 0.5655, B–C는 0.9658입니다. 여기서 **순위 상관**은 동률 평균 순위로 구한 Spearman 상관으로, 두 모델이 지역을 비슷한 순서로 놓는 정도입니다. 1에 가까울수록 전체 순서가 비슷하며, 이번에는 A와 B보다 B와 C가 더 비슷한 순서를 만들었습니다. 다만 B·C도 개별 지역의 최대 순위차가 96.5등이어서 비중 선택을 가볍게 볼 수 없습니다. 실제 성과가 없으므로 어느 지역이 과대평가됐는지 확정한 것은 아닙니다.

### 정규화를 바꿔도 작은 분모 문제는 남았습니다

혼합 방식에서 20개 미만 지역의 상위 진입은 B 13→14동, C 16동 유지였습니다. 작은 집단과 점포 20개 이상 집단의 평균 점수 격차는 줄었지만, 상위 진입 수는 일관되게 줄지 않았습니다.

가양3동의 B 순위는 35→59위로 내려간 반면 상계9동은 B·C 모두 4위를 유지했습니다. 돈암1동·삼성동 등 5동은 꼬리 제한으로 서로 다른 원본값이 같은 점수로 묶였습니다. 혼합 B **57.08점·189위**, C **62.78점·103위**입니다.

행정동 B의 두 정규화 사이 순위 상관은 0.9697이지만 최대 순위차는 97등입니다. 혼합 B·C의 평균도 50점에서 각각 55.06·54.53점으로 이동했습니다. 순위 기반 가중합의 평균 50점은 계산 방식에서 생기는 값이며 성능 기준이 아닙니다. **개별 점수 상승이나 높은 전체 상관만으로 개선을 판단할 수 없습니다.** 전체 순서가 비슷해도 한 동네가 97등 이동하면 살펴볼 후보지가 달라질 수 있고, 평균 상승은 실제 지역 환경이 좋아졌다는 뜻이 아닙니다.

### D는 보상을 줄였지만 강남구·서교동도 0점이 됐습니다

다음은 **같은 순위 정규화·가중치로 A·D·E를 비교한 실제 결과**입니다. 표의 숫자는 점수 / 평균 순위입니다.

| 지역              | A             | D            | E           |
| ----------------- | ------------- | ------------ | ----------- |
| 강남구            | 72.50 / 2     | 0.00 / 23.5  | 63.45 / 2   |
| 마포구 서교동     | 67.76 / 23    | 0.00 / 419.5 | 61.51 / 54  |
| 관악구 삼성동     | 60.36 / 83    | 0.00 / 419.5 | 56.31 / 125 |
| 성북구 돈암1동    | 41.36 / 322.5 | 8.59 / 410   | 45.14 / 307 |
| 서대문구 북아현동 | 64.50 / 45    | 26.21 / 351  | 58.48 / 96  |

강남구와 서교동은 각각 구·동 집단에서 점포 수가 가장 많았습니다. 점포가 적을수록 유리하게 평가하므로 두 곳의 점포 수 평가값은 0이 됐고, 다른 값이 높아도 D 전체가 0점이 됐습니다. “카페가 가장 많으면 전체 점수도 0이어야 한다”는 강한 판단이 숨어 있는 셈입니다.

D의 0점은 구·동 각각 4곳입니다. 원본이 0이어서가 아니라 정규화의 끝값 때문입니다. 동 A–D의 최대 순위차는 서교동의 **396.5등**입니다. 0점을 피하려고 작은 상수나 최소 점수를 넣지는 않았습니다.

### E에서도 낮은 매출을 다른 입력이 메웠습니다

삼성동의 당월 추정매출은 **362,431원**으로 집단 최저입니다. 매출 순위값은 0인데 A는 60.36점, E는 56.31점입니다. 인구·적은 점포·폐업률 0이 낮은 매출을 보상한 결과입니다.

돈암1동의 매출은 **406,669원**입니다. 매출 순위값은 0.002381로 0에 가깝지만 D는 8.59점으로 양수입니다. 두 동의 D 차이를 실제 사업 위험의 차이로 해석해서는 안 됩니다.

구 A–D 순위 상관은 0.6039, A–E는 0.9938이고, 동에서는 각각 0.8154·0.9948이었습니다. A를 D로 바꿀 때보다 E로 바꿀 때 전체 순서는 더 비슷했다는 뜻입니다. 그래도 동 A·E 상위 5곳의 중복은 송중동 **1곳뿐**입니다. D·E의 동 상위 5곳은 같은 집합이었지만 순서는 달랐습니다.

A·D·E 모두 점포 20개 미만 지역이 상위 43동에 없었습니다. 그러나 세 모델은 점포당 나눗셈을 하지 않으므로, 이를 B·C의 작은 분모 문제가 해결됐다는 증거로 사용하지 않습니다.

## 6. 현재 결론과 구현 전 결정사항

**계산이 가능하고 후보마다 결과가 다르다는 것은 확인했습니다. 어느 후보가 실제 창업 환경을 더 잘 설명하는지는 확인하지 못했습니다.**

따라서 어느 모델도 채택하지 않았습니다. 점수 구간을 ‘좋음·나쁨’으로 나누거나 성공 가능성으로 표시하는 정책도 미확정입니다.

### 다음 검증의 우선순위

1. **입력 의미부터 확인:** 현재 판본의 매출·점포 모집단, 집계 기간, 폐업률 분모·반올림, 인구 배분·중복, 경계 호환과 매출 누락 4동의 원인을 제공기관 명세·원본 키로 확인합니다.
2. **평가 가정 결정:** 적은 점포를 유리하게 볼지, 낮은 매출을 어디까지 보상할지, D의 0을 허용할지, 소규모 기준을 둘지 합의합니다. 이후 입력·가중치·정규화를 한 번에 바꾸지 않고 민감도를 비교합니다.
3. **기간·성과 검증:** 호환되는 과거 분기의 순위 안정성, 가중치·꼬리 경계의 변화, 독립적인 창업 성과와의 관계를 확인합니다. 현재 단면 결과만으로 성능을 주장하지 않습니다.

AHP는 전문가의 비교 판단으로 **가중치를 정하는 방법**, ELECTRE는 조건 간 우월관계·거부 기준을 다루는 방법, Huff Model은 거리·매력도에 따른 점포 선택을 다루는 후속 검토 대상입니다. 이번 점수 결합식의 채택 근거가 아니며 실험하지 않았습니다.

### Spring Boot 구현 전에 정할 계약

- **입력·대상:** 필수 지표, 기준 분기 선택, 최소 커버리지·집단 크기, 결측·소규모 제외 조건.
- **계산:** 모델·방향·가중치·정규화, 동일값·D의 0·E의 거리 합 0 처리, 순위·표시 반올림.
- **재현성:** 지역·분기·업종, 비교 집단, 경계와 각 통계 행의 실제 출처, 원본 입력·제외 사유·정규화 기준·알고리즘 버전을 남기는 방법. 현재 Upsert 테이블은 배치 ID만으로 과거 값을 항상 복원할 수 없습니다.
- **저장·실행:** 사전 계산 또는 요청 시 계산, `region_score` 저장 여부, 재게시·캐시 무효화 방식.
- **API·설명:** 산출 불가와 조회 오류의 구분, 기존 통계 API 계약 유지, 원본 지표·평가 범위·한계 설명.

이 계약을 정하기 전에는 기존 통계 API에 임의 점수를 붙이지 않습니다. 구현 시에는 [데이터 재현성 설계](data-design.md#5-평가-결과의-재현성)와 [서비스의 점수 요구사항](service-spec.md#3-창업-환경-점수-확인)을 함께 맞춥니다.

## 7. MVP 평가 기준 추가 검증

**2026-11-02에 기존 A를 기준선으로 점포 수 방향과 A·E의 가중치 민감도를 검증했습니다. 최종 모델·방향·가중치는 여전히 미확정입니다.** 새 결합 모델은 만들지 않았습니다. 기존과 같은 정상 게시 조건의 `20262` 카페 자료로 25구·421동을 비교했고, DB는 단일 읽기 전용 스냅샷으로 조회한 뒤 ROLLBACK했습니다. [상세 분석 기록](archive/score-mvp-criteria-validation.md)에 조건·출처·검산과 전체 결과를 남겼습니다.

### 점포가 적어야 좋은지, 많아야 좋은지는 아직 정하지 못했습니다

A에서 **점포 수만 많을수록 유리하게** 바꾸고 다른 입력·순위 정규화·비중은 고정했습니다.

| 단위   | 기존 A와의 순위 상관 | 평균 / 최대 순위차 | 상위 5곳 중복 |
| ------ | -------------------- | ------------------ | ------------- |
| 자치구 | 0.8824               | 2.56 / 10          | 4/5           |
| 행정동 | 0.8836               | 43.99 / 192        | 2/5           |

| 실제 지역       | 기존 A 점수 / 순위 | 점포 증가 방향 점수 / 순위 |
| --------------- | ------------------ | -------------------------- |
| 강남구          | 72.50 / 2          | 92.50 / 1                  |
| 마포구 서교동   | 67.76 / 23         | 87.76 / 5                  |
| 서대문구 신촌동 | 73.31 / 3          | 92.55 / 1                  |

행정동 상위 5곳은 2곳만 겹쳤습니다. 강남구·서교동·신촌동은 올라갔지만, 최대 변화는 가양1동의 374→182위였습니다.

매출과 점포 수의 순위 상관은 구 0.9115·동 0.8589였습니다. 점포 수 상위 약 10% 동들의 매출 중앙값은 6,079,275,884원으로 나머지 동들의 589,469,752원보다 높았고, 인구 중앙값도 더 높았습니다. **점포가 많다는 것이 경쟁 부담과 큰 수요 규모를 함께 나타낼 수 있습니다.** 반대로 증가 방향은 매출과 비슷한 규모 정보를 중복 반영할 수 있습니다. 이 상관만으로 창업에 유리한 방향을 선택하지 않습니다.

### 낮은 매출의 보상은 가중치에 따라 상위 선택까지 바꿨습니다

기본 A·E에서는 **매출 하위 약 10%인 3구·43동 중 종합 상위 약 10%에 든 곳이 모두 0곳**이었습니다. 다만 삼성동처럼 매출이 매우 낮아도 다른 항목이 점수를 메우는 현상은 남았습니다.

각 비중을 하나씩 0.05 올리거나 내리는 8개 조건을 비교했습니다. 나머지 세 비중은 기존 비율대로 조정해 합계 1을 유지했고, 점포 방향은 기존 감소 방향으로 고정했습니다. 매출 비중을 0.30→0.25로 낮추자 A에서 매출 하위인 **삼양동·북아현동·삼성동 3곳이 상위 43동에 진입**했습니다.

최소 매출 조건·보상 제한은 **후속 정책 후보**입니다. 이번 하위 10% 경계는 현상을 찾기 위한 분석 기준일 뿐, 산출 제외 기준이 아닙니다. 먼저 원천 매출의 대상 점포·기간을 확인하고, 점수가 ‘수요 규모’와 ‘경쟁 부담’ 중 무엇을 얼마나 표현할지 정해야 합니다. 실제 창업 성과가 없어 특정 동네의 과대평가를 확정하지 않습니다.

### 과거 자료는 있지만, 분기 간 순위 안정성 검증은 보류했습니다

`20251~20262`의 모든 분기에 구 점포·매출·인구는 각각 25행, 동 점포·인구는 각각 425행이 있었습니다. 동 매출은 `20251` 420행, 나머지 5분기 421행입니다. 모든 관찰 행의 정상 출처를 확인했고, 존재하는 필수 측정값의 NULL·음수·비유한 값은 없었습니다. `20251`은 기존 매출 누락 4동 외에 둔촌1동도 빠집니다.

하지만 **같은 코드와 같은 CSV 배치에 속한다는 사실만으로 과거 경계·모집단·집계 기간의 호환성이 확인되지는 않습니다.** 해당 판본별 근거가 없어 과거 A 점수·분기 간 순위 상관·상위 지역 변화는 계산하지 않았습니다.

집단 차이만 따로 살피려고 동일한 `20262`에서 전체 421동과 전 기간 입력이 있는 420동을 비교했습니다. 둔촌1동 하나를 제외하고 다시 정규화해도 공통 동의 순위가 최대 3등 달라졌습니다. 향후 호환성을 확보하면 분기별 전체 집단과 고정 집단을 나눠 비교해야 합니다. 이 결과는 기간 안정성을 검증한 것이 아닙니다.

### MVP v1은 A의 설명 가능한 구조를 우선 검증하되, 채택은 보류합니다

A는 지표별 점수 기여를 설명할 수 있어 **MVP 검증 기준선**으로 유지할 만합니다. B·C의 작은 분모, D의 일괄 0점, E의 추가 복잡성으로 바꿔도 원천 의미와 보상 허용 범위 문제는 해결되지 않았습니다.

우선순위는 **① 판본별 원천 의미·과거 경계 확인 → ② 점포 수 방향과 보상 허용 기준 합의 → ③ 고정 집단의 기간·성과 검증**입니다. 현재 비중을 최종 정책으로 굳히거나 임의 매출 하한을 넣지 않습니다. 이 근거를 확보하기 전에는 종합 점수를 창업 적합성으로 제공하지 않고 원본 지표와 한계를 중심으로 설명하는 방향을 권합니다.

## 8. 원천 데이터 검증 및 MVP v1 결정 준비

**2026-11-02 공식 공개 자료를 다시 확인했지만, 현재 적재 판본의 의미를 모두 확정하지는 못했습니다. A를 포함한 최종 알고리즘·방향·가중치는 아직 채택하지 않았습니다.** 이번에는 DB 조회나 점수 실험을 하지 않았습니다. [상세 조사와 정책 후보](archive/score-source-verification.md)에 근거 URL·판본 적용 범위·결정 조건을 기록했습니다.

### 공공데이터의 일반 설명과 현재 CSV의 의미는 구분합니다

공식 [제공정보 PDF 2쪽](https://golmok.seoul.go.kr/images/seoul_info.pdf#page=2)은 점포 수에 해당 기간 폐업한 점포도 포함하는 구조를 설명합니다. 따라서 원본 점포 수를 ‘지금 영업 중인 경쟁 카페 수’로 단정하지 않습니다. 폐업률도 해당 기간 신고와 전체 점포를 이용한 비율이지, 새 카페의 실패 확률이 아닙니다.

반면 **현재 DB의 매출이 월평균인지 분기합계인지, 점포·매출의 대상 점포가 같은지, 인구 총계가 어떤 시간 합계·평균인지**는 일부 확인 또는 미확인입니다. 공식 안내끼리 매출 보정 설명에 차이가 있고, 특정 상권 배포 자료의 설명을 현재 구·동 CSV 전체에 적용할 근거가 없습니다. 4개 동의 매출 누락 이유도 확인하지 못했습니다. 원본값을 환산하거나 결측을 0으로 채우지 않습니다.

### 권장 후보는 ‘A의 단일 분기 참고 비교’이며, 공개 채택은 조건부입니다

### 다음 개발 단계로 넘어가기 위한 조건

1. **먼저 해결:** 사용할 판본의 같은 분기·공간·업종 기준으로 입력을 비교해도 되는지 확인하고, 점포 감소 가정·보상 허용·산출 불가·재현 규칙을 결정합니다. 현재의 정상 게시 조건은 필요하지만 의미의 호환성까지 보증하지 않습니다.
2. **한계를 명시해 잠정 처리 가능:** 값은 보정하지 않고 ‘원천 추정매출·원천 인구 규모’로 표시합니다. 정확한 보정계수·고유 인원 해석·누락 사유를 확인하지 못해도, 이를 사실처럼 표시하지 않고 누락 지역을 명시하는 단기 비교 후보는 준비할 수 있습니다. 판본 내 비교 가능성 확인을 생략한다는 뜻은 아닙니다.
3. **기능을 미루면 후속 확인 가능:** 과거 경계·기간 호환성이 확보되기 전에는 분기 간 순위 변화나 안정성을 제공하지 않습니다. 점포·매출 모집단 일치 전에는 점포당 실제 매출로 해석하지 않습니다. 실제 창업 성과 검증은 MVP 이후 과제이며, 그 전에도 성공 예측을 주장하지 않습니다.

**현재 가능한 것은 계산·설명·재현 계약의 준비이며, 사용자에게 제공할 종합 점수의 최종 구현 착수 조건은 아직 충족하지 못했습니다.** 우선 사용할 판본의 비교 가능성과 평가 목적에 대한 결정을 확보합니다. 공개 점수 채택이 보류돼도 기존 원본 통계의 조회·비교는 계속할 수 있습니다. 기존 서비스·DB·API 계약은 바꾸지 않았습니다.

### A. 입력 조회와 출처 검증

자치구는 아래 `district_` 테이블, 행정동은 `dong_` 테이블을 직접 읽습니다. 예를 들어 구 매출은 `district_sales_stat.monthly_sales_amount`입니다.

| 기호·입력          | 자치구 테이블 / 행정동 테이블                           | 컬럼·자료형                            |
| ------------------ | ------------------------------------------------------- | -------------------------------------- |
| S: 당월 추정매출액 | `district_sales_stat` / `dong_sales_stat`               | `monthly_sales_amount` · `BIGINT` · 원 |
| F: 총 유동인구     | `district_foot_traffic_stat` / `dong_foot_traffic_stat` | `total_foot_traffic` · `NUMERIC`       |
| N: 전체 점포 수    | `district_store_stat` / `dong_store_stat`               | `store_count` · `BIGINT` · 개          |
| c: 폐업률          | 위 점포 통계 테이블                                     | `closure_rate` · `NUMERIC` · %         |

점포·매출은 지역 코드·`industry_code`·`quarter_code`, 인구는 지역 코드·`quarter_code`로 연결합니다. **공식 구 통계를 동 합계나 동 점수 평균으로 대체하지 않습니다.** 상세 원칙은 [자치구 통계 정책](district-statistics-policy.md#지표별-집계-정책)을 따릅니다.

정규화 전에 자치구·행정동을 분리하고, 같은 단위에서 모든 모델에 동일한 입력 완비 지역을 고정합니다. 기존 공통 조건은 S·F·N·c가 유한한 비음수이며 N>0인 것입니다. 단위별 지역 수 n은 25·421이었고, 소문자 n과 개별 지역 점포 수인 대문자 N을 구분합니다.

#### 정상 게시 출처를 먼저 검증합니다

테이블에 행이 있다는 이유만으로 점수 입력으로 사용하지 않습니다.

- 경계는 `etl_batch`의 `SEOUL_DONG_BOUNDARY / SHAPEFILE / SEOUL / scope_code IS NULL / PUBLISHED / published_at IS NOT NULL` 중 `published_at, started_at, batch_id DESC`의 첫 배치를 고릅니다. 그 뒤 실제 구·동 행을 확인하며, 빈 최신 게시본 대신 과거 경계로 돌아가지 않습니다.
- 구는 선택한 경계 배치를, 동과 부모 구는 같은 경계 배치를 참조해야 합니다.
- 통계는 각 행의 실제 `source_batch_id`를 `etl_batch`에 연결해 해당 단위의 점포·매출·인구 데이터셋인지 검사합니다. 데이터셋 코드는 `SEOUL_DISTRICT_{STORE,SALES,FOOT_TRAFFIC}_STAT` 또는 `SEOUL_DONG_{STORE,SALES,FOOT_TRAFFIC}_STAT`입니다. 중괄호 부분은 자료별로 치환하는 표기이며, `CSV / SEOUL / scope_code IS NULL / PUBLISHED / published_at IS NOT NULL`도 충족해야 합니다.
- 통계에 전역 최신 배치 조건을 강제하지 않습니다. 새 빈 배치나 `SKIPPED` 이력이 기존 정상 행을 가리면 안 됩니다.

기존 통계 API의 미준비 503, 지역 미존재 404, 준비 후 요청 행 없음의 `200, data: null` 계약은 그대로입니다. 실제 행의 측정값이 NULL인 경우도 구분합니다. 향후 점수 산출 불가 응답은 별도로 정해야 합니다.

### B. 순위 정규화와 동률

**입력:** 같은 비교 집단의 한 지표 원본값 x. **출력:** 0~1 값 R(x). n은 지역 수, r은 작은 값부터 세는 평균 순위입니다. a는 x보다 작은 값의 개수, k는 x와 같은 값의 개수입니다.

$$
r=a+\frac{k+1}{2},\qquad R(x)=\frac{r-1}{n-1}
$$

동률은 차지한 순위의 평균을 공유합니다. 매출·인구·점포당 지표에는 R을 그대로, 점포 수·폐업률에는 **1−R**을 사용합니다. n≤1이면 계산하지 않습니다.

**최소 검산:** 100, 200, 200, 400, 500에서 두 200은 a=1, k=2이므로 r=2.5, R=1.5/4=0.375입니다. 가상 5지역의 점포 20개가 2등이면 R=0.25, 감소 방향은 0.75입니다.

동률 때문에 관측 범위가 꼭 0~1을 모두 채우지는 않습니다. 실제 421동의 폐업률 0인 99동은 평균 순위 50을 공유했습니다. 따라서 R(0)=49/420, 감소 방향은 371/420입니다. 폐업률 0을 임의의 만점으로 바꾸지 않습니다. 집단 전체가 같은 지표의 서비스 처리 정책은 아직 미확정입니다.

### C. log/winsor와 type 7 분위수

**입력:** 같은 비교 집단의 비음수 규모형 값 x. **출력:** 0~1 값 H(x). S·F·N·S/N·F/N에 적용하며, N은 결과 방향을 반전합니다. **폐업률은 B절의 순위 정규화를 유지합니다.** D·E의 기존 비교는 순위 방식만 사용했습니다.

계산 순서는 **로그 변환 → 로그값의 P05·P95 산출 → 경계 밖 값 제한 → 0~1 변환**입니다. y는 로그값, L·U는 하위·상위 경계, b는 제한한 값입니다. ln은 자연로그, max·min은 각각 큰 쪽·작은 쪽을 고르는 함수입니다.

$$
y=\ln(1+x),\quad L=q(0.05),\quad U=q(0.95)
$$

$$
b=\min(\max(y,L),U),\qquad H(x)=\frac{b-L}{U-L}
$$

1을 더하므로 원본 x=0도 y=0으로 계산할 수 있습니다. 원본 9·99·999는 로그 뒤 약 2.3026·4.6052·6.9078이 됩니다. 큰 값의 차이를 줄이지만 원본 크기를 그대로 보존하지는 않습니다.

**type 7:** 먼저 로그값 y를 오름차순으로 정렬하고 0부터 번호를 매깁니다. p는 분위수 비율, h는 그 위치, j는 정수 위치, t는 다음 값까지의 보간 비율입니다. floor는 아래 정수로 내림, y[j]는 j번째 값입니다.

$$
h=(n-1)p,\quad j=\operatorname{floor}(h),\quad t=h-j
$$

$$
q(p)=(1-t)y[j]+t\,y[j+1]
$$

t=0이면 y[j]만 사용합니다. 원본 분위수에 나중에 로그를 취하는 방식으로 바꾸지 않습니다.

**최소 검산:** 가상 로그값 0, 1, 3.4, 5, 7에서 P05 위치는 0.2, P95 위치는 3.8입니다.

- L=0.8×0+0.2×1=0.2, U=0.2×5+0.8×7=6.6입니다.
- y=0은 b=0.2로 제한돼 H=0, y=3.4는 H=(3.4−0.2)/6.4=0.5, y=7은 b=6.6으로 제한돼 H=1입니다.

U=L이면 계산하지 않습니다. 원본이 양수여도 P05 이하이면 H=0이 될 수 있습니다. 경계 밖 값을 삭제하거나 결측을 0으로 바꾸지 않습니다.

### D. 모델별 수식과 검산

**공통 표기:** S는 매출, F는 인구, N은 점포 수, c는 원천 폐업률입니다. z는 방향을 맞춘 네 순위값, 아래첨자 1~4는 매출·인구·적은 점포 수·낮은 폐업률 순서입니다. 모든 z는 클수록 실험상 유리합니다.

$$
z=(R(S),R(F),1-R(N),1-R(c)),\qquad w=(0.30,0.30,0.20,0.20)
$$

| 모델 | 지표와 가중치               |
| ---- | --------------------------- |
| A    | S·F 각 0.30, N·c 각 0.20    |
| B    | S/N 0.40, F/N 0.35, c 0.25  |
| C    | B의 세 지표 각각 정확히 1/3 |
| D    | A와 동일                    |
| E    | A와 동일                    |

**검산용 가상 입력:** 본문의 다섯 동네에 아래 인구·점포·폐업률을 가정합니다. 실제 DB 자료가 아닙니다.

| 가상 동네 | 매출 S(원) | 인구 F(예시 규모) | 점포 N(개) | 폐업률 c(%) |
| --------- | ---------- | ----------------- | ---------- | ----------- |
| 가        | 1,000      | 100               | 10         | 1           |
| 나        | 2,000      | 200               | 30         | 2           |
| 다        | 3,000      | 300               | 40         | 3           |
| 라        | 4,000      | 400               | 20         | 4           |
| 마        | 5,000      | 500               | 50         | 5           |

‘라’는 매출·인구 4등, 점포 2등, 폐업률 4등이므로 z=(0.75,0.75,0.75,0.25)입니다. A·D·E의 아래 검산에 이 입력을 한 번씩 사용합니다.

#### A: 가중합

**입력:** z와 w. **출력:** 0~100점 A. 각 정규화값에 비중을 곱하고 합산한 뒤 100을 곱합니다.

$$
A=100\times(0.30z_1+0.30z_2+0.20z_3+0.20z_4)
$$

**검산:** ‘라’의 기여분은 22.5+22.5+15+5이므로 A=65점입니다. 혼합 방식에서는 S·F·N의 R을 H로 바꾸고 폐업률 순위와 비중은 유지했습니다.

#### B·C: 점포당 입력의 가중합

**입력:** S/N·F/N·c의 같은 비교 집단 값. N>0을 먼저 검사합니다. u·v는 두 점포당 지표의 순위값, t는 낮은 폐업률 값입니다. **출력:** 0~100점 B·C.

$$
u=R(S/N),\quad v=R(F/N),\quad t=1-R(c)
$$

$$
B=100\times(0.40u+0.35v+0.25t),\qquad C=100\times\frac{u+v+t}{3}
$$

**별도 가상 검산:** 매출 1,000,000원·인구 10,000·폐업률 2%가 같은 두 지역만 비교합니다. 위의 5지역과는 별개이며 지역 수 n=2입니다.

| 점포 N | S/N     | F/N   | u·v·t   | B                          | C               |
| ------ | ------- | ----- | ------- | -------------------------- | --------------- |
| 10개   | 100,000 | 1,000 | 1·1·0.5 | 100×(0.40+0.35+0.125)=87.5 | 100×2.5/3≈83.33 |
| 100개  | 10,000  | 100   | 0·0·0.5 | 100×0.125=12.5             | 100×0.5/3≈16.67 |

폐업률은 동률 평균 순위 1.5이므로 t=0.5입니다. 두 지역에서 지표 전체가 같은 상황의 서비스 정책을 채택한 예시는 아니며, 기존 평균 순위 규칙만 검산한 것입니다.

혼합 방식에서는 u·v를 H(S/N)·H(F/N)으로 바꾸고 t와 가중치는 유지했습니다. 가중치 합은 B가 1, C는 정확히 1/3씩 합계 1입니다. 결측 대체나 가중치 재분배는 하지 않습니다.

#### D: 가중 기하평균

**입력:** A와 같은 z·w. **출력:** 0~100점 D. 각 값을 비중만큼 거듭제곱한 뒤 곱합니다. 예를 들어 0.75^0.30은 0.75에 0.30을 곱한다는 뜻이 아닙니다.

$$
D=100\times z_1^{0.30}\times z_2^{0.30}\times z_3^{0.20}\times z_4^{0.20}
$$

**검산:** ‘라’의 네 항은 약 0.917315·0.917315·0.944088·0.757858입니다. 곱은 약 0.602056이므로 D≈60.21점입니다. 같은 입력의 A=65점보다 낮습니다. 네 값이 모두 0.75라면 A·D 모두 75점입니다.

모든 z가 양수이면 다음 로그 동치식으로도 계산할 수 있습니다. Σ는 네 항을 더하는 기호, exp는 자연로그를 되돌리는 함수입니다. j는 네 조건을 가리킵니다.

$$
D=100\times\exp\left(\sum_{j=1}^{4}w_j\ln z_j\right)
$$

양의 가중치 항의 z가 하나라도 0이면 D=0으로 처리하고 ln(0)은 계산하지 않습니다. 가상 ‘라’의 마지막 값만 0으로 두면 A=60점, D=0점입니다. epsilon이나 최소 점수는 추가하지 않았습니다. 같은 입력에서는 D≤A이며, 점수가 낮아졌다는 것만으로 개선을 뜻하지 않습니다.

#### E: 기존 정규화값을 재사용한 TOPSIS형 변형

**입력:** 같은 집단의 A·D와 동일한 z·w. **출력:** 0~100점 E. i는 지역, j는 네 조건, zᵢⱼ는 해당 지역의 정규화값입니다. p·q는 항목별 관측 최댓값·최솟값을 모은 기준점입니다. 실제 한 지역의 값일 필요는 없습니다.

$$
p_j=\max_i z_{ij},\qquad q_j=\min_i z_{ij}
$$

각 기준까지 가중 거리를 계산합니다. d⁺는 좋은 기준점까지, d⁻는 나쁜 기준점까지의 거리입니다. +·−는 이름이며 거리의 양수·음수 부호가 아닙니다. √는 제곱근입니다.

$$
d_i^+=\sqrt{\sum_{j=1}^{4}w_j(z_{ij}-p_j)^2},\qquad
d_i^-=\sqrt{\sum_{j=1}^{4}w_j(z_{ij}-q_j)^2}
$$

$$
E_i=100\times\frac{d_i^-}{d_i^++d_i^-}
$$

**가중치는 차이의 제곱에 한 번만 곱합니다.** 좌표에 비중을 곱한 뒤 제곱해 비중까지 제곱하는 방식과 다릅니다. 기존 순위값을 추가 정규화 없이 재사용하므로 [통상 TOPSIS 절차](https://link.springer.com/article/10.1186/s40537-023-00788-3)와 구분합니다.

**검산:** 가상 5지역의 p=(1,1,1,1), q=(0,0,0,0)입니다. ‘라’에 적용하면:

- 좋은 기준점까지 제곱 차이의 가중합은 0.01875+0.01875+0.0125+0.1125=0.1625, 거리는 약 0.403113입니다.
- 나쁜 기준점까지 제곱 차이의 가중합은 0.16875+0.16875+0.1125+0.0125=0.4625, 거리는 약 0.680074입니다.
- E=100×0.680074/(0.403113+0.680074)≈62.78점입니다. 계산에는 반올림 전 거리를 씁니다.

실제 실험에서는 구의 p=(1,1,1,47/48), 동의 p=(1,1,839/840,53/60), q는 모두 (0,0,0,0)이었습니다. 동률로 생긴 범위를 다시 늘리지 않았습니다. 거리 합이 0이면 산출 불가입니다.

### E. 예외, 정밀도와 재현 규칙

- **검증 순서:** 정상 출처·같은 분기와 지역을 확인한 뒤 유한한 비음수 입력, NULL·분모, 공통 비교 집단을 검증하고 정규화합니다. NaN·Infinity·음수는 입력으로 사용하지 않습니다.
- **실제 0과 결측:** 관찰된 0은 유지합니다. 행 없음·필수 컬럼 NULL은 0으로 대체하거나 다른 분기로 채우지 않습니다. 설명용 지표의 결측까지 모두 점수 불가로 간주하지는 않습니다.
- **산출 불가:** 필수 입력·출처 부재, 점포당 지표의 N=0·NULL, n≤1, H의 U=L, E의 거리 합 0은 계산하지 않습니다. 임의의 0점·50점을 넣지 않습니다. D에서 정상 계산된 0점과 구분합니다.
- **미확정 정책:** 필수 지표가 집단 전체에서 동일할 때의 서비스 처리, 최소 커버리지·집단 크기·소규모 제외 기준은 확정하지 않았습니다.
- **원천 값 보존:** 일반 점포만 뜻하는 `general_store_count`로 전체 점포 수를 대체하지 않습니다. `closed_store_count / store_count`로 원천 폐업률을 다시 만들거나 100%를 상한으로 자르지 않습니다.
- **정밀도:** 원본 `BIGINT`·`NUMERIC`을 보존하고 나눗셈에 정수 나눗셈을 쓰지 않습니다. 위 검산의 표시용 중간값을 계산 입력으로 재사용하지 않습니다. Spring Boot의 수치 타입·계산 정밀도·표시 자릿수·반올림 모드는 아직 정하지 않았습니다.
- **최종 순위:** 반올림 전 점수를 내림차순 정렬해 동률 평균 순위를 구합니다. 표시 점수가 같다는 이유만으로 동률을 만들지 않습니다. 점수 동률을 판정할 수치 표현·허용오차는 구현 전에 정해야 하며, 임의로 새 기준을 적용하지 않습니다.
- **상위 약 10%:** 지역 수 n에 대해 `ceil(n×0.10)`번째 높은 점수를 기준으로 그 점수와 동률인 지역까지 포함했습니다. ceil은 올림입니다. 421동에서는 이번 결과가 43동이었습니다. 소규모 집단만 따로 정규화하지 않았습니다.
- **스냅샷·재현:** 각 기존 실험 안에서는 동일 입력·비교 집단을 사용했지만 서로 다른 실험을 같은 DB 스냅샷으로 표현하지 않습니다. 모델·정규화·가중치를 동시에 바꾸지 않는 비교 조건을 유지합니다. 원본 입력·제외 사유·경계·행별 출처·정규화 기준·버전의 보존 방법은 6절의 구현 전 계약과 함께 결정합니다.

세부 분포·배치 정보·재현 SQL이 필요하면 현재 브랜치의 기존 기록을 확인합니다. A·B·C 및 정규화 비교까지의 상세본은 `git show d993aae:docs/score-design.md`로 볼 수 있습니다. A·D·E의 상세 원문은 [실험 보존 기록](archive/score-experiments-ade.md)에 있습니다. 현재 설계의 핵심 계산 정의와 판단 근거는 이 문서에서 확인합니다.

# 서비스 명세

RecycleYoungs는 서울의 카페 창업 후보지를 찾고 주변 카페와 상권 통계를 비교하는 MVP입니다. 현재 이용할 수 있는 기능은 아래 탐색 흐름을 따릅니다. 다중 자치구 선택은 후속 범위입니다. [README의 상세 기술 문서](../README.md#상세-기술-문서)

## 상세 이용 흐름

### 메인 페이지

랜딩(`/`)은 지역·장소 검색, 경쟁 카페 확인, 상권 통계와 후보지 비교를 화면 예시로 소개합니다. **시작하기**로 `/explore`를 열면 지도를 불러옵니다. 알 수 없는 경로의 404 화면에는 홈·탐색 링크가 있습니다.

### 탐색 페이지

탐색은 서울특별시를 대상으로 합니다. 지도와 장소 검색, 공통 지역 필터를 유지하면서 **주변 카페**, **상권 분석**, **후보지 분석**을 전환합니다. 상세 패널은 처음에 접혀 있고 메뉴나 닫기 버튼·Escape로 닫을 수 있습니다. 닫으면 선택 메뉴로 포커스를 돌립니다. 모바일은 하단 메뉴와 확장 가능한 패널을 사용합니다.

#### 지도와 현재 위치

기본 지도 중심은 서울시청입니다. 첫 진입 시 브라우저에 위치 권한을 요청하고 Kakao SDK로 현재 위치가 서울임을 확인하면 이동해 표식으로 표시합니다. 권한 거부·오류·서울 외부·서울 소재 확인 실패 시 현재 지도 상태를 유지합니다. **내 위치로 이동**으로 다시 시도할 수 있으며, 위치 응답이 늦게 도착해도 그사이의 지도 조작이나 지역·장소·후보지 선택을 덮어쓰지 않습니다.

현재 위치 좌표는 브라우저 메모리에서 사용하며 별도 수집·저장·로그를 남기지 않습니다. SDK 키 누락, 로딩, 실패는 화면에서 구분하고 실패 시 재시도를 제공합니다. [Kakao Maps 설정](development.md#kakao-maps-설정)

#### 지역 필터

자치구를 먼저 선택하고 해당 구의 행정동을 고릅니다. 구를 바꾸면 동 선택이 초기화됩니다. 각 필터의 **전체**는 해당 단계의 제한을 해제합니다. 구를 선택하고 동을 **전체**로 두면 구 전체가 분석 단위가 됩니다.

지역을 선택하면 해당 구·동의 경계로 이동하고 강조합니다. 경계 조회 중이나 실패 상태에서는 이전 강조를 숨깁니다. 목록·경계는 로딩·빈 결과·오류를 구분하고 실패 시 재시도할 수 있습니다. 지도 조작만으로 지역 필터는 변경되지 않습니다. [행정구역 조회 계약](data-design.md#행정구역-rest-api-계약)

#### 장소 검색

장소명·지하철역 등 키워드와 도로명·지번주소를 검색합니다. 첫 페이지에서 최대 15개를 표시하며 서울 소재 결과를 우선합니다. 결과를 고르면 지도와 검색 표식만 이동하고 기존 구·동 필터는 유지합니다. 서울 밖이나 소재를 확인할 수 없는 결과도 좌표와 지원 범위 안내를 표시합니다.

**이 위치 주변 카페 보기**를 눌러야 선택 결과가 반경 탐색의 중심이 됩니다. 기존 500m·1km 선택을 유지하며 구·동 필터는 반경 조회에 전달하지 않습니다. 구·동을 다시 고르면 지역 이동이 우선하고 이전 검색 표식은 정리됩니다. 검색창은 빈 결과와 오류·재시도를 구분합니다.

## 카페 조회와 상권 통계

| 조회                | 범위와 표시                                                                                                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 현재 지도 영역 카페 | 화면의 사각 영역과 선택 구·동 경계에 해당하는 개별 카페를 표시합니다. 구 미선택 상태에서는 지도 레벨 4 이하로 확대해야 조회합니다. 최대 200곳의 마커·목록과 서버 전체 건수를 구분합니다.               |
| 선택 지점 주변 카페 | 지도에서 고르거나 검색에서 넘긴 지점을 중심으로 500m 또는 1km 반경의 카페를 조회합니다. 화면에 중심점과 원을 표시하고 서버 거리순을 유지합니다. 구·동 선택은 유지하지만 이 조회에는 적용하지 않습니다. |
| 상권 분석           | 선택한 자치구 또는 행정동 **전체**의 점포·당월 추정매출·유동인구를 표시합니다. 점포·매출은 카페 업종, 유동인구는 업종 구분 없는 지역 전체 기준입니다. 구 통계는 공식 자치구 원천을 사용합니다.         |

주변 카페 조회는 서울 공공데이터를 대상으로 합니다. 지도에서 고른 중심점은 주소를 확인할 수 없으면 선택 위치로 표시하며, 검색에서 넘긴 중심점은 해당 장소명·주소를 사용합니다. 중심점과 반경은 탐색 상태로 유지되며 후보지로 추가할 때만 후보지 목록에 저장됩니다. 카페의 위치·거리·주소 등 제공된 정보만 표시합니다. 지도에서 묶인 마커의 수는 표시 중인 마커 수입니다. [반경 API](data-design.md#주변-카페-rest-api-계약) · [지도 영역 API](data-design.md#지도-영역-카페-rest-api-계약)

지역 전체의 점포·매출·유동인구는 반경 안의 실측값으로 환산하거나 겹치는 행정구역끼리 단순 합산하지 않습니다. 전체 통계의 점포 수와 위치 검색의 카페 수는 각각의 집계 범위와 원천을 따릅니다. [공식 자치구 원천과 지표별 집계 정책](data-design.md#공식-자치구-통계와-집계-정책)

### 상권 통계의 표시와 전분기 정책

상권 분석은 선택 지역의 2026년 2분기(`20262`)와 이전 1분기(`20261`)를 조회합니다. 요약과 세부 탭은 같은 응답을 공유합니다. 지표·분기별 로딩·오류·재시도·자료 없음을 구분하고, 지역이 바뀌면 이전 선택의 늦은 응답이 새 화면을 덮어쓰지 않도록 합니다.

문자열 수치의 정밀도와 소수 후행 0을 유지합니다. 측정값 NULL과 실제 0을 구분하며, 조건에 맞는 행이 없는 경우와 모든 측정값이 NULL인 게시 행도 구분합니다. 출처와 게시 시각은 지표·분기별로 표시하고 화면의 시각은 한국시간으로 안내합니다. 게시 시각은 공식 원본의 생성일과 구분합니다.

점포·추정매출·유동인구의 전분기 비교 정책은 세 지표 모두 **`unverified`**입니다. 원천 비교 가능성이 확인되기 전에는 증감 숫자·증감률을 숨기고 이유를 표시합니다. 이전 분기 조회 오류와 재시도는 현재 분기 통계에 영향을 주지 않습니다. [전분기 검증과 공개 정책](archive/quarter-comparison-verification.md#구현-및-계산-정책) · [공식 원천 후속 대조](archive/official-source-verification-20261-20262.md)

## 창업 후보지 비교

**후보지 분석**에서 지도 추가 모드 또는 검색 결과로 A·B·C 최대 3곳을 등록합니다. 서울 자치구 경계가 중심점을 포함하는지 확인하며, 중복 위치나 서울 경계 밖 위치는 등록할 수 없습니다. 후보지의 이름·좌표는 브라우저 탭의 `sessionStorage`에 임시 저장합니다. 목록에서 지도 확인·이름 변경·삭제를 할 수 있습니다.

한 곳은 상세 분석, 두세 곳은 같은 500m 또는 1km 기준으로 비교합니다. 각 위치는 서버가 반환한 반경 내 **전체 경쟁 카페 수**와 거리순 최대 3곳을 표시합니다. 별도로 소속 행정동의 2026년 2분기 점포·추정매출·유동인구를 보여 줍니다. 같은 행정동의 후보지는 통계 응답을 공유합니다.

소속 행정동을 유일하게 확정할 수 없으면 행정동 통계만 비교 불가로 안내합니다. 서울 소속을 확인한 위치의 반경 분석은 계속합니다. 후보지별 조회 오류·재시도·빈 결과와 각 데이터의 게시 시점을 구분합니다. 현재 비교는 원본 통계와 경쟁 환경을 보여 주며 미검증 전분기 증감은 표시하지 않습니다.

## 서비스 데이터 흐름

ETL에서 공공데이터 파일·API 응답을 검증하고 PostgreSQL·PostGIS에 게시합니다. 탐색 화면은 Backend를 통해 현재 조회 조건에 해당하는 행정구역·카페·통계를 읽습니다. 각 원천의 기준 시점과 정상 게시 출처를 보존합니다. [ETL 실행 절차](etl-guide.md) · [ETL 검증 이력](archive/etl-validation-history.md) · [REST API와 게시 계약](data-design.md#행정구역-rest-api-계약)

## 다중 자치구 선택

검색 위치의 반경이 여러 자치구와 겹칠 때 개별 구나 해당 구 **모두**를 선택하는 흐름은 후속 요구사항입니다. 이 경우에도 겹치는 지역의 통계는 지역별로 제공하는 방향이며, 지역 전체 수치를 반경 실측값으로 표시하지 않습니다. 현재 화면은 자치구 한 곳과 그 아래 행정동을 고르는 필터, 별도의 반경 카페 조회를 제공합니다.

# 서비스 명세

- [README의 상세 기술 문서 안내](../README.md#상세-기술-문서)

이 문서는 서울 카페 창업 탐색 서비스의 **목표 기능과 이용 정책**을 설명합니다. 기본 탐색 화면·Kakao Maps와 구·동 선택에 따른 지도 이동을 구현했습니다. 아래 상세 이용 흐름에는 **목표 동작을 설명하는 요구사항**이 포함됩니다.

**구현 완료**

- 메인 랜딩(/), 지연 로딩되는 상권 탐색(/explore), 404 화면을 제공합니다.
- 브랜드 아이콘을 통합한 사이드바·반응형 지도 레이아웃. 초기 상세 패널은 닫고 주변 카페·상권 분석·후보지 분석 3개 메뉴로 접기·펼치기·전환. 모바일 하단 내비게이션·확장형 패널 제공
- Kakao Maps 비동기 SDK 로딩, 위치 조회 중 서울시청 기본 지도, 서울로 확인된 현재 위치 시작·별도 표식·내 위치 재조회, 확대·축소, 로딩·오류·재시도 상태. 키 설정은 [개발 가이드](development.md#kakao-maps-설정) 참조
- 자치구·행정동 목록 및 경계 API 연동, Polygon·MultiPolygon 범위 기반 지도 이동과 선택 경계 강조. 구 변경 시 동 초기화, 전체 선택, 로딩·빈 목록·오류·재시도와 요청 경합 방지. 분리 영역과 내부 링을 보존한 녹색 Polygon 오버레이 표시, 조회 중·실패·전체 선택 시 이전 강조 제거
- 행정구역 목록·GeoJSON 경계·주변 조회 API 5개
- 행정동별 분기·업종 [점포](data-design.md#행정동-점포-통계-rest-api-계약)·[추정매출](data-design.md#행정동-추정매출-통계-rest-api-계약) API와 업종 구분 없는 분기별 [유동인구 API](data-design.md#행정동-유동인구-통계-rest-api-계약)
- 공식 자치구 [점포](data-design.md#자치구-점포-통계-rest-api-계약)·[추정매출](data-design.md#자치구-추정매출-통계-rest-api-계약)·[유동인구 API](data-design.md#자치구-유동인구-통계-rest-api-계약)
- 현재 지도 영역 카페 조회·최대 200개 마커·목록·안전한 기본 정보창. 전체 건수와 일부 표시를 구분하고 선택 구·동 경계의 내부·경계 위 카페만 표시. 구 미선택 시 지도 레벨 4 이하에서 조회하며 반경 결과로 표현하지 않음
- 임시 관심 위치의 500m·1km 반경 카페·거리순 목록·중심점 마커·원형 범위 표시. 브랜드·프랜차이즈 여부를 추정하지 않으며 지도 영역 조회와 구분
- 장소·지하철역 키워드와 도로명·지번주소 검색, 서울 소재 우선 첫 페이지 최대 15개 결과·검색 위치 마커·지도 이동. 선택만으로 반경 조회하지 않고 별도 버튼으로 현재 반경에 연결
- 상권 분석은 실제 지역명·2026년 2분기·카페·음료 업종과 점포 수·당월 추정매출액·지역 전체 유동인구 요약을 표시합니다. 점포·추정매출·유동인구 세부 탭은 같은 구·동 통계 API 응답을 공유하며 전환 시 재조회하지 않습니다. 점포·매출은 카페 업종, 유동인구는 업종 구분이 없는 지역 전체 기준입니다. 각 지표의 로딩·오류·자료 없음·재시도를 독립적으로 안내하고 문자열 정밀도·NULL·실제 0을 보존합니다. 자치구는 공식 원천을 사용하며 지표별 게시 시각은 원문을 보존한 한국시간으로 표시합니다. 내부 코드·배치 ID와 임의 평가는 표시하지 않습니다. 현재 2026년 2분기·이전 1분기를 조회하되 증감 공개는 원천 비교 검증을 통과한 지표만 허용합니다. 현재는 세 지표 모두 증감 숫자 대신 비교 불가 사유를 표시합니다. [검증 근거와 계산 정책](quarter-comparison-verification.md)을 참고하세요. 이전 분기 오류·재시도는 현재 통계와 독립적이며 두 분기의 게시 시각을 합치지 않습니다.
- 카페 [반경 조회](data-design.md#주변-카페-rest-api-계약)·[지도 영역 조회 API](data-design.md#지도-영역-카페-rest-api-계약)
- 지도나 장소 검색으로 후보지 최대 3곳을 등록하고 탭 안에서 이름 변경·삭제·비교합니다. 500m·1km 반경 경쟁 카페 수와 2026년 2분기 행정동 전체 통계를 구분해 표시합니다.
- 승인 전 내부 A 계산·입력 스냅샷/재현 도구와 [점수 REST 미승인 차단 경로](score-v1-contract.md#5-점수-rest-api-제안): `db`에서 잘못된 요청 400·유효 요청 503, 점수 비공개

입력·응답·오류 등 확정된 API 계약은 [데이터 설계](data-design.md#행정구역-rest-api-계약)에서 관리합니다.

**개발 예정**

승인 게이트를 통한 점수 성공 응답, 후속 상권 분석입니다. 현재 화면은 점수 API를 호출하거나 점수를 표시하지 않으며 공개 미승인 상태를 유지합니다.

**미확정 설계**

점수 평가 항목·가중치·정규화·점수 구간, 계산 시점·저장 방식과 후속 API 계약은 확정하지 않았습니다. [점수 설계](score-design.md)에서 A~E와 실험 결과를, [v1 계약](score-v1-contract.md)에서 구현·계산 규칙을, [공개 준비](score-20262-publication-readiness.md)에서 원천·승인 과제를 확인합니다. A 후보의 내부 계산은 구현했지만 최종 정책과 데이터 판본을 채택·승인한 것은 아닙니다.

## 상세 이용 흐름

아래는 현재 구상 중인 서비스 이용 흐름이며, 실제 기능과 화면 구성은 개발 과정에서 변경될 수 있습니다.

### 메인 페이지

메인 랜딩(`/`)은 “카페 창업할 곳, 감으로만 고르지 마세요.”라는 문구와 함께 서울 카페 창업 후보지를 공공데이터로 탐색·비교하는 방법을 소개합니다. 지역·장소 검색, 경쟁 카페 확인, 상권 통계, 후보지 비교 기능을 안내합니다.

이용 방법은 장소 검색, 주변 카페와 상권 통계 확인, 후보지 등록, 후보지 비교 순서입니다. 지도 탐색·반경 카페·행정동 통계·후보지 비교의 실제 조회 화면을 정적 이미지로 소개합니다. 프리뷰에는 조회 예시와 지도 출처를 표기하며, 창업 환경 점수는 표시하지 않습니다.

‘시작하기’를 누르면 `/explore`로 이동합니다. 랜딩은 지도 SDK나 탐색용 API 요청 없이 렌더링합니다. 알려지지 않은 경로의 404 화면은 홈과 탐색 링크를 제공합니다.

### 탐색 페이지

탐색 페이지에서는 서울 지도를 중심으로 관심 지역을 찾고, 관련 공공데이터와 자체 평가 알고리즘을 활용해 카페 창업 환경을 분석·비교합니다.

#### 1. 지역 및 위치 탐색

탐색 대상 지역은 **서울특별시로 고정**하며, 행정구역 탐색과 장소 주변 탐색을 구분하여 제공합니다.

##### 행정구역 탐색

- 지역 필터는 업종과 독립적인 공통 도구이며 `서울특별시(고정) → 자치구 → 행정동` 순서로 구성합니다. 별도 지역 탐색 메뉴 없이 지도 오른쪽 상단에서 선택하며, 1024px 미만에서는 `지역 필터` 버튼으로 펼칩니다. 모바일은 검색창 아래 상단에 버튼을 배치합니다. 구·동 `전체`, 구 변경 시 동 초기화, 목록·경계의 로딩·빈 결과·오류·재시도를 제공합니다. 필터의 Escape·닫기는 필터만 접고 버튼으로 포커스를 돌립니다.
  - **시·도:** 서울특별시 고정
  - **구:** 전체 또는 특정 자치구 선택
  - **동:** 전체 또는 선택한 구에 속한 행정동 선택
- 특정 구를 선택하면 해당 구의 행정동 목록을 제공합니다.
- 동 필터의 `전체`는 선택한 구에 속한 전체 행정동을 의미합니다.
- 행정구역을 선택하면 해당 구 또는 행정동을 기준으로 지도와 상권 정보를 표시합니다.
- 지도 이동 및 확대·축소를 통해 관심 지역을 자유롭게 살펴볼 수 있습니다.

##### 장소 주변 탐색

- 검색창에서 지하철역, 주요 장소, 주소, 구·행정동 이름 등의 키워드 검색을 지원합니다.
- 첫 탐색 진입에서 현재 위치 권한을 요청합니다. SDK 좌표→행정구역 확인으로 서울 소재가 검증된 경우에만 이동하며 거부·오류·미지원·서울 외부·검증 실패는 현재 지도 중심과 확대 수준을 유지합니다. 최초 자동 조회 실패 시에는 서울시청 기본 지도를 유지합니다. 위치 조회가 지도 사용을 막지 않으며, 늦은 자동 응답은 지역·장소·후보지 선택이나 직접 지도 조작을 덮어쓰지 않습니다. `내 위치로 이동` 재조회도 요청 후의 새 선택을 우선하며, 실패 시 선택 지역 경계·검색 장소·카페 마커·후보지 선택을 유지합니다. 위치는 브라우저 메모리에만 두고 별도 수집·저장·로그를 남기지 않습니다.
- 검색 결과는 검색창 아래의 고정 레이어에 유지하고 열린 상세 패널 위에 표시합니다. 모바일은 지역 필터·지도 컨트롤·하단 메뉴를 피하며 내부 스크롤로 읽을 수 있습니다.
- 검색 결과를 선택하면 해당 위치로 지도를 이동합니다. 반경 범위는 별도 주변 카페 버튼으로 탐색을 시작할 때 표시합니다.
- 장소 검색으로 이동한 위치가 기존 지역 필터와 다르더라도 기존 필터를 즉시 변경하지 않습니다. 검색 결과는 사용자가 직접 선택하며 서울 밖 결과는 원래 좌표와 서비스 범위 안내를 제공합니다. `이 위치 주변 카페 보기`를 누르면 구·동 필터를 적용하지 않는 기존 반경 탐색에 연결하고 현재 500m·1km 반경을 유지합니다. 이후 구·동을 새로 선택하면 기존 지역 이동을 우선하고 검색 마커를 정리합니다.
- 아래 다중 자치구 범위 선택은 후속 확장 요구사항입니다. 현재 화면은 구·동 재선택 시 지역 이동을 우선합니다.
- 검색 위치의 탐색 범위와 겹치는 서울시 자치구를 확인합니다.
  - 하나의 자치구만 포함되면 해당 자치구를 안내합니다.
  - 여러 자치구가 포함되면 사용자가 분석할 자치구를 직접 선택하도록 합니다.
- 예를 들어 `염창역 9호선`을 검색했을 때 탐색 범위에 강서구와 양천구가 포함된다면 `강서구 / 양천구 / 모두` 중 선택할 수 있습니다.
- 3개 이상의 자치구가 포함되는 경우에도 각 자치구와 `모두` 선택지를 제공합니다.
- **`모두`는 검색 위치의 탐색 범위와 겹치는 모든 자치구를 선택한다는 의미**이며, 해당 자치구 전체로 주변 탐색 반경을 확장하는 것은 아닙니다.
- 사용자가 자치구 선택을 확정하면 관련 구·동 필터와 분석 정보를 갱신하고, 검색한 장소의 위치는 유지합니다.
- 여러 자치구가 선택되면 관련 행정동을 자치구별로 구분하여 제공합니다.

#### 2. 탐색 범위 및 조건 설정

##### 탐색 대상과 반경

- 사용자가 선택한 행정구역 전체를 탐색하는 방식과 특정 위치 주변을 탐색하는 방식을 구분합니다.
- 장소 주변 탐색은 기본 반경을 500m로 시작하고, 1km까지 변경할 수 있도록 검토합니다.
- 장소 주변 탐색에서 특정 자치구를 선택한 경우, **설정된 반경과 선택한 자치구가 겹치는 영역**을 위치 기반 조회 대상으로 사용합니다.
  - 예: `염창역 → 반경 500m → 강서구`를 선택하면 염창역 반경 500m 중 강서구에 속하는 영역의 주변 카페를 조회합니다.
  - `모두`를 선택하면 해당 반경 내에서 확인된 모든 서울시 자치구의 관련 위치 정보를 조회합니다.

**현재 구현된 API 범위**

- **반경:** 기본 500m이며 소수를 포함한 1~1000m를 지원합니다. 반경 접촉과 선택 구 경계 위의 카페도 포함합니다.
- **구 선택:** 최신 정상 경계와 카페 좌표의 공간 관계로 판정합니다. 행정동 FK 유무에 영향을 받지 않습니다. 구를 지정하지 않으면 경계 데이터 없이 최신 서울 전체 카페 게시본을 조회합니다.
- **목록·건수:** 거리순·업소번호순 목록과 페이징 전 전체 건수를 제공합니다. 반경 밖이거나 검색 결과가 없으면 정상 빈 목록으로 처리합니다.
- **지도 영역:** 별도 API로 WGS84 사각 영역의 변·모서리까지 포함합니다. 선택 구 필터와 업소번호 사전순 페이징을 제공합니다.

현재 화면은 지도 사각 영역 조회·구·동 공간 필터·최대 200곳 표시를 연결했습니다. `선택 지점 주변` 방식에서는 지도 클릭으로 임시 관심 위치를 지정하고 500m·1km의 실제 미터 반경을 조회합니다. 구·동 선택은 유지하지만 반경 요청에는 적용하지 않습니다. 두 방식은 마커·목록·선택 상태를 분리하고, 패널을 닫거나 다른 메뉴로 이동하면 중심점 지정 클릭을 해제합니다. 거리·건수·게시 기준은 서버 응답을 사용하며 중심점을 후보지로 저장하지 않습니다. 세부 계약은 [주변 카페 API](data-design.md#주변-카페-rest-api-계약)와 [지도 영역 카페 API](data-design.md#지도-영역-카페-rest-api-계약)를 따릅니다.

카페가 밀집한 영역은 현재 조회된 마커를 묶어 표시하고, 확대하면 개별 카페를 확인할 수 있습니다. 클러스터 숫자는 해당 묶음에 포함된 현재 표시 대상 마커 수입니다. API 전체 건수나 지역·반경 내 전체 분포를 뜻하지 않으며 최대 200곳의 부분 조회 안내를 유지합니다. 묶음을 누르면 한 레벨 확대하고, 목록에서 카페를 고르면 개별 핀과 정보창을 표시합니다. 후보지·검색 위치·반경 중심 및 행정구역 경계는 별도로 유지합니다.

반경 중심점은 검색한 장소명·주소를 유지하거나 지도 클릭 좌표의 도로명주소·지번주소 순서로 표시합니다. 주소 조회는 카페 조회와 독립적이며 조회 중에는 `주소 확인 중…`, 결과 없음·오류·8초 시간 초과에는 `지도에서 선택한 위치`를 표시합니다. 새 중심점과 해제는 이전 이름·주소를 제거하고, 검색 결과 닫기와 500m·1km 변경은 이름을 보존합니다. 늦은 응답은 현재 좌표에 해당할 때만 표시하며, 표시 정보 변경은 카페 재조회나 선택 해제를 일으키지 않습니다.

개별 카페 이름 라벨은 클러스터가 없는 레벨 1·2에서 겹침을 제한해 화면 안의 최대 40개만 표시합니다. 데스크톱 Hover는 이름·지점·업종·주소·제공된 거리를 임시 정보창으로 표시하며 이동·확대·선택을 변경하지 않습니다. 클릭·모바일 탭·목록 선택은 상세 정보를 고정하고, 명시적 닫기로 선택을 해제합니다. Hover나 마우스 이탈은 고정 정보를 덮어쓰거나 닫지 않습니다. SDK 마커의 키보드 접근은 목록 버튼으로 보완하며 제공되지 않은 영업시간·평점·전화번호 등은 추정하지 않습니다.


##### 분석 조건과 지도 이동

- 분석 기간과 관심 지표 등 필요한 조건을 설정합니다.
- 행정구역 단위의 통계와 특정 위치 주변에서 조회한 데이터를 구분하여 제공합니다.
- 지도를 이동하거나 확대·축소하더라도 적용된 분석 조건은 유지합니다.
- 필요한 경우 `이 지역에서 다시 검색` 기능으로 현재 지도 위치를 기준으로 탐색할 수 있도록 검토합니다.

##### 조회 범위와 후보지 점수 구분

| 구분                   | 기준 범위                         | 제공 정보·해석                                                                              |
| ---------------------- | --------------------------------- | ------------------------------------------------------------------------------------------- |
| 행정구역 점수·통계     | 선택한 구 또는 행정동 전체        | 점수·점포 현황·추정매출·유동인구. 반경 내 실제 수치로 해석하지 않습니다.                    |
| 위치 주변 정보         | 설정 반경과 선택 자치구의 교집합  | 주변 경쟁 카페의 위치·수·분포. `모두`를 선택해도 반경은 확장하지 않습니다.                  |
| 후보지에 표시되는 점수 | 후보지가 속한 구 또는 행정동 전체 | MVP에서는 지역 점수를 사용합니다. 개별 후보지 위치에 별도의 100점 점수를 부여하지 않습니다. |

#### 3. 창업 환경 점수 확인

사용자가 분석할 구 또는 행정동을 선택하면 해당 지역의 주요 공공데이터를 바탕으로 **100점 만점의 카페 창업 환경 점수**를 제공합니다.

##### 점수 표시 방식

- 상세 통계보다 창업 환경 점수를 먼저 표시해 사용자가 해당 지역의 전반적인 특성을 빠르게 파악할 수 있도록 합니다.
- 점수는 `0~100점` 범위로 표시하며, 지역명과 평가 기준 지역을 함께 안내합니다.
- 예를 들어 염창역 검색 후 강서구를 선택했다면 다음과 같이 표시합니다.

  **강서구의 카페 창업 환경 점수는 70/100 (예시)**

- 위 점수는 화면 구성 설명을 위한 예시입니다. 내부 계산과 별개로 실제 공개 점수는 정책·판본·커버리지 승인과 공개 게이트 구현 후에만 제공합니다.
- 구를 선택하면 해당 자치구 전체의 데이터를 기준으로 점수를 계산하고, 행정동을 선택하면 해당 행정동의 데이터를 기준으로 계산합니다.
- 여러 자치구를 선택하거나 `모두`를 선택한 경우에는 각 자치구의 점수를 개별적으로 표시합니다. 서로 다른 지역의 점수를 임의로 합산하여 하나의 점수로 만들지 않습니다.

##### 점수 평가 범위

- 창업 환경 점수는 구 또는 행정동 등 명시된 행정구역을 기준으로 산출합니다.
- 장소 검색 시 사용하는 탐색 반경과 창업 환경 점수의 평가 범위는 별도로 관리합니다.
- 결과 화면에는 **점수 평가 범위**와 **주변 탐색 범위**를 함께 표시합니다.
- 예를 들어 `염창역 → 반경 500m → 강서구`를 선택한 경우 다음과 같이 구분합니다.
  - **창업 환경 점수:** 강서구 전체의 공공데이터를 기준으로 산출한 점수
  - **주변 탐색 정보:** 염창역 반경 500m 중 강서구에 속하는 영역의 위치 기반 데이터
- 따라서 강서구 전체의 점수를 염창역 주변 500m만을 평가한 점수처럼 표현하지 않습니다.
- 행정동을 선택한 경우에는 해당 행정동 전체를 기준으로 산출한 점수임을 명시합니다.
- 서로 다른 집계 단위인 구와 행정동의 점수를 동일한 기준의 점수처럼 직접 비교하지 않도록 안내합니다.

##### 점수 조회 상태 및 예외 처리

- **초기 진입:** 분석 대상이 선택되지 않았다면 구 또는 행정동을 선택하도록 안내하고, 임의의 기본 점수는 표시하지 않습니다.
- **조회 및 계산 중:** 점수 데이터를 불러오거나 계산하는 동안 로딩 상태를 표시합니다.
- **조회 완료:** 지역명, 평가 범위, 최종 점수를 우선 표시합니다.
- **데이터 부족:** 점수 산출에 필요한 데이터가 충분하지 않다면 `산출 불가` 상태와 사유를 안내합니다.
- **조회 실패:** API 오류 등으로 결과를 불러오지 못한 경우 오류 메시지와 다시 시도할 수 있는 기능을 제공합니다.
- 실제 데이터가 없거나 계산할 수 없는 상황에서 임의의 점수를 생성하지 않습니다.

##### 점수 산출 방식

- 카페 수, 추정매출, 유동인구, 개업·폐업 현황 등 확보한 공공데이터를 활용하여 자체 평가 알고리즘을 설계합니다.
- 지표별 특성과 방향성을 고려해 정규화 및 가중치를 적용하고, 최종 점수를 100점 만점으로 환산합니다.
- 주요 평가 항목은 다음과 같이 검토합니다.
  - **소비 및 상권 수요:** 추정매출, 유동인구 등의 지표
  - **경쟁 환경:** 카페 수와 밀집도 등 경쟁 점포 관련 지표
  - **상권 변화 및 안정성:** 개업·폐업 현황과 지역 변화 관련 지표
- 단순히 유동인구가 많거나 카페 수가 적다는 이유만으로 높은 점수를 부여하지 않고, 지표 간 관계를 함께 고려합니다.
- 구와 행정동은 규모와 특성이 다르므로 각각의 비교 기준을 설계하며, 서로 다른 집계 단위의 점수를 직접 비교하지 않도록 합니다.
- 행정동 단위 자료를 이용해 구 단위 점수를 산출해야 하는 경우에는 지표별 집계 가능 여부와 산출 방법을 별도로 검증합니다.
- 평가 항목, 가중치, 정규화 방식 및 점수 구간은 실제 데이터의 품질과 분포를 확인한 뒤 확정합니다.
- 점수 계산에 필요한 데이터가 부족하거나 기준이 맞지 않으면 임의의 점수를 생성하지 않고 `산출 불가` 또는 데이터 부족 상태를 안내합니다.

##### 점수 산출 근거 확인

- 기본 화면에서는 지역명과 최종 점수를 중심으로 간결하게 표시합니다.
- 사용자가 `점수 산출 근거 보기` 또는 `더보기`를 선택하면 상세 분석 정보를 펼쳐서 확인할 수 있도록 합니다.
- 상세 정보에는 다음 내용을 제공합니다.
  - 평가 항목별 점수 및 반영 비중
  - 실제 계산에 사용된 주요 공공데이터 지표
  - 지역별 특징과 점수에 영향을 준 주요 요인
  - 데이터 출처 및 기준 시점
  - 적용된 평가 알고리즘의 기준과 한계
- 사용자가 점수를 맹목적으로 신뢰하지 않고 직접 분석 근거를 확인할 수 있도록 합니다.

##### 점수 해석 시 유의사항

창업 환경 점수는 공공데이터를 기반으로 자체 산출한 상대적 평가 지표입니다. 실제 창업 성공 확률이나 예상 수익을 의미하지 않으며, 임대료·입지의 세부 조건·운영 역량 등 반영되지 않은 요인이 존재할 수 있습니다.

#### 4. 지도에서 관심 대상 선택

##### 기존 카페 확인

- 지도에서 기존 카페의 위치와 분포를 확인합니다.
- 카페 마커를 선택하면 상호명, 위치, 업종 등 확인 가능한 기본 정보를 제공합니다.
- 마우스 호버 시 간단한 정보를 미리 표시하고, 클릭 또는 터치 시 상세 정보를 확인할 수 있도록 구성합니다.

##### 창업 후보지 지정과 상세 패널

- 지도에서 사용자가 직접 관심 지점을 선택해 창업 후보지로 지정할 수 있도록 합니다.
- **창업 후보지는 실제 입점 가능한 상가 매물이 아니라, 주변 상권을 분석하고 비교하기 위해 사용자가 지정한 관심 위치**로 정의합니다.
- 실제 입점 가능 여부, 임대 조건 및 영업 관련 요건은 별도로 확인해야 함을 안내합니다.
- 기존 카페를 선택한 경우와 창업 후보지를 선택한 경우를 구분하여 관련 정보를 제공합니다.
- 선택한 대상에 따라 상세 정보 패널을 열고, 지도를 유지한 상태에서 정보를 확인할 수 있도록 합니다.

#### 5. 상권 상세 분석

##### 주요 지표와 표현 방식

- 창업 환경 점수의 산출 근거와 관련 상권 데이터를 확인합니다.
- 선택한 지역의 점포 수, 개업·폐업 현황, 추정매출, 유동인구 등을 살펴봅니다.
- 주변 경쟁 카페의 위치와 분포를 지도 및 목록으로 확인합니다.
- 기간별 변화 추이와 주요 지표를 차트 및 표로 제공합니다.

##### 집계 범위별 해석

- 상세 분석 정보는 집계 범위에 따라 구분합니다.
  - **선택 위치 주변 정보:** 설정된 반경 내 경쟁 카페의 위치와 수 등 위치 기반으로 조회할 수 있는 정보
  - **행정구역 단위 통계:** 선택한 구 또는 행정동 전체를 기준으로 집계된 점포 현황, 추정매출, 유동인구 등
- 장소 주변 탐색에서 자치구를 선택한 경우, 위치 기반 데이터는 해당 자치구와 탐색 반경이 겹치는 영역을 기준으로 조회합니다.
- 행정동 단위 통계는 탐색 반경과 겹치는 행정동의 전체 집계값을 참고 정보로 제공하며, 반경 내 실제 통계로 해석하지 않도록 표시합니다.
- 여러 자치구가 포함되면 지역별 통계를 구분하여 확인할 수 있도록 합니다.

##### 출처와 데이터 부재 표시

- 각 데이터의 출처, 기준 시점, 집계 단위 및 점수 산출 기준을 함께 표시합니다.
- 데이터가 제공되지 않는 경우 실제 값이 `0`인 경우와 구분하여 안내합니다.

#### 6. 창업 후보지 비교

##### 비교 대상과 주요 지표

- `후보지 분석` 패널의 지도 추가 모드 또는 장소 검색에서 후보지를 등록합니다. A·B·C 최대 3곳의 이름과 좌표를 브라우저 탭에만 임시 저장합니다.
- 중심점을 덮는 서울 자치구 경계가 있을 때 등록합니다. 중심점을 포함하는 행정동이 없거나 여러 개이면 행정동 통계를 표시하지 않습니다.
- 500m 또는 1km의 공통 반경에서 서버가 반환한 경쟁 카페 전체 건수를 비교합니다. 점포·당월 추정매출은 카페 업종, 유동인구는 업종 구분 없이 2026년 2분기 행정동 전체 통계를 사용합니다. 자료별 게시 시점을 표시합니다.
- 여러 후보지의 주변 경쟁 카페, 점포 현황, 추정매출, 유동인구 등 주요 지표를 비교합니다.
- 창업 환경 점수 표시는 공개 승인 이후의 요구사항입니다.
- 후보지별 반경 내 위치 기반 정보와 행정구역 단위 통계를 구분하여 비교합니다.

현재 `/explore` 메뉴 이름은 **후보지 분석**입니다. 1곳은 상세 분석, 2~3곳은 같은 반경 기준으로 비교합니다. 가로 스크롤 표 대신 후보지 요약 카드 → 주변 경쟁 환경 → 소속 행정동 상권 특성으로 구분합니다. 요약은 이름·지역·전체 경쟁 카페 수·선택됨 표시와 지도 확인·이름 변경·삭제를 제공하고 좌표는 접힌 상세에 둡니다.

주변 경쟁 환경은 `totalCount`와 실제 반환 목록의 차이를 표시하며 서버 거리순 최대 3곳의 이름·지점·거리·주소를 제공합니다. 반경 조회는 최대 200곳을 유지하며 후보지별 오류·재시도·빈 결과와 게시 시각을 독립적으로 표시합니다. 행정동 전체 통계는 반경 통계로 환산하거나 합산하지 않습니다. 같은 행정동은 동일한 통계 응답을 공유하며 경계에 걸쳐 소속을 확정하지 못하면 통계만 비교 불가로 표시합니다. 당월 매출을 분기 합계로 해석하지 않고, NULL·실제 0·원본 정밀도를 보존합니다. 경쟁 카페 수를 창업 유불리로 평가하거나 순위·점수·미검증 증감률을 표시하지 않습니다. 기존 저장 데이터와 등록·복원·지도 마커 연동은 유지합니다.

##### 비교 기준과 예외 표시

- 동일한 기준 기간과 집계 단위에서 비교할 수 있도록 안내합니다.
- 구 단위와 행정동 단위 점수는 평가 기준이 다를 수 있으므로 직접적인 우열 비교를 피합니다.
- 같은 행정동에 속한 후보지는 동일한 행정동 통계를 공유할 수 있지만, 각 위치 주변의 경쟁 카페 수와 분포는 다를 수 있음을 안내합니다.
- 데이터가 없거나 기준 시점이 다른 경우 해당 내용을 명확하게 표시합니다.
- 비교 결과를 통해 후보지별 특징을 파악하고, 창업 전 추가로 조사할 사항을 확인합니다.

##### 후보지 점수와 지역 점수의 구분

- MVP에서는 개별 창업 후보지의 위치 자체에 별도의 100점 점수를 부여하지 않습니다.
- 후보지에 표시되는 창업 환경 점수는 **해당 후보지가 속한 구 또는 행정동의 평가 점수**입니다.
- 동일한 행정동에 있는 두 후보지는 같은 행정동 점수를 공유할 수 있습니다.
- 다만 각 후보지의 위치와 탐색 반경에 따라 주변 경쟁 카페 수와 분포 등의 위치 기반 정보는 달라질 수 있습니다.
- 비교 화면에서는 점수의 평가 단위를 명확히 표시하여 지역 점수를 특정 지점의 독립적인 점수로 오해하지 않도록 합니다.
- 추후 충분한 위치 기반 데이터와 검증 기준이 확보되면 개별 후보지의 반경 단위 평가 점수를 별도로 도입하는 방안을 검토합니다.

#### 탐색 화면 구성

탐색 페이지는 전체 화면 지도를 중심으로 검색·필터와 확장 가능한 상세 정보 패널을 배치하는 방향으로 구성할 예정입니다.

지역 선택 후에는 창업 환경 점수를 우선적으로 표시하고, 사용자가 원하는 경우에만 점수 산출 근거와 세부 상권 데이터를 확장하여 확인할 수 있도록 합니다.

#### 검색 및 데이터 이용 시 유의사항

##### 서울 지원 범위

- 서울특별시 외 지역을 검색한 경우 서비스 지원 범위를 안내하고, 서울 외 지역에 대한 상권 분석은 제공하지 않습니다.
- 검색 위치의 탐색 반경이 서울 외 지역까지 걸치면 서울특별시 내부만 분석 대상으로 포함합니다.

##### 집계 단위와 점수 해석

- 행정동별 추정매출·인구·점포 통계와 개별 카페의 위치 정보는 집계 범위가 다릅니다.
- 특정 위치 주변에 여러 행정구역이 포함되더라도 행정동 전체의 통계를 해당 위치 주변의 실제 수치로 해석하거나 단순 합산하지 않습니다.
- 서로 다른 기준 시점이나 집계 단위의 데이터를 비교할 때에는 한계를 안내합니다.
- 창업 환경 점수는 자체 평가 알고리즘에 따른 참고 지표이며, 실제 창업 성공이나 수익을 보장하지 않습니다.

## 서비스 데이터 흐름과 설계 고려사항

아래는 완성 후의 목표 흐름입니다. 공공데이터 ETL·DB 적재와 행정구역·점포·추정매출·유동인구·카페 반경·지도 영역 조회는 구현했습니다. 내부 A 계산·스냅샷 재현도 구현했으며 추가 구 단위 집계·승인 후 점수 공개를 잇는 흐름은 구현 예정입니다.

### 주요 데이터 흐름

#### 1. 공공데이터 수집 및 적재

1. ETL이 외부 공공데이터 API 또는 제공 파일에서 데이터를 수집합니다.
2. 외부 데이터의 형식과 필수 값을 검증합니다.
3. 날짜, 행정구역 코드, 좌표계, 업종 분류 등 필요한 항목을 정제·변환합니다.
4. 데이터의 기준 시점과 출처를 관리하면서 PostgreSQL에 적재합니다.
5. 적재된 데이터가 API 조회와 점수 계산에 사용할 수 있는 상태인지 검증합니다.

구 단위 통계는 [공식 자치구 원천 우선 정책](district-statistics-policy.md)을 따릅니다. 행정동 수치의 합계·비율 평균으로 공식 구 값을 대신하지 않습니다.

**공식 자치구 통계의 구현·검증**

- **점포:** 실제 CSV 검증, V5, 적재 ETL과 조회 API를 구현했습니다. DB 없는 probe도 유지합니다.
- **추정매출:** V6·적재 ETL·조회 API를 구현했습니다. 당월 의미·BIGINT·NULL·정상 게시 출처를 보존합니다. 실제 개발 DB의 V6 적용·매출 적재는 [검증 기록](etl-guide.md#자치구-추정매출-개발-db-적용적재-검증-2026-10-31)을 따릅니다.
- **유동인구:** V7·적재 ETL·조회 API를 구현했습니다. 업종을 사용하지 않으며 세 NUMERIC의 정밀도·소수 자릿수·NULL·정상 출처를 보존합니다. 실제 개발 DB의 V7 적용·550행 인구 적재·API 대조는 [검증 기록](etl-guide.md#자치구-길단위인구-개발-db-적용적재-검증-2026-11-01)을 따릅니다.

실제 서비스 화면과 위 데이터를 연결하는 작업은 후속 범위입니다.

#### 2. 지역 탐색 및 상권 조회

1. 사용자가 프론트엔드에서 구·행정동 또는 특정 장소를 선택합니다.
2. 프론트엔드는 선택한 지역과 탐색 조건을 백엔드 API에 전달합니다.
3. 백엔드는 필요한 경우 PostGIS를 사용해 탐색 반경과 행정구역 경계의 관계를 확인합니다.
4. 해당 조건에 맞는 카페 위치와 상권 통계를 조회합니다.
5. 프론트엔드는 응답받은 데이터를 지도, 상세 패널, 차트 및 표로 표시합니다.

#### 3. 창업 환경 점수 제공

1. 백엔드는 선택한 구 또는 행정동의 점수 산출에 필요한 데이터를 확보합니다.
2. 검증된 평가 알고리즘을 적용해 창업 환경 점수와 항목별 결과를 산출합니다.
3. 최종 점수, 평가 지역, 기준 시점, 평가 항목 및 산출 근거를 API 응답으로 제공합니다.
4. 프론트엔드는 최종 점수를 먼저 표시하고, 사용자가 요청한 경우 상세 산출 근거를 보여줍니다.

[현재 v1 권장안](score-v1-contract.md#61-권장-조회-시-계산-v1에는-region_score-미도입)은 승인된 입력과 현재 DB를 대조한 뒤 조회 시 전체 집단을 계산하고 별도 `region_score`를 두지 않는 방식입니다. 내부 조회·계산은 구현했지만 공개 계산 시점·저장 정책은 아직 채택하지 않았습니다.

### 설계 시 고려사항

- **집계 단위 구분:** 반경 내 점포 정보와 행정구역 전체의 통계를 혼동하지 않도록 데이터 모델과 API 응답을 설계합니다.
- **데이터 정합성:** 서로 다른 출처의 데이터가 가진 행정구역 코드, 집계 기준 및 갱신 주기를 검증합니다.
- **점수의 재현성:** 평가 알고리즘의 버전, 적용 가중치 및 사용 데이터 기준 시점을 관리하는 방향으로 설계합니다.
- **보안:** 외부 공공데이터 인증키와 데이터베이스 접속 정보는 서버 측 환경변수 등으로 관리합니다.
- **검증:** ETL 데이터 검증, 점수 계산 단위 테스트, 데이터베이스 공간 조회 통합 테스트를 고려합니다.

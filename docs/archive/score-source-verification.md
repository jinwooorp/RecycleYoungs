# 창업 환경 점수 원천 데이터 검증 및 MVP v1 정책 후보

**확인일: 2026-11-02 KST. 최종 모델·방향·가중치·제외 기준을 채택한 문서가 아닙니다.** 공식 공개 설명이 현재 적재 CSV 판본에도 적용되는지 구분하고, 구현 전에 필요한 결정만 정리했습니다. 새 모델·점수 실험·DB 조회·원본 파일 재수집은 하지 않았습니다.

핵심 판단은 **A를 단일 분기 참고 비교의 조건부 후보로 유지하되, 현재 적재 판본의 비교 가능성과 평가 목적을 확인한 뒤 공개 채택 여부를 결정한다**는 것입니다. 모든 미확인 사항의 완전한 해명을 기다릴 필요는 없지만, 출처가 정상이라는 이유만으로 서로 다른 의미의 값을 섞어도 된다고 볼 수는 없습니다.

### 2.1 매출: 제공 주기와 합계 기간은 다른 질문입니다

**확인됨 — 일반 제공 기준:** [서비스 소개](https://golmok.seoul.go.kr/introduce.do)와 [제공정보 PDF 1쪽](https://golmok.seoul.go.kr/images/seoul_info.pdf#page=1)은 분기별 제공과 분기별 해당 월을 안내합니다. [구 매출](https://data.seoul.go.kr/dataList/OA-22176/S/1/datasetView.do)·[동 매출](https://data.seoul.go.kr/dataList/OA-22175/S/1/datasetView.do)은 지역별 추정매출이며 금액 단위가 원임을 설명합니다. 이것만으로 `당월_매출_금액`을 분기합계 또는 월평균으로 확정할 수는 없습니다.

**일부 확인 — 월평균이라는 근거의 범위:** 기존에 인용한 [서울시 배포 자료 8쪽](https://culture.seoul.go.kr/culture/cmmn/file/fileDown.do?atchFileId=af365d87d23c4c5b8411d3ba236292f6&bbsId=&fileSn=2&menuNo=200050#page=8)은 동대문 패션타운 관광특구의 2019·2024년 비교에서 분기 월평균을 3개월분으로 환산했다고 설명합니다. 이번에는 공식 URL의 검색 색인에서도 해당 설명을 확인했으나 원문 파일 재열람은 시간 초과였습니다. **재열람에 성공한 새 원문 근거로 격상하지 않습니다.** 그 자료가 언급한 공간 단위·기간은 현재 구·동 `20251~20262` CSV와 다르므로 기존 미확인 판단을 유지합니다.

**설계 제안:** DB 이름을 근거로 ‘월매출’이라고 단정하거나 3을 곱하거나 나누지 않습니다. 임시 표시명은 ‘원천 추정매출(원), 기준 분기 20262’로 하고 합계 기간 미확인을 함께 안내합니다. 실제 월매출·연간 매출·절대 매출 하한·점포 평균 매출을 제공하려면 적용 판본의 집계 기간 확인이 선행돼야 합니다.

같은 지표의 모든 지역에 동일한 양의 환산배수를 곱해도 순위 정규화는 바뀌지 않습니다. 이는 **수학적 성질**이며 현재 데이터가 지역별로 동일한 기간·환산 규칙을 사용한다는 증거는 아닙니다. 따라서 환산을 하지 않는 단기 비교와 판본 내 비교 가능성 확인을 함께 제안합니다.

### 2.2 추정 대상과 보정: 공식 설명 간 차이가 남습니다

**확인됨 — 일반 구조:** [제공정보 PDF 3쪽](https://golmok.seoul.go.kr/images/seoul_info.pdf#page=3)은 카드 자료와 연도·지역·업종별 보정비율을 이용하는 추정을 설명합니다. 개별 카페의 실제 수익이나 현금흐름을 측정한 값이 아닙니다.

**일부 확인 — 설명 차이:** 현재 [서비스 소개](https://golmok.seoul.go.kr/introduce.do)의 카드 표는 신한카드를, [별도 제공정보 안내](https://golmok.seoul.go.kr/policy/sectorAnalysis.do)는 BC·KB·SH를 제시합니다. 두 안내의 문장에는 보정비율을 곱한다고 쓰지만 표에는 나눗셈이 나옵니다. [데이터 출처](https://golmok.seoul.go.kr/source.do)는 2026-08-18 업데이트 표에 BC·KB와 SH의 서로 다른 자료 기준시점도 제시합니다. 하나의 현재 CSV에 어느 조합이 적용됐는지 단정할 수 없습니다.

앞의 관광특구 배포 자료는 현금·지역화폐가 제외됐다고 설명하지만, 이를 현 적재 판본의 포함·제외 규칙으로 일반화하지 않습니다. 보정 결과를 다시 보정하거나 카드사별 금액을 합쳐 새 원본을 만들지 않습니다.

**미확인:** 현재 파일의 대상 사업체 목록·추정 대상의 범위, 프랜차이즈 포함 조건, 현금·지역화폐·외국인 매출 포함 여부, 사용 계수와 적용 연도입니다. 제공기관의 판본별 명세가 필요합니다. A에서 이미 제공된 지역 규모 지표를 비교하는 것과 B·C에서 이를 ‘실제 점포당 매출’로 해석하는 것은 서로 다른 요구입니다.

### 2.3 점포와 폐업률: 영업 중 경쟁 점포 수로 바꾸지 않습니다

**확인됨 — 공식 일반 정의:** [제공정보 PDF 2쪽](https://golmok.seoul.go.kr/images/seoul_info.pdf#page=2)은 운영 점포와 당기 폐업 점포를 함께 세는 구조를 설명합니다. 폐업률은 당기 신고 건수와 전체 점포를 이용한 비율이며, 분모의 전체 점포에는 해당 기간 폐업 기록이 있는 점포도 포함됩니다. [구 점포 안내](https://data.seoul.go.kr/dataList/OA-22173/S/1/datasetView.do)·[동 점포 안내](https://data.seoul.go.kr/dataList/OA-22172/S/1/datasetView.do)는 전체 점포가 일반 점포와 프랜차이즈의 합임을 명시합니다.

**일부 확인 — 현재 필드 적용:** 위 정의는 폐업률의 개념을 좁혀 주지만, 현재 `CLSBIZ_RT`가 어느 점포 컬럼·기준일·반올림을 사용했는지까지 증명하지는 않습니다. 기존 CSV의 100% 초과 비율 관찰도 남아 있으므로, 일반 설명에 맞추려 원본을 수정하지 않습니다. `closed_store_count / store_count`로 재산정하거나 100%로 자르지 않습니다.

**설계상 가정:** A의 점포 감소 방향을 유지한다면 ‘기록상 점포가 적은 쪽에 비중을 주는 경쟁 부담 가정’이라고 설명해야 합니다. 영업 중인 실시간 경쟁점 수 또는 적정 점포 수를 측정한 것으로 표현하지 않습니다. 점포 수가 많을수록 수요가 큰 상권일 수도 있다는 기존 실험 결과는 이 가정의 반대 근거로 함께 제시합니다.

점포·매출의 업종 코드가 같아도 모집단 일치가 확인되지는 않습니다. 일치 여부는 A의 독립적인 지역 지표 조합에서는 한계로 남길 수 있지만, B·C를 실제 점포당 평균으로 제공하는 경우에는 먼저 해결해야 합니다.

### 2.4 인구: 길에 배분한 규모와 고객 수는 다릅니다

**확인됨 — 일반 생성 구조:** [데이터 출처](https://golmok.seoul.go.kr/source.do)는 서울시·KT 생활인구를 공간 격자와 집객시설을 이용해 길 단위로 배분한다고 설명합니다. [제공정보 PDF 4쪽](https://golmok.seoul.go.kr/images/seoul_info.pdf#page=4)은 10m 길 단위 생성을 안내합니다. [구](https://data.seoul.go.kr/dataList/OA-22179/S/1/datasetView.do)·[동](https://data.seoul.go.kr/dataList/OA-22178/S/1/datasetView.do) 포털은 이를 지역별 생활인구로 소개합니다.

**일부 확인 — 기간·중복:** 공식 [뜨는 상권 화면](https://golmok.seoul.go.kr/commercialArea/commercialArea.do)의 정적 설명에는 일평균 표현과 3개월간 인구 추이 표현이 함께 있습니다. 화면용 값이 OA의 `TOT_FLPOP_CO`와 어떤 변환 관계인지 확인하지 못했습니다. 정적 예시 숫자는 실제 지역 관측값으로 사용하지 않았습니다.

사람이 여러 시점·공간에 존재할 수 있는 자료이므로, 원천 총계를 서로 다른 고객의 수로 볼 근거가 없습니다. 정확한 중복 여부·횟수, 시간별 합인지 일평균인지, 내·외국인 포함 기준은 현 적재 판본에서 미확인입니다. **임의로 일수·시간·도로 길이로 나누지 않고 카페 방문자·고유 통행자 수로 표시하지 않는 것**을 잠정안으로 제안합니다.

### 2.5 과거 분기와 결측: 코드표가 모든 문제를 해결하지는 않습니다

**확인됨 — 공개 변경 공지:** 여섯 OA 페이지에는 2026-07-03 적용 공지가 있습니다. 2024년부터 표준단위구역을 사용하며 해당 기준 카드 매출이 2021년부터 제공돼 2021년 이후 자료를 제공한다는 설명입니다. 예: [구 매출 공지](https://data.seoul.go.kr/dataList/OA-22176/S/1/datasetView.do), [동 인구 공지](https://data.seoul.go.kr/dataList/OA-22178/S/1/datasetView.do). 이는 `20251~20262`가 제공 범위에 들어간다는 일반 근거이며, 기간별 모든 행의 동등성·완전성이나 재배포 이력을 보증하지 않습니다.

공식 [자치구-행정동 코드표](https://golmok.seoul.go.kr/images/adstrd_code.pdf)는 코드·명칭 대응을 제공합니다. 그러나 적용 시작·종료일과 과거 분기별 폴리곤을 확인할 자료는 아니므로 현재 경계와 과거 통계의 호환성을 확정하지 않습니다. 현재 포털의 갱신일이나 2025년 ZIP의 수정일도 적재 CSV의 체크섬과 직접 연결되지 않습니다.

**미확인 — 매출 누락 사유:** 공식 코드표에는 면목5동 `11260550`·하계2동 `11350612`·북가좌1동 `11410710`·개포1동 `11680660`이 나옵니다. 이것은 해당 지역의 카페 매출이 0이거나 비공개라는 근거가 아닙니다. 공식 안내와 제한한 공식 도메인 검색에서 네 동의 누락을 설명하는 근거는 확보하지 못했습니다. 소수점포 비공개·재개발·추정 불가·ETL 오류 중 하나를 원인으로 채택하지 않습니다.

기존 검증에서는 6분기 모두 이 4동의 매출이 없고, `20251`에는 둔촌1동 `11740690`도 없었습니다. 현재 `20262` 비교 집단은 25구·421동이며, `20251`의 동 입력 완비는 420개입니다. **이는 이전 읽기 전용 검증의 관찰 사실**입니다. 이번에 DB를 다시 조회하거나 과거 점수·분기 간 안정성을 계산한 것은 아닙니다.

## 3. 무엇이 MVP를 막고, 무엇은 잠정 처리할 수 있나요?

따라서 **원본 통계 비교와 계산·재현 계약 준비는 진행할 수 있으나, 공개 종합 점수의 무조건적인 구현 승인을 내릴 근거는 아직 부족합니다.** 잠정 진행은 불확실성을 없앤다는 뜻이 아니라 기능과 해석을 좁히고 그 한계를 받아들이는 결정입니다.

### 다른 후보보다 이 안을 먼저 검토하는 이유

- **A의 장점:** 각 입력이 몇 점을 만들었는지 설명할 수 있고 기존 민감도 기록을 그대로 판단 근거로 쓸 수 있습니다. 새로운 결합식을 검증하는 부담이 없습니다.
- **점포 증가안은 보류:** 기존 실험에서 동 상위 5곳이 2곳만 겹치고 최대 192등 이동했습니다. 수요 규모와 점포 수의 양의 상관은 감소 가정의 약점이지만, 증가 방향의 정답 근거도 아닙니다. 감소 유지 역시 이전 기준선을 고정하는 선택일 뿐입니다.
- **B·C·D·E로 교체하지 않는 이유:** 점포당 지표의 작은 분모와 모집단 문제, D의 0점, E의 보상 잔존·설명 부담은 현재 목적·원천 의미의 빈틈을 해결하지 못합니다. 새 실험을 수행한 판단은 아닙니다.
- **비중을 임의 조정하지 않는 이유:** 이전 매출 0.30→0.25 조건에서 삼성동·북아현동·삼양동이 A 상위 43동에 진입했습니다. 그때 남은 비중은 기존 비율로 재배분했으며 합계는 1입니다. 이 민감도를 알고도 ‘조금 바꾸면 해결’된다고 할 수 없습니다.

기존 실제 사례에서 삼성동은 매출 362,431원인데 A 60.36점·83위입니다. 전체 지역의 매출 최저값이므로 매출 기여는 0점이며, 다른 항목이 점수를 만듭니다. 이 사실을 원본 0·결측과 혼동하거나 실제 과대평가의 증명으로 사용하지 않습니다. **이 보상을 허용하지 않는 서비스라면 A 공개 채택을 보류하고 제한 정책의 근거부터 정해야 합니다.** 이번에 임계값을 만들거나 제한 적용 점수를 계산하지 않았습니다.

### 부족·예외·정밀도 후보

아래는 기존 계약을 바꾸지 않는 후보와, 기존에 미확정이었던 부분에 대한 **추가 제안**을 구분한 것입니다.

- **기존 원칙 유지:** 최신 정상 경계 선택 후 실제 행 확인, 구·동 동일 경계 게시본, 통계 각 행의 실제 `source_batch_id` 검증. 공식 구 통계를 동 합계로 대체하지 않고 통계 전역 최신 배치를 강제하지 않습니다.
- **기존 원칙 유지:** 필수 S·F·N·c의 행 없음·NULL·비유한 값·음수는 계산하지 않습니다. 완비 공통 집단에서만 정규화하고 가중치 재분배·다른 분기 대체는 하지 않습니다. 실제 0은 원본 그대로 보존합니다. 기존 공통 비교 조건 N>0을 후보에서도 유지하며, 이는 A의 수학적 분모 때문이 아니라 비교 조건의 연속성 때문입니다.
- **기존 원칙 유지:** n≤1이면 산출 불가입니다. n은 비교 지역 수이고 N은 한 지역의 점포 수입니다. D의 정상 계산 0과 결측, E의 거리 합 0을 구분하는 기존 정의는 보존하며 v1 A 후보 때문에 다른 모델 정의를 바꾸지 않습니다.
- **추가 제안:** 필수 지표 중 하나라도 모든 지역에서 같은 값이면 해당 항목에 변별력이 없으므로, v1 종합 점수는 산출 보류·사유 안내를 권장합니다. 임의 0점·50점 또는 비중 재분배를 넣지 않습니다. 이는 이전 실험의 동일값 순위 계산을 소급 변경하는 것이 아니며, 최종 서비스 예외 정책의 선택지입니다.
- **추가 제안:** 비교 집단이 변하면 새 기준으로 계산한 별도 결과라는 점을 남깁니다. 최소 커버리지의 임의 숫자는 정하지 않습니다. 제외 목록·비율·입력 출처를 검토하고 허용 범위를 확정하기 전에는 부분 자료를 조용히 정상 서비스로 게시하지 않습니다.
- **추가 제안:** A의 순위 정규화·가중합은 정확한 유리수 계산을 재현 기준으로 삼고, 순위는 표시 반올림 전에 동률 평균으로 결정합니다. 저장 정밀도·Java 표현·표시 자릿수·반올림 모드는 구현 전에 선택합니다. 이번 문서의 2자리 실험 표시를 서비스 정책으로 확정하지 않습니다.
- **구현 전 결정:** 입력·비교 집단·경계·행별 출처·제외 사유·비중·정규화·알고리즘 버전을 보존할 방법을 정해야 합니다. Upsert 이후 배치 ID만으로 과거 값을 항상 복원할 수는 없습니다. 저장 방식·캐시·API 필드는 이번에 정하거나 구현하지 않았습니다.

### 사용자에게 함께 설명할 내용

정상 결과에는 지역 단위·분기·카페 업종, 비교 집단 수와 제외 지역, 네 원본 지표·방향·기여, ‘서로 다른 집계 단위와 비교할 수 없는 상대 참고값’임을 함께 제공합니다. 예를 들면 ‘추정매출은 현 적재 판본의 월평균·분기합계 구분을 확인 중이며 임의 환산하지 않았습니다’라고 안내합니다.

‘카페가 적어 유리하게 반영했지만 수요 부족일 수도 있음’, ‘인구는 카페 고객이나 고유 방문자 수가 아님’, ‘폐업률은 창업 실패 확률이 아님’, ‘낮은 매출을 다른 항목이 보완할 수 있음’을 설명합니다. 미확인 사항을 작은 각주 하나로 숨긴 채 창업 추천 지역이라고 표시하지 않습니다.

매출이 없는 4동에는 ‘데이터 부족으로 산출 불가, 원인 미확인’과 사용 가능한 원본 통계를 표시하는 후보를 권장합니다. 경계·데이터 미준비, 지역 미존재, 조회 실패는 기존 통계 API의 503·404·`200, data: null` 계약과 분리해 후속 점수 API에서 정의해야 합니다. 기존 API 의미를 이번 문서로 변경하지 않습니다.

### 제공기관에 추가로 확인할 질문

문의처는 여섯 데이터셋의 제공부서인 서울신용보증재단 데이터분석팀입니다. **이번에 문의를 발송하거나 답변을 받지 않았습니다.** 다음 질문을 현재 로컬 파일 체크섬·기준 분기·OA 식별자와 연결해 확인해야 합니다. 인증정보나 전체 원본을 공개할 필요는 없습니다.

1. 적재한 구·동 추정매출의 `THSMON_SELNG_AMT`는 어떤 기간의 합·평균이며, 같은 판본의 모든 지역에 같은 규칙이 적용되는가? 적용 카드사·보정 방식·현금 등 포함 범위의 판본 명세는 무엇인가?
2. 점포·매출이 포함하는 사업체가 같은가? `CLSBIZ_RT`의 정확한 분모 필드·당기 정의·반올림과 100% 초과의 가능한 사유는 무엇인가?
3. `TOT_FLPOP_CO`의 시간 집계와 공간 배분·중복 처리·인구 포함 범위는 무엇이며, 구·동별 기준은 일관적인가?
4. `20251~20262` 재배포본의 공간 기준·행정동 경계·소속과 변경 이력은 무엇인가? 현재 표시 경계와 대응할 자료가 있는가?
5. 카페 매출이 없는 4동 및 `20251` 둔촌1동의 누락은 제공·비공개·추정 범위 중 어떤 규칙 때문인가? 현 적재 파일의 행 부재가 공식 배포본과 일치하는가?

공개 자료 조사는 여기서 종료합니다. 같은 일반 설명을 반복 검색해 확정 등급을 올리지 않습니다. **다음 단계는 새 모델 연구가 아니라 사용할 판본의 연결 근거 확보와 위 정책 선택의 명시적인 결정**입니다. 원본 통계 기반 MVP 준비는 진행하되, 공개 종합 점수는 그 조건을 통과한 뒤 별도 승인·구현합니다.

## 6. 검증 범위와 미실행 사항

- 기존 `score-design.md` 1~7절·기술 부록과 두 실험 보존 기록의 수식·실제 수치·배치 정보를 수정하지 않았습니다. 도입 탐색 안내와 새 8절, 이 조사 기록만 변경 대상입니다.
- 공식 HTML·제공정보 PDF·코드표를 읽기 전용으로 확인했습니다. PDF는 추출 텍스트로 확인했으며 페이지 이미지 조회는 이미지가 반환되지 않아 시각적으로 대조하지 못했습니다. 관광특구 배포 자료의 직접 재열람 시간 초과와 현재 CSV 판본 연결 미확인을 위에 남겼습니다. 동적 Open API 탭의 새 산정 명세는 확보하지 못했으며 기존 프로젝트의 필드 대응을 변경하지 않았습니다.
- DB 조회·원본 파일 재수집·새 점수 계산·과거 순위 안정성·실제 창업 성과 검증은 미실행입니다. 확인하지 않은 모집단·기간·경계·누락 사유를 추정하지 않았습니다.
- 최종 검증 대상은 링크·앵커·표·Prettier·공백 오류와 기존 기록 보존입니다. 새 정책 후보는 채택 완료 또는 API 계약 변경으로 표현하지 않습니다.

# R03 실제 데이터 대표값 대조 및 현재 입력 검산

**2026-11-02 실행 결과: 대표 6곳과 기존 커버리지·통계 출처가 일치했고, 현재 446개 지역의 정확한 계산 검산을 통과했습니다. 과거 전체 입력 fixture가 없어 R03 완전 재현은 미완료입니다.** 공개 점수·정책·판본 비교 가능성을 승인한 결과가 아닙니다.

기준은 [계산 계약 R03](../score-v1-contract.md), [이전 평가 기준 검증](score-mvp-criteria-validation.md), [원천 의미의 미확인 사항](score-source-verification.md)입니다. 기존 기록·계산기·Repository·Service 계약은 변경하지 않았습니다.

## 1. 실행 환경과 안전 확인

- 대상: `20262`·카페 `CS100010`. 유동인구에 업종 조건을 적용하지 않았습니다.
- 환경: Java 21·기존 Gradle Wrapper·로컬 개발 PostgreSQL/PostGIS. 테스트용 합성 DB를 실데이터로 보고하지 않았습니다.
- 도구는 Spring Boot나 웹 서버를 시작하지 않고 필요한 Repository·Service·트랜잭션 빈만 구성합니다. Flyway 빈·자동 마이그레이션은 없습니다.
- JDBC 시작 옵션으로 `default_transaction_read_only=on`, 조회 제한 40초·잠금 대기 제한 5초를 설정했습니다. 상위 트랜잭션은 읽기 전용 `REPEATABLE_READ`이며 JDBC 트랜잭션 관리자도 `SET TRANSACTION READ ONLY`를 적용합니다.
- 실제 DB가 반환한 `default_transaction_read_only=on`, `transaction_read_only=on`, `transaction_isolation=repeatable read`를 먼저 확인한 뒤 입력을 읽었습니다. 하나라도 다르면 통계 조회를 진행하지 않습니다.
- 종료는 `ROLLBACK`으로 강제합니다. INSERT·UPDATE·DELETE·DDL·임시 테이블·ETL·재게시·원본 파일·백업 생성은 수행하지 않았습니다. 전체 입력은 메모리에서만 사용했습니다.

| 시점                         | KST 시각                         | 의미                                                  |
| ---------------------------- | -------------------------------- | ----------------------------------------------------- |
| DB 트랜잭션 시작             | 2026-11-02T17:38:10.227556+09:00 | DB의 `transaction_timestamp()`                        |
| 안전 조건 확인               | 2026-11-02T17:38:10.238637+09:00 | 안전 조회 시 DB의 `clock_timestamp()`                 |
| 롤백 완료 후 클라이언트 확인 | 2026-11-02T17:38:10.419484+09:00 | 트랜잭션 실행이 반환된 뒤의 시각, DB 완료 시각은 아님 |

설정 확인 단계에서는 미해석된 환경변수 참조 때문에 한 차례 실행을 중단했습니다. 이 단계에서는 DB에 연결하지 않았고, 포트·DB명 참조를 메모리에서 해석한 뒤 위의 실데이터 트랜잭션 한 번을 실행했습니다. 서로 다른 실행을 같은 스냅샷으로 표현하지 않습니다.

안전 조건의 합성 통합 테스트에서 JDBC `readOnlyMode=always`는 자동 커밋 해제 시 세션 기본 읽기 전용 값을 해제함을 확인했습니다. 도구는 `transaction` 모드를 사용해 시작 옵션의 기본값과 현재 트랜잭션의 읽기 전용 상태를 모두 유지합니다. 해당 테스트 실패 시점에는 개발 DB 조회를 시작하지 않았습니다.

## 5. 재실행 방법과 일반 테스트 분리

코드는 [별도 실행 소스셋](../../backend/src/scoreRegression/java/kr/ac/recycleyoungs/score/ScoreRegressionMain.java)과 [검산기](../../backend/src/scoreRegression/java/kr/ac/recycleyoungs/score/ScoreRegressionVerifier.java), [Gradle 명시 작업](../../backend/build.gradle)에 있습니다. 제품 JAR에는 도구가 포함되지 않습니다. 일반 `test`·`integrationTest`·`build`가 이 실데이터 작업을 호출하지 않습니다.

| 환경변수                   | 필수 값·용도                                                   |
| -------------------------- | -------------------------------------------------------------- |
| `SCORE_REGRESSION_ENABLED` | 명시 실행 시에만 `1`                                           |
| `DB_JDBC_URL`              | 사용할 개발 PostgreSQL의 완전히 해석된 JDBC URL, 인증정보 제외 |
| `DB_USER`                  | 개발 DB 사용자, 출력하지 않음                                  |
| `DB_PASSWORD`              | 개발 DB 비밀번호, 출력하지 않음                                |

환경변수는 기존 개발 환경 절차로 준비합니다. 도구는 `.env`를 자동 로드하지 않으며 `${DB_PORT:-5432}`·`${DB_NAME}` 같은 참조도 자체 해석하지 않습니다. 이번에는 로컬 설정의 참조를 메모리에서 해석해 전달했고 값·접속 문자열·개인 경로를 출력하지 않았습니다.

인증정보를 명령행 인자로 전달하거나 로그에 출력하지 않습니다. URL query는 `sslmode`·`ssl`·`currentSchema`만 허용하며, `options`·`readOnly`·`readOnlyMode`·인증정보·추가 설정 파일로 도구의 안전 설정을 덮어쓰지 못하게 합니다.

```bash
cd backend
# DB_JDBC_URL, DB_USER, DB_PASSWORD는 안전하게 준비한 환경변수를 사용합니다.
SCORE_REGRESSION_ENABLED=1 ./gradlew scoreRegression --quiet --console=plain 2>/dev/null
```

표준출력에는 검증 요약 또는 안전한 실패 단계만 나옵니다. Gradle의 일반 오류 로그에 Java 실행 경로 등이 포함될 수 있어 위 명령은 표준오류를 버립니다. 실패 시 종료값을 확인하고, `--info`·`--debug`·`--stacktrace` 로그나 접속 설정을 공유하지 않습니다.

Java 도구의 종료값은 0=대표 대조·현재 검산 성공, 1=기준선 차이·검산 실패, 2=설정·접속·안전 조건 등으로 미완료입니다. Gradle은 도구의 비정상 종료를 작업 실패로 전달하므로 외부 Gradle 종료값만으로 1과 2를 구분하지 말고 안전한 표준출력도 확인합니다. **0도 R03 완전 재현·공개 승인이라는 뜻이 아닙니다.**

일반 테스트에서는 합성 입력 또는 일회용 PostGIS만 사용합니다. 실행 비활성·안전 속성 덮어쓰기 차단, 정확한 기여·순위, 입력 순서, 체크섬·커버리지·대표값 변경, 인증 실패·빈 최신 경계, DB 읽기 전용 설정·롤백·마이그레이션 이력 불변을 검증합니다. 실행 명령은 `backend/`에서 다음과 같습니다.

```bash
./gradlew test
./gradlew integrationTest
./gradlew build
./gradlew spotlessCheck
```

최종 검증은 단위 **482개(기존 476·신규 6)**, 일회용 DB 통합 **828개(기존 825·신규 3)** 모두 통과했으며 실패·건너뜀은 없습니다. DB 없는 기본 프로필 기동, 빌드·Spotless, 이 문서의 Prettier·상대 링크·표와 신규 파일을 포함한 `git diff --check`도 확인했습니다. 문서에 적은 대표 분수의 기여 합과 HALF_UP 표시는 Python 표준 라이브러리로 별도 검산했습니다.

2. 이번에도 전체 원본 입력을 파일로 저장하지 않았습니다. 체크섬·배치 ID·대표 분수만으로 446개 지역의 과거 입력을 복원할 수 없습니다.
3. 매출 모집단·정확한 기간, 폐업률 분모·반올림, 인구 집계·중복, 경계와 통계 판본의 의미적 비교 가능성, 누락 원인은 기존 미확인 상태를 유지합니다. 과거 분기 안정성·실제 창업 성과도 검증하지 않았습니다.
4. 후속 작업은 별도 승인 절차로 전체 입력·경계·행별 출처·제외 사유를 포함한 불변 스냅샷과 manifest를 보존하고, 그 보존본으로 DB 없는 회귀·재현 테스트를 수행하는 것입니다. 이번 검산기를 승인 manifest 검증기로 대신 사용하면 안 됩니다.
5. 정책·데이터·커버리지 승인과 공개 API는 미구현입니다. 모든 내부 결과는 계속 `NOT_APPROVED`이며, 이번 결과로 승인 상태를 변경하지 않았습니다.

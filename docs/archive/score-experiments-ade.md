# A·D·E 상세 실험 기록

이 문서는 2026-11-01 A·D·E 비교 실험의 **기존 상세 원문**을 보존합니다. 문서를 축약하기 직전 이 대화에서 메모리에 보존한 로컬 작업 트리 스냅샷에서 복구했으며, 실험을 다시 수행하거나 내용을 추정해 재작성하지 않았습니다.

보존 범위는 당시 `docs/score-design.md`의 **11절 전체**와 원문 내부 링크가 참조하는 **게시 조건·9절 계산 기준**입니다. 아래 원문 구간의 문장·수치·표·수식은 그대로 유지했습니다. 원문에 나오는 1~10절은 당시 문서의 절 번호이며, 현재 설계 문서의 절 번호가 아닙니다.

현재의 읽기 쉬운 설명과 구현 전 결정사항은 [점수 설계 문서](../score-design.md)를 봅니다. A·B·C 및 정규화 비교까지의 당시 상세본은 현재 브랜치의 `git show d993aae:docs/score-design.md`로 확인할 수 있습니다.

## 11. 공식 데이터 의미 확인과 A·D·E 추가 비교 (2026-11-01)

**D는 입력 간 보상을 줄이지만 순위 끝값 0에 과도하게 민감하고, E에도 낮은 매출의 보상이 남습니다.** 둘 다 채택하지 않았습니다. 이번에는 순위 정규화·A의 입력·방향·가중치·공통 비교 집단을 고정하고 **결합 방식만** 바꿨습니다. B·C·log/winsor의 추가 비교나 재설계는 하지 않았습니다.

공식 월평균 설명을 발견했어도 **기존 1~10절의 당시 미확인 기록을 수정하지 않았습니다.** 새 근거의 적용 범위를 이 절에 보완했습니다. 일부 A형 데이터셋 페이지는 처음에 지연 안내를 반환해 S형 상세 페이지로 확인했으며, 동적 전체 컬럼 명세와 원본 판본 대조는 완료하지 못했습니다.

### 이번 A·D·E 실험의 실행 조건

- 단일 트랜잭션 시작: **2026-11-01 22:32:23.657869 KST** (`2026-11-01T13:32:23.657869Z`). 분석 SELECT 시작: `2026-11-01T13:32:23.660497Z`.
- 로컬 Compose의 기존 `db`에서 `BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY`, `SET LOCAL statement_timeout='30s'`, `PGOPTIONS=-c default_transaction_read_only=on`을 사용했습니다. DB 응답의 읽기 전용·격리 수준을 확인하고 **ROLLBACK**으로 종료했습니다.
- 그 스냅샷에서 정상 원본·출처와 A 기준 계산값을 반환하고, 종료 후 같은 반환값만 메모리에서 A·D·E 계산·검산에 사용했습니다. 추가 DB 조회·변경·DDL·임시 테이블·ETL·마이그레이션·API 실행·원본 파일 생성은 하지 않았습니다.
- `20262`·카페 `CS100010`이며 유동인구에는 업종 필터가 없습니다. [게시 조건](#반드시-유지할-게시-조건)에 따라 최신 경계의 실제 행, 동·부모 구의 동일 게시본, 통계 행별 실제 출처의 데이터셋·CSV·SEOUL·범위 NULL·PUBLISHED·게시 시각 존재를 검사했습니다. 전역 최신 통계 배치 제한은 없습니다.
- 경계 배치 `e8653cde-14bd-42e1-b539-d6ac6e355fd5`와 6개 통계의 실제 배치 ID·체크섬·ETL 버전·게시 시각·기간, 원본 입력값은 10절 당시와 같았습니다. **같은 값이어도 3·9·10절과 이번 결과는 각각 다른 시점의 스냅샷**입니다.
- 실제 경계는 **25구·425동**, 점포·인구는 모두 존재하고 매출은 **25구·421동**입니다. 공통 비교 집단은 A·D·E 모두 **25구·421동**입니다. 면목5동(`11260550`), 하계2동(`11350612`), 북가좌1동(`11410710`), 개포1동(`11680660`)은 매출 행이 없어 제외했습니다. 점포·인구는 존재하며 결측을 0으로 바꾸지 않았습니다.

### D·E의 정의와 재현 기준

각 지역 i에 대해 순위 정규화한 방향 통일값을 `zᵢ=(R(Sᵢ),R(Fᵢ),1−R(Nᵢ),1−R(Cᵢ))`, 가중치를 `w=(0.30,0.30,0.20,0.20)`로 둡니다. R과 동률 평균 처리·구/동 분리는 [9절 정의](#계산동률검산-기준)를 사용합니다. 같은 정규화값을 A·D·E에 전달하며 집단·입력·가중치를 모델별로 바꾸지 않습니다.

**A: 가중합 기준선** — `Aᵢ=100Σⱼwⱼzᵢⱼ`. 네 값을 비중대로 더하며 낮은 입력을 다른 입력이 메울 수 있습니다.

**D: 가중 기하평균** — `Dᵢ=100Πⱼ(zᵢⱼ^wⱼ)`. 모든 z>0일 때 `100exp(Σw ln z)`로 계산할 수 있습니다. 양의 가중치 지표에 z=0이 하나라도 있으면 **D=0**으로 정의하고 log(0)은 호출하지 않습니다. epsilon·임의 하한·가중치 재분배는 없습니다. 이 0은 산출 불가가 아닙니다.

이번 가중치에서는 `P=z₁³z₂³z₃²z₄²`, `D=100P^(1/10)`이므로 P를 정확한 유리수로 비교해 동률·순위를 판정했습니다. 가중 산술평균–기하평균 부등식으로 같은 입력의 D≤A이며, 점수 하락 자체가 품질 개선을 입증하지 않습니다.

**E: 기존 정규화값을 쓰는 TOPSIS형 변형** — j는 지표, i는 지역입니다. 지표마다 이번 공통 집단의 `pⱼ=maxᵢzᵢⱼ`(최선), `qⱼ=minᵢzᵢⱼ`(최악)을 구합니다. 여러 지역에서 각각 취한 성분을 조합한 가상 기준점이며 실재 지역일 필요는 없습니다.

1. `dᵢ⁺=√Σⱼ[wⱼ(zᵢⱼ−pⱼ)²]`, `dᵢ⁻=√Σⱼ[wⱼ(zᵢⱼ−qⱼ)²]`를 계산합니다. **가중치는 제곱 차이에 한 번만 적용**합니다.
2. `Eᵢ=100dᵢ⁻/(dᵢ⁺+dᵢ⁻)`입니다. 최선에 가까우며 최악에서 멀수록 커집니다. 거리 합이 0이면 산출 불가로 두며 임의 50점을 주지 않습니다.
3. 이번에는 d⁺²>0이므로 정확한 유리수 `d⁻²/d⁺²` 순서로 E 순위·동률을 판정했습니다. 이 값은 E와 단조 대응합니다. 일반적으로 d⁺=0·d⁻>0이면 E=100, d⁻=0·d⁺>0이면 E=0입니다.

| 단위 | 관찰 최선 p (S, F, N 역방향, C 역방향) | 관찰 최악 q  |
| ---- | -------------------------------------- | ------------ |
| 구   | (1, 1, 1, 47/48)                       | (0, 0, 0, 0) |
| 동   | (1, 1, 839/840, 53/60)                 | (0, 0, 0, 0) |

동의 최소 점포 수와 폐업률 0에 동률이 있어 최선도 모두 1이 되지는 않습니다. 이 범위를 다시 0~1로 늘리지 않았습니다.

통상 TOPSIS의 벡터 정규화·가중 정규행렬에 대한 유클리드 거리 절차와 구분합니다. [방법 절차를 제시한 연구](https://link.springer.com/article/10.1186/s40537-023-00788-3)의 기본 절차와 달리 이번에는 **이미 얻은 R을 재사용하고 별도 벡터 정규화를 하지 않으며 가중치를 거리 제곱합 안에 한 번 적용**했습니다. w를 좌표에 곱하고 다시 제곱하는 방식과도 다릅니다. 이 정의는 이번 실험의 설계 선택이며 표준 TOPSIS 재현 결과가 아닙니다.

Spearman은 점수의 내림차순 동률 평균 순위 사이의 Pearson 상관입니다. 순위차는 지역별 평균 순위의 절댓값 차이입니다. 상위 5번째 점수의 동률은 모두 포함하며, 괄호는 각 모델의 집합 크기입니다.

## 원문에서 참조한 기준

### 반드시 유지할 게시 조건

1. 경계는 `SEOUL_DONG_BOUNDARY / SHAPEFILE / SEOUL / scope_code IS NULL / PUBLISHED / published_at IS NOT NULL` 중 `published_at, started_at, batch_id DESC` 첫 배치를 선택한 **후** 실제 구·동 경계 행 존재를 검사합니다. 최신 적격 배치가 비었다고 과거 경계로 되돌아가지 않습니다.
2. 구는 선택 경계 게시본을 참조해야 하고, 동은 자신과 부모 구 모두 그 게시본을 참조해야 합니다. 이번 커버리지의 분모도 이 조건을 사용합니다. 현재 경계의 코드 일치가 통계 시점의 경계 일치까지 증명하지는 않습니다.
3. 통계는 아래 데이터셋과 `CSV / SEOUL / scope_code IS NULL / PUBLISHED / published_at IS NOT NULL`을 **행별 `source_batch_id` JOIN**으로 검사합니다. `FAILED / RUNNING / SKIPPED` 및 잘못된 출처는 제외합니다.

| 단위   | 점포                        | 매출                        | 인구                               |
| ------ | --------------------------- | --------------------------- | ---------------------------------- |
| 자치구 | `SEOUL_DISTRICT_STORE_STAT` | `SEOUL_DISTRICT_SALES_STAT` | `SEOUL_DISTRICT_FOOT_TRAFFIC_STAT` |
| 행정동 | `SEOUL_DONG_STORE_STAT`     | `SEOUL_DONG_SALES_STAT`     | `SEOUL_DONG_FOOT_TRAFFIC_STAT`     |

통계에는 전역 최신 배치 제한을 추가하지 않습니다. ETL이 보존한 과거 정상 행을 새 빈 배치나 `SKIPPED`가 가리지 않아야 합니다. 이번에는 자료별 한 배치씩 관찰했지만 이를 단일 배치 제약으로 일반화하지 않습니다. 점포·매출·인구의 UUID가 서로 다르다는 것은 정상입니다.

유효한 실제 행이 전체에 하나라도 있어야 해당 데이터셋이 준비된 상태입니다. 기존 API는 다음을 구분합니다.

- 경계·데이터셋 미준비: 503.
- 현행 지역 미존재: 404.
- 데이터셋 준비 후 조건별 행 미존재: `200, data: null`.
- 측정값 전부 NULL인 실제 행: `data` 객체와 출처 유지.

점수 산출 불가를 향후 어떻게 표현하더라도 이 통계 API 계약은 유지합니다.

### 계산·동률·검산 기준

각 단위의 공통 집단에서 증가 방향 지표는 `R(x)=(평균 순위(x)-1)/(n-1)`, 감소 방향은 `1-R(x)`로 정규화했습니다. 원본 값은 오름차순으로 순위를 매기고 같은 값에는 평균 순위를 부여했습니다. 코드순으로 동률을 나누지 않았습니다. 같은 집단에서 나눗셈 후 얻은 점포당 지표도 별도로 순위를 매겼습니다.

가중치는 6절의 A·B·C를 그대로 사용했습니다.

- A: 매출액 0.30, 총 유동인구 0.30, 점포 수 감소 방향 0.20, 폐업률 감소 방향 0.20.
- B: 매출액/점포 수 0.40, 유동인구/점포 수 0.35, 폐업률 감소 방향 0.25.
- C: B의 같은 세 지표에 정확한 **1/3**씩 적용했습니다. `0.3333`으로 근사하지 않았습니다.
- 세 후보의 가중치 합계는 모두 **1**이며 `100 × Σ(wᵢ × 정규화 지표ᵢ)`로 환산했습니다. 결측 대체·자동 비중 재분배·log·winsorization·최소 점포 수 제외는 적용하지 않았습니다.

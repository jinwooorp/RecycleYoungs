## 서비스 목적과 요구사항

예비 창업자는 후보지 주변의 경쟁 점포와 지역 통계를 여러 사이트에서 따로 확인해야 합니다. 이 서비스는 자료를 한 화면에 모아 위치별 창업 환경을 비교하도록 돕습니다.

대상 지역은 서울이며, 우선 검증 업종은 카페입니다. 예비 창업자를 주요 사용자로 정했지만, 사용자 인터뷰와 서비스 효과 검증은 별도로 필요합니다.

핵심 요구사항은 다음과 같습니다.

- 지도에서 후보 위치를 선택하고 해당 행정동·상권을 확인합니다.
- 주변 경쟁 카페와 지역의 점포·추정매출 통계를 보여줍니다.
- 최대 3곳을 같은 업종·반경·분기 조건으로 비교합니다.
- 출처·기간·집계 단위와 확인되지 않은 사항을 함께 표시합니다.
- 값 없음, 실제 0, 요청 실패를 구분합니다.

창업 성공·수익·폐업을 예측하거나 보장하지 않습니다. 행정동 추정매출을 후보 반경의 매출이나 개별 가게의 이익으로 바꾸지 않습니다.

## MVP와 비목표

MVP는 시연에 필요한 핵심 기능 범위입니다. **2026-10-31까지 시연 가능한 서비스 완성**을 목표로 합니다.

현재 범위는 서울 구·행정동 검색, 지도 위치 선택, 지역 판정, 반경 500m 카페 조회, 2025년 분기 통계, 카페 소비규모·소비증감 점수와 최대 3곳 비교입니다. 화면 업종은 CAFE로 고정하며 일반 통계 API의 기존 업종 계약은 유지합니다.

다음 기능은 현재 필수 범위에 포함하지 않습니다.

- AI·머신러닝 기반 성공률·수익 예측
- 실시간 원본 수집과 정기 갱신
- 전국 확대, 임의 반경·연령 조건
- 추가 인구·시설 지표와 종합 점수
- 전체 서비스의 운영 배포

추가 기능은 자료의 의미와 계산 방법을 검증한 뒤 결정합니다.

## 현재 사용자 흐름

| 단계 | 사용자가 하는 일 | 제공되는 정보 |
| --- | --- | --- |
| 지역 검색 | 지도 상단에서 서울→구→행정동 선택 후 ‘지역 보기’ | 선택 동 경계 강조·지도 이동·두 카페 점수, 상세에서 행정동 통계 |
| 위치 선택 | 지도 클릭 또는 지도에 초점 후 방향키·Enter | 왼쪽 패널의 지역명·분기·창업 검토 요약·두 점수, 고정 반경 500m 표시 |
| 주변 확인 | 메인 패널의 가까운 카페·종류 필터·지도 이름표/묶음 선택 | 선택 지점과의 직선거리, 반경 500m 조회 수와 최대100개 수신 목록의 필터 결과 |
| 후보 저장 | 선택 위치 요약에서 최대 3곳 등록 | 지역명으로 식별하는 후보 목록과 지도 번호, 후보 선택·삭제 |
| 후보 비교 | 비교 창에서 공통 분기 선택 후 ‘같은 분기로 후보 분석’ | 검토 요약·소비규모·실제 증감·주변 카페 수·다음 확인사항. 전체 통계와 점수 근거는 펼쳐 보기 |
| 통계 조회 | ‘상세 분석 보기’로 이동 후 분기 변경 | 검토 근거·추가 확인사항·부족한 정보, 선택 분기 수치와 그래프, 펼쳐 보는 정확한 값·세부지표 |

지도 클릭은 지역 판정과 카페 조회를 각각 요청합니다. 단일 행정동이 확정되고 통계 지원 목록에 있으면 조회 조건에 반영하고 통계·추세를 자동 조회합니다. 초기 분기는 서버가 제공한 최신 분기를 사용하고 사용자가 변경할 수 있습니다. CAFE가 지원 목록에 없으면 다른 업종으로 대체하지 않습니다.

행정동 검색만으로 대표점이나 500m 결과를 만들지 않습니다. 실제 지도 지점을 선택한 뒤에만 주변 카페와 후보 추가를 제공합니다. 공식 서울 외곽선은 항상 표시하며 선택된 행정동만 채워 강조합니다. 외곽선 안의 모든 지점에서 판정·통계가 보장되는 것은 아닙니다.

후보 비교의 공통 분기는 지도·상세 분석 분기와 별도로 선택합니다. 비교 분기를 바꾸면 이전 결과를 무효화하고 ‘같은 분기로 후보 분석’ 실행 후 점수와 통계를 함께 요청합니다. 비교표를 먼저 보여주며 같은 행정동의 소비 근거는 첫 후보를 참조합니다. 전체 통계와 동별 점수 근거는 펼쳐 읽습니다.

상단 내비게이션은 지도 탐색·후보 비교 N/3·데이터 안내입니다. 후보 비교 진입은 상단 한 곳이며 패널에는 후보 추가만 남깁니다. 햄버거는 열린 패널 헤더 또는 접힌 지도 위 한 곳에만 표시합니다. 초기에는 서울 전체를 보여주고 이후 사용자가 이동한 지도를 크기 변경 때 초기화하지 않습니다. 하단 바를 제거했고 조작법·경계 출처는 데이터 안내에 모았습니다. 위도·경도는 화면에 표시하지 않으며 요청 좌표 정밀도를 유지합니다.

`/analysis?dongCode=11110515&quarterCode=20254` 직접 진입은 행정동 분석을 제공합니다. 앱 내 상세 전환·뒤로/앞으로 가기는 지도 인스턴스·선택 지점·후보를 보존하고, 과거 상세 조건은 새 지도 선택을 지우지 않습니다. 다른 지점의 주변 카페를 과거 상세에 연결하지 않습니다. 새로고침 후 후보·정확한 지점 복구는 지원하지 않습니다. 지역 검색이나 상세 URL로 가상 중심점을 만들지 않으며 지도 오류가 있어도 지역 분석을 사용할 수 있습니다.

모바일은 지도 아래에 접을 수 있는 분석 패널을 배치합니다. 패널은 약 200ms 동안 접히며, 움직임 줄이기 설정에서는 즉시 전환합니다. 접힌 내용은 키보드·보조기기 탐색에서 제외합니다. 짧은 높이의 지도 화면은 페이지 세로 스크롤을 허용해 조회 조작을 숨기지 않으며, 상세 화면은 내용 영역 안에서 스크롤합니다.

공통 필터는 기본 선택 동작을 유지하며 화살표와 오른쪽 가장자리 사이 여백을 둡니다. 상세 통계는 항목명과 값을 같은 행에 표시하고, 소비·점포 그래프는 0부터 시작하는 세로축·단위·눈금을 제공합니다. 원값은 정확한 표에서도 확인할 수 있습니다. 점수와 자료 설명은 쉬운 뜻을 먼저 안내하고, 코드·버전·검증 상태는 ‘자료 식별 정보’에 보존합니다.

100점 **카페 소비규모 점수**는 같은 분기 서울 행정동의 카페 거래 건수 중간 순위를 환산합니다. 원 거래 건수·비교 행정동 수·기간·산식·모델·조회 기준 식별값을 함께 제공합니다. 0·결측·행 부재를 구분하며 비교 집단이 30개 미만이면 산정하지 않습니다. 면적이 큰 동에 유리할 수 있고 수요·경쟁·임대료·유동인구·수익·창업 성공률을 뜻하지 않습니다.

별도의 ‘카페 상권환경지수’(수요 35·경쟁 25·소비 25·변동성 15)는 검증 전 초안으로 유지합니다. 실제 인구·점포 유형·전년·기준 집단 자료는 미연동이며 소비규모 점수를 이 종합지수로 재표기하지 않습니다.

100점 **카페 소비증감 점수**는 직전 분기 대비 거래 건수 증감률을 두 분기 모두 유효한 서울 카페 행정동 집단 안에서 비교합니다. 전분기 0·NULL·누락·음수와 직전 분기 미지원은 산정 불가이며 현재 0/전분기 양수는 -100%로 계산합니다. 높은 상대 점수라도 거래가 감소할 수 있어 방향과 증감률을 함께 표시합니다. 기본 증감률은 소수 한 자리로 표시하고, 0으로 반올림되는 변화는 ‘0.1% 미만 증가/감소’로 구분합니다. API의 소수 넷째 자리 값은 자료 식별 정보에서 확인할 수 있습니다. 계절성 보정·가중 종합점수는 제공하지 않습니다. 최소 집단 30개는 실험적 운영 기준입니다.

주변 카페는 좌표 반경, 통계는 행정동 전체를 기준으로 합니다. 같은 행정동의 후보는 같은 통계를 공유할 수 있으며, 이를 독립된 지역 통계처럼 합산하지 않습니다.

메인 패널은 창업 검토 요약·작은 두 점수와 주변 카페 목록을 제공하며 지도·목록 선택이 연결됩니다. 이름표는 상호·거리를 표시하고 밀집 구간은 묶음 목록으로 확인합니다. 연결선은 이름표와 조작 영역을 피해 끊어 표시하고 초점·선택 그룹의 선을 강조합니다. 점포를 눌러도 분석 기준 위치나 행정동을 바꾸지 않습니다. 종류 필터는 받은 최대100개를 대상으로 하며 스타벅스·컴포즈·메가·매머드·투썸·이디야·빽다방·더벤티·할리스·파스쿠찌·탐앤탐스의11개 사전을 사용합니다. ‘브랜드 카페(추정)’와 ‘브랜드 미식별’을 개인/가맹 확정 분류로 해석하지 않습니다. 상세 분석의 분기 선택은 점수·그래프 앞에 둡니다.

창업 검토 요약은 기존 두 소비 점수와 실제 전분기 증감으로 소비 신호를 설명하고, 상세에서 근거·현장 확인·비용 조사·아직 반영하지 못한 정보를 안내합니다. 상대 증감 점수가 높아도 실제 거래가 감소하면 감소 확인을 먼저 안내합니다. 현재 조건과 응답이 맞지 않거나 자료가 부족하면 해석을 보류하며 종합점수·유망/위험 등급·수익 예측은 만들지 않습니다. 반경 카페 수는 자료상 관측값이며 많고 적음만으로 입지 우열을 정하지 않습니다.

코드 구현과 실행 검증은 별개입니다. 아래 상태는 기록된 검증 범위이며, 현재 PC·DB의 정상 동작을 보장하지 않습니다.

| 통계 API·추세 | 구현 | 단위 테스트, 격리 실자료 SQL·HTTP 대조 |

| 지도·최대 3곳 비교 | 구현 | 2026-10-14 격리 시연, 2026-10-16 개편 화면의 실제 지도·3곳 비교·모바일·일반 테스트 |

| 지역 검색·경계 표시 | 공식 구·동 목록·선택 동 API·서울 외곽선 | 일반 테스트와 실제 API·Kakao 화면, 역사적 경계 호환성은 미검증 |
| 카페 소비규모 점수 | 읽기 전용 API·패널·후보 비교 연결 | 정확한 정수 산식·결측·늦은 응답 테스트와 실제 팀 API 조회 |
| 카페 소비증감 점수 | 읽기 전용 API·패널·후보 비교·상세 연결 | 정밀 비율 순위·전분기 0/누락·응답 취소 일반 테스트와 실제 팀 API 조회 |
| 상세 분석·가독성 | 두 점수의 쉬운 설명·세로축 그래프·정확한 표·패널 전환 | 2026-10-17 일반 테스트·빌드/린트와 PC·모바일 대표 화면 확인. 전체 기기·접근성 검증은 미실행 |
| 창업 검토·근거 비교 | 현재 소비 자료 해석·다음 조사 항목·같은 동 공유 표시 | 일반 회귀 테스트와 실제 지도·상세·2후보 흐름. 실제 창업 결과에 대한 예측 검증은 아님 |
| 카페 종합환경지수 | 기준 초안·순수 계산 모듈 | 합성 자료 검증만, 실제 종합점수 데이터·API 미연동 |
| 운영 배포·부하 검증 | 미완료 | 개발·시연 검증과 구분 |

검증 기록은 다음처럼 해석합니다.

- **단위·모의 검증:** 가짜 응답이나 연결로 로직을 검사합니다.
- **격리 DB 검증:** 기존 환경과 분리한 실제 DB에서 검사합니다.
- **실자료·지도 검증:** 명시한 데이터와 실제 SDK로 흐름을 확인합니다.
- **미검증·SKIP:** 확인하지 못한 항목입니다. 성공으로 계산하지 않습니다.

기록의 날짜·대상·제한은 [검증 이력](technical.md#검증-이력)에서 확인합니다. 최근 창업 검토 중심 개선은 [2026-10-17 검증 기록](technical.md#2026-10-17-창업-검토-요약근거-비교상세-통합)에 있습니다. 각 기록의 일반 테스트·브라우저 확인과 과거 격리 DB 검증을 구분합니다.

## 다음 작업

시연 준비를 우선하며, 완료 조건을 다음처럼 잡습니다.

1. **개발 환경 재현:** 현행 README로 새 환경을 준비하고 서비스가 연결되는지 확인합니다. 기존 데이터가 있는 PC를 초기화해 시험하지 않습니다.
2. **개편 화면의 시연 점검:** 지도 지역 검색·소비규모/소비증감 점수·상세 분석·후보 비교와 딥 그린·아이보리 테마를 유지하며 긴 이름·결측·오류·경계 모호성 사례를 확인합니다.
3. **접근성과 시연 준비:** 키보드 조작, 모바일 표, 지도 키 오류, 부분 실패·재시도 사례를 확인합니다. 발표 시나리오와 운영 구성을 구체화합니다.
4. **화면 미리보기:** 프론트엔드 기능 완료 후 현재 서비스 캡처를 최소 2장 이상 README에 추가합니다. 지도 탐색과 상세 분석을 우선 후보로 두며, 현재는 안내 문구만 제공합니다.
5. **운영 배포 준비:** Docker Compose + AWS EC2 배포를 예정하고 nginx와 배포 CI/CD 도입을 검토합니다. 현재 Compose는 개발 DB·데이터 준비용이며, 기존 GitHub Actions는 독립 E2E 검증용입니다. 운영 서비스 배포 구성과 자동 배포는 아직 완료하지 않았습니다.

실제 DB·브라우저 재검증은 사용할 대상과 실행 범위를 정한 뒤 수행합니다. 문서나 코드 정리만으로 실측 완료 상태를 갱신하지 않습니다.

카페 평가용 인구·점포 유형·전년 자료와 기준 집단의 데이터 계약을 후속 검토합니다. 실제 수집·적재·API 확장은 별도 범위로 진행하고 기존 DB 승인 절차를 지킵니다. 추가 업종·성능 개선·원본 갱신 체계는 그 범위를 정한 뒤 진행합니다.

## 현재 blocker와 미확정 사항

- **점포 자료의 기준일·완전성:** 파일명 `202606`을 정확한 관측일이나 모든 영업 점포의 목록으로 볼 수 없습니다.
- **점포 운영 형태:** 상호명 기반 브랜드 추정만 제공하며 가맹·직영·독립 운영은 미확인입니다. 정확한 점포 식별/주소·브랜드 소속·점포별 운영 형태 근거·기준일·확인 상태를 갖춘 자료를 확보·검증한 뒤 별도 API/ETL 확장으로 다룹니다. 브랜드별 집계나 미등록 이름만으로 개별 점포를 확정하지 않습니다.
- **역사적 경계 호환성:** 현재 경계가 2025년 통계 집계 당시와 같다는 근거가 부족합니다.
- **원본 경계의 겹침·속성 충돌:** 행정동 겹침과 홍지문 상권의 충돌을 보존합니다. 임의 보정하지 않습니다.
- **자료 교체 정책:** 통계·점포 전체를 같은 시점에 교체하고 재현하는 운영 기능은 미완료입니다.
- **테스트 대상 구분:** 과거 V1 전용 `dbTest`의 기대값을 현재 팀 DB에 그대로 적용하면 안 됩니다.
- **시연·운영 범위:** 예정한 EC2/Compose 배포의 구체 구성·자동화, 부하 기준, 팀원 PC 재현, 포괄적 접근성 검증이 남아 있습니다.
- **기존 DB 변경 경로:** 실제 감사 자료 수집기와 안전 실행기는 미구현입니다. 현재 팀 개발 경로와 별개의 보류 과제입니다.

## 추가 지표와 점수 정책

인구·시설·변화 지표를 추가하려면 지역 단위와 기간, 중복 여부부터 확인합니다. 서울 전체 수치를 모든 후보지의 지역 수요로 반복해서 넣지 않습니다.

규칙 기반 점수를 도입할 경우 계산식·가중치·비교 집단·버전을 공개해야 합니다. 원지표도 함께 보여주며, 필수 자료가 없으면 점수를 만들지 않습니다.

추가 SEMAS 업종은 공식 분류와 포함·제외 기준을 확인한 뒤 연결합니다. 상호명이나 서울시 업종 코드만으로 점포를 임의 분류하지 않습니다.

## 기존 DB 적용을 위한 보류 과제

이 절은 과거 트랙 A의 목적을 설명합니다. 퇴역한 DB를 재생성·복원하는 계획이 아니며, 팀 개발 환경 실행의 선행 조건도 아닙니다.

현재 세 모듈의 역할은 제한적입니다.

- `source_validation.py`: 전달받은 변경 전후 자료를 비교합니다.
- `source_audit.py`: 입력·코드·관찰 과정의 출처 기록 형식을 검사합니다.
- `source_control.py`: 가짜 자료로 단계 전환을 검사하며 실제 실행은 거부합니다.

향후 기존 DB 변경 기능이 필요하다면 다음 순서로 검토합니다.

1. 비교·출처 기록 계약을 검토합니다. 가짜 연결로 수집 흐름을 검사합니다.
2. 승인된 DB에서 실제 자료를 수집하고, 연결 대상·쓰기 주체·권한을 확인합니다.
3. 변경 전후 보존 검사, 최신 백업, 독립 복원, 중단·복구 처리를 준비합니다.
4. 새 격리 환경에서 실패 사례까지 검증한 뒤 독립 리뷰를 받습니다.
5. 마지막으로 대상·변경 범위의 승인을 받고 실행합니다.

기존 작업 ID A-01~A-11과 B-01~B-12의 상세 조건은 위의 과거 기록을 참고합니다. 실행 조건의 기준은 [DB 안전 정책](db-safety.md#향후-source-실행과-검증-gate)입니다. 테스트의 성공이나 READY만으로 실제 변경을 승인하지 않습니다.
